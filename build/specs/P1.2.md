## Objective

Implement the deterministic state core of Substrate: an append-only JSONL event store with validation, replay, torn-tail recovery, and run lock; a pure reducer deriving run and task lifecycle states; a scheduler computing DAG layers, serializing overlapping write/create sets, managing concurrency pools, and checking budgets; an escalation ladder enforcing retry and replan caps; and a usage ledger with pricing calculation and pre-flight cost estimation. All transitions and control decisions are pure code without LLM-driven flow.

## Behavior

- Event Store:
  - IF appending an event THEN validate `event` against `EngineEvent` schema AND verify `event.seq === lastSeq + 1` AND append JSON line to `.substrate/runs/<run_id>/events.jsonl`; ELSE reject with validation error.
  - IF reading log AND the final line is incomplete/torn JSON THEN drop or ignore the torn line AND parse all preceding valid lines; ELSE IF valid JSON on all lines THEN return all parsed events.
  - IF a non-terminal line contains invalid JSON or schema violation THEN halt replay and throw corruption error naming file and line number.
- Run Lock:
  - IF acquiring lock AND lock file `.substrate/state/<run_id>.lock` does not exist THEN write pid, run_id, and timestamps AND return true.
  - ELSE IF lock exists AND holder process is alive AND heartbeat is not stale THEN return false (locked).
  - ELSE IF holder process is dead OR heartbeat exceeds stale timeout THEN overwrite lock with current pid AND return true (reclaimed).
  - IF releasing lock AND current pid matches lock holder THEN unlink lock file; ELSE do not remove foreign lock.
- Reducer:
  - IF `run.created` THEN initialize `EngineState` with status `CREATED`, sequence 0, zero usage.
  - IF `run.routed` THEN transition run from `CREATED` to `ROUTING` then `PLANNING`.
  - IF `plan.produced` THEN transition run from `PLANNING` to `LINTING`.
  - IF `plan.approved` THEN transition run from `AWAITING_APPROVAL` to `SETUP`; ELSE IF `plan.rejected` THEN transition to `CANCELLED`.
  - IF `setup.done` THEN transition run from `SETUP` to `EXECUTING`.
  - IF `task.ready` THEN transition task from `PENDING` to `READY`.
  - IF `task.session.started` THEN transition task from `READY` to `RUNNING` and record `session_id`.
  - IF `task.scope.checked` THEN transition task from `RUNNING` to `SCOPE_CHECK`.
  - IF `task.verify.started` THEN transition task from `SCOPE_CHECK` to `VERIFYING`.
  - IF `task.verify.finished` AND all checks pass THEN transition task from `VERIFYING` to `PASSED`; ELSE IF first verify failure in current generation THEN transition task to `HEALING`; ELSE transition task to `FAILED`.
  - IF `task.healing` THEN increment attempt and transition task to `HEALING`.
  - IF `task.passed` THEN transition task from `PASSED` to `MERGING`.
  - IF `task.merged` THEN transition task from `MERGING` to `MERGED`.
  - IF `task.failed` AND generation < max replans THEN transition task to `REPLANNING` and ready generation `g + 1`; ELSE IF replans exhausted THEN transition task to `BLOCKED`.
  - IF a task transitions to `FAILED` or `BLOCKED` THEN transition all dependent tasks in `depends_on` closure to `BLOCKED`.
  - IF all batch tasks are `MERGED` THEN transition run from `EXECUTING` to `INTEGRATING`.
  - IF `integration.finished` AND verification succeeds THEN transition run to `FINISHED` (or `REVIEWING` if enabled); ELSE IF integration fails THEN mark run or failing task `FAILED`.
  - IF `usage.recorded` THEN accumulate `record.cost_usd` into `total_usd` and role breakdown in `usage.by_role`.
  - IF accumulated cost >= `max_usd` OR tokens >= `max_tokens` THEN transition run to `PAUSED(budget_exhausted)`.
  - IF accumulated cost >= 80% of `max_usd` THEN record budget warning flag.
  - IF `run.paused` THEN set state to `PAUSED` with specified `PauseReason`.
  - IF `run.resumed` THEN restore prior state before pause.
- Scheduler:
  - IF calculating DAG layers THEN construct graph from task `depends_on` AND return topological layers; ELSE IF a dependency cycle is detected THEN throw cycle error.
  - IF candidate tasks in a layer have intersecting `write` or `create` globs THEN mark them as overlapping AND serialize execution by `TaskId` order; ELSE allow concurrent execution.
  - IF active task count < `concurrency.workers` AND READY tasks with non-overlapping write sets exist AND run budget is unexhausted THEN yield next eligible task IDs; ELSE yield empty array.
- Escalation Ladder:
  - IF failure is first verify failure in current generation THEN return L0 action `heal` resuming same session once.
  - ELSE IF failure is second verify failure OR scope violation OR protected modified OR budget exceeded OR merge conflict:
    - IF task generation < `budgets.l1_replans_per_task` (default 2 replans, max generation 3) THEN return L1 action `replan` targeting next tier up in `routing.escalation` in a fresh worktree;
    - ELSE IF run L2 count < `budgets.l2_per_run` (default 2) THEN return L2 action `contract_defect` for manifest/contract amendment;
    - ELSE return L3 action `pause` with `needs_human`.
  - IF failure is `permission_denied` THEN return L3 action `pause` with `permission_denied` immediately (never replan).
  - IF failure is `rate_limited` THEN back off exponentially and halve concurrency (floor 1), never replan; IF backoff exhausted THEN return L3 action `pause` with `rate_limited`.
- Pricing & Ledger:
  - IF model exists in `PricingTable.models` THEN compute cost using `(input * input_per_mtok + output * output_per_mtok + cache_read * cache_read_per_mtok + cache_write * cache_write_per_mtok) / 1_000_000`; ELSE throw error for unlisted model.
  - IF recording usage THEN append `LedgerEntry` to ledger store.
  - IF estimating run cost THEN multiply task count by historical median cost per class from ledger (or settings default if empty) times retry multiplier `(1.0 + retry_factor)`; IF estimated cost > `approval_threshold_usd` THEN set `requires_approval = true`; ELSE set `false`.

## Invariants

- Code owns control flow (I1): state transitions, retry counters, caps, locks, and verdicts are never decided by an LLM.
- State reduction is pure: `reduce(state, event)` has no filesystem, process, or network side effects.
- Event store is the source of truth: any execution state can be completely reconstructed by replaying `.substrate/runs/<run_id>/events.jsonl` from sequence 1.
- Parallel only when disjoint (I9): concurrent tasks must be dependency-ready and have disjoint `write` and `create` file sets.
- Single runner lock: only one active engine process may hold `.substrate/state/<run_id>.lock` at any time.
- Hard budget limits (I7): budget exceeded transitions run to `PAUSED(budget_exhausted)`.
- Strict escalation caps (§5): L0 cap 1 per generation; L1 cap 2 replans per task (max generation 3); L2 cap 2 per run.
- Non-replannable failures (§5): `permission_denied` and `rate_limited` never trigger replanning.
- Architectural boundaries (§15): `store`, `ledger`, and `backends/pricing.ts` import only `contracts` and `util`; `engine` imports `contracts`, `util`, `store`, `ledger`, `backends/pricing.ts`, and never `cli`, `tui`, or `hooks`.

## Edge cases

- Torn last line in JSONL log from ungraceful kill: parser recovers by dropping partial line and preserving valid events up to that point.
- Middle line corruption in JSONL log: parser refuses to silently skip lines and throws a fatal integrity error.
- Event sequence out of order or duplicate seq: event append rejects with non-monotonic sequence error.
- Replay with zero events: returns initial blank state without crashing.
- Stale lock detection when PID was reused by unrelated process: heartbeat timestamp expiration resolves stale locks even if PID exists.
- Cyclic task dependencies: DAG computation detects cycle and rejects before any task is readied.
- Missing model in pricing table: computation throws an explicit error rather than silently returning zero cost.
- First run with empty ledger: cost estimation safely falls back to configured default class budgets.
- All tasks fail in a batch: scheduler blocks dependent tasks, marks run as failed or awaiting replan, and avoids infinite loops.
- Overlapping paths with wildcard globs (e.g. `src/**` vs `src/foo.ts`): picomatch matching detects intersection and enforces serialization.
- Negative or NaN token values: rejected by `UsageRecord` validation.

## Guardrails

- Pure state logic: no child process spawning, git executions, network calls, or harness adapter instantiations within this package.
- File system access restricted to `.substrate/runs/<run_id>/events.jsonl` and `.substrate/state/<run_id>.lock` (plus ledger persistence in `.substrate/`).
- No modifications outside `create` path list.
- Keep every code fence <= 12 lines.
- Preserve test protection: `test/unit/store/**`, `test/unit/engine/**`, `test/unit/ledger/**` must not be weakened or edited to pass.
- No git commits, resets, rebases, or pushes.
- Secrets and tokens must never be logged in event payloads or ledger entries.
