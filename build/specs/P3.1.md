## Objective

Implement the backend foundation for Substrate: a robust process supervisor with process groups, execution timeouts, staged SIGTERM-to-SIGKILL escalation, tail-capped outputs, and stream backpressure; an asynchronous NDJSON reader with line-length bounds and raw stream persistence; a deterministic fake harness binary featuring a multi-scenario engine and Claude stream-json dialect emulator; and the shared adapter conformance test suite that every harness adapter must import and satisfy.

## Behavior

- Process Supervisor (`src/backends/process.ts`):
  - Spawning & Process Group:
    - IF `spawnSupervisedProcess(options)` is called THEN spawn process via `node:child_process` with `detached: true` in `options.cwd` with provided `env`.
    - IF platform is POSIX THEN child becomes process group leader where PGID equals child PID; ELSE record child PID as target identifier.
  - Output Streaming & Tail Capping:
    - IF child writes to stdout THEN pass chunks downstream to `stdout` stream without unbounded in-memory buffering; IF `maxStdoutBytes` is configured THEN retain tail buffer capped using `capBytes`/`takeTail` from `src/util/index.js`, setting `stdoutTruncated: true` when exceeded; ELSE retain complete output with `stdoutTruncated: false`.
    - IF child writes to stderr THEN pass chunks downstream to `stderr` stream; IF `maxStderrBytes` is configured THEN retain tail buffer capped using `capBytes`/`takeTail`, setting `stderrTruncated: true` when exceeded; ELSE retain complete output with `stderrTruncated: false`.
  - Timeout & Graceful Termination:
    - IF process run duration reaches `timeoutMs` before natural exit THEN set `timedOut: true`, initiate process-group termination with kill reason `"timeout"`.
    - IF `kill(reason)` is called OR timeout fires THEN send `SIGTERM` to `-pgid`.
    - IF process group exits within `gracePeriodMs` (default 5000 ms) THEN complete termination with exit signal `SIGTERM`.
    - ELSE IF process group does not exit within `gracePeriodMs` THEN escalate to `SIGKILL` sent to `-pgid`.
    - IF process group already exited (ESRCH) THEN ignore error and complete termination cleanly.
  - Backpressure & Drain:
    - IF consumer stream or stdout/stderr pipe experiences backpressure THEN pause reading / respect drain events so child process never blocks or deadlocks.
  - Completion:
    - IF child process group exits THEN resolve `wait()` with `ProcessExitResult` containing exit code, termination signal, total duration, stdout/stderr tails, and truncation flags.

- NDJSON Reader (`src/backends/ndjson.ts`):
  - Chunk Splitting:
    - IF incoming chunk contains newline `\n` THEN split chunk into discrete lines; IF a trailing fragment remains without newline THEN retain fragment in memory buffer until next chunk.
    - IF buffered fragment exceeds `maxLineLength` (default 10 MB) THEN raise protocol error to prevent out-of-memory exhaustion.
  - Line Filtering & Parsing:
    - IF a line is empty or whitespace-only THEN skip without emitting an event.
    - IF line contains valid JSON THEN parse line into object; IF `readNdjsonStream` was called THEN yield object via `AsyncIterable`.
    - ELSE IF line contains invalid JSON THEN invoke `onParseError` if provided; ELSE throw protocol error (never silently swallow invalid JSON).
  - Raw Stream Persistence:
    - IF `rawSink` callback is configured THEN forward raw bytes/chunks to `rawSink` so raw output stream is persisted to `raw/<session_id>.ndjson`.

- Fake Harness & Scenario Engine (`test/fixtures/fake-harness/**`):
  - CLI Dispatch:
    - IF fake harness binary is executed THEN inspect CLI arguments and scenario configuration.
    - IF scenario is `"success"` THEN emit `session.started`, assistant text, token usage, and `session.result` with `ok: true, exit_code: 0`.
    - IF scenario is `"edit_files"` THEN modify designated files in working directory, emit `tool.call` and `tool.result`, exit 0.
    - IF scenario is `"verify_fail_then_fix"`:
      - IF initial attempt (no resume flag) THEN write broken changes, exit with non-zero code.
      - ELSE IF resumed session (`--resume` flag present) THEN write fixed changes, exit 0.
    - IF scenario is `"hang"` THEN sleep indefinitely without writing completion result to exercise supervisor timeout and SIGKILL.
    - IF scenario is `"crash"` THEN exit abruptly with code 1 or simulate abnormal termination.
    - IF scenario is `"soft_deny"` THEN emit tool denial event or write soft-deny output to stderr with exit 0.
    - IF scenario is `"budget_overshoot"` THEN emit token usage exceeding budget and subtype `error_max_budget_usd`, exit 1.
    - IF scenario is `"rate_limit"` THEN emit rate limit event or error event with `kind: "rate_limit"`, exit with rate limit code.
    - IF scenario is `"resume"` THEN preserve and echo requested `session_id`, resume state context.
  - Claude Dialect:
    - IF Claude dialect is selected THEN format output stream matching Claude `stream-json` NDJSON:
      - line 1: `system` event with `subtype: "init"`, `session_id`, `tools`, `model`.
      - line 2: `assistant` event with message content and turn token usage.
      - line 3 (optional): `rate_limit_event` or tool call/result events.
      - line 4: `result` event with `subtype`, `total_cost_usd`, `usage`, `permission_denials`.

- Adapter Conformance Suite (`test/conformance/**`):
  - Battery Execution:
    - IF conformance suite is run against an adapter THEN execute uniform test battery covering capabilities, environment validation, and session lifecycle.
    - IF `validateEnvironment()` is invoked THEN verify it returns `EnvReport` with boolean `ok`, `pin_matches`, and string array `problems`.
    - IF `spawn(req)` is invoked THEN verify it returns `SessionHandle` with valid `pid > 0`, async iterable `events`, `result()`, and `kill()`.
    - IF iterating `events` THEN assert every event matches `BackendEvent` zod schema; assert first event is `session.started` and final event is `session.result`.
    - IF awaiting `result()` THEN assert return value matches `SessionResult` zod schema.
    - IF `handle.kill(reason)` is invoked THEN assert process group terminates, `result()` resolves with `ok: false` and `killed_for: reason`.
    - IF tool denial occurs THEN assert `permission.denied` event is yielded and denial recorded in `SessionResult.denials`.
    - IF resume is spawned THEN assert session ID matches resumed session.
  - Conformance Test Execution:
    - IF `npm test -- test/conformance` is executed THEN run conformance suite against `FakeAdapter` (using fake harness Claude dialect) and assert all tests pass.

## Invariants

- Import boundaries: `src/backends/process.ts` and `src/backends/ndjson.ts` import strictly from `src/contracts/**`, `src/util/**`, and Node standard libraries. They never import `engine`, `git`, `spec`, `verify`, `roles`, `config`, `ledger`, `cli`, or `tui`.
- Never treat exit code alone as success (Plan §11.1 requirement 2 / invariant I11): adapter success is determined by structured result verification.
- Process group isolation: supervisor always spawns with `detached: true` on POSIX and terminates entire process groups via negative PID (`-pgid`).
- Staged termination escalation: process termination always issues `SIGTERM` first, waits up to `gracePeriodMs`, and escalates to `SIGKILL` only if the process group remains active.
- Schema fidelity: all events emitted by adapters and the fake harness strictly validate against `BackendEvent` zod schema; all results strictly validate against `SessionResult` zod schema.
- Universal battery: the adapter conformance suite in `test/conformance/**` is the exact battery imported by all subsequent adapter packages (P3.2, P3.3, P3.4) and may not be modified by individual adapters.
- Deterministic execution: unit and conformance test runs in P3.1 invoke only the local fake harness; no real model CLIs, network requests, or credentials are required.
- Tail buffer capping: output capture uses `capBytes` / `takeTail` from `src/util/index.js` to bound memory consumption under large stdout/stderr volumes.

## Edge cases

- Process exits before termination signal arrives: `killProcessGroup` catches `ESRCH` errors gracefully and returns false/cleanly without throwing.
- Guard against invalid PID/PGID: supervisor validates that PGID > 0 before sending signals to prevent signaling the process group of the test runner or host OS (`pgid === 0` or `-1`).
- Long lines without newlines: `readNdjsonLines` enforces `maxLineLength` buffer limit; if exceeded without encountering a newline, it raises a protocol error and clears buffer to avoid memory exhaustion.
- End of stream without final newline: trailing line fragment is parsed if valid JSON; if malformed, `onParseError` or protocol error is triggered.
- Multiple or idempotent kill calls: calling `kill()` multiple times on a `SupervisedProcess` or `SessionHandle` executes safely without duplicate timers or unhandled promise rejections.
- Process exit due to signal: when a process is killed by signal, `exitCode` is `null`, `signal` records the signal name (e.g. `"SIGTERM"`), and `killed` is set to `true`.
- Stream closed prematurely (EPIPE): pipe write errors on child process communication are handled without uncaught exceptions.
- Zero-byte stdout/stderr: tail buffers correctly record empty strings with `stdoutTruncated: false` and `stderrTruncated: false`.
- Slow child processes ignoring SIGTERM: supervisor escalation timer triggers `SIGKILL` to forcefully terminate stuck or unresponsive processes.

## Open questions

- What is the default grace period between `SIGTERM` and `SIGKILL`? The specification assumes 5000 ms as a reasonable default, configurable via `gracePeriodMs` in `SupervisedProcessOptions`.
- Which component owns creating the parent directory for `raw/<session_id>.ndjson` streaming? The specification assumes the adapter or session initializer ensures directory presence before opening the raw sink stream.
