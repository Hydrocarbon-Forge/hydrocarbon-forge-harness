## Objective

Implement the git workspace lifecycle, verify runner with bubblewrap sandbox wrapper, and batch merger for Substrate. This includes run and task branch management (using `substrate/runs/<run_id>` and `substrate/tasks/<run_id>/<task_id>-g<generation>` to eliminate Git D/F ref conflicts), worktree provisioning, spec materialization, worktree setup execution, scope checking against write/create globs, protected file byte-hashing, engine-owned pathspec commits, verify command execution with tail-capped outputs and timeout process-group kills, bubblewrap sandboxing with network isolation, merge-tree preflight conflict detection, deterministic batch merges into the run branch, integration gate verification with deterministic bisection on failure, and checkpoint rollbacks.

## Behavior

- Worktree and Branch Management:
  - IF run branch `substrate/runs/<run_id>` does not exist THEN create it from `base_ref`; ELSE reuse the existing run branch.
  - IF a task worktree is requested for `task_id` and `generation` THEN derive branch name `substrate/tasks/<run_id>/<task_id>-g<generation>`, ensure `.substrate/worktrees/` and `.substrate-task/` exist in `.git/info/exclude`, and create worktree under `.substrate/worktrees/<task_id>-g<generation>`; ELSE IF worktree path already exists THEN remove stale worktree before creation.
  - IF `materializeSpec` is called THEN write the TaskSpec content to `.substrate-task/TASK.md` within the task worktree; ELSE reject if worktree directory does not exist.
  - IF `runSetup` is called with `manifest.setup` commands THEN execute each command in sequence inside the task worktree with network access enabled; IF any setup command exits non-zero THEN abort workspace initialization and surface failure; ELSE complete setup.
  - IF `removeWorktree` is called THEN run `git worktree remove --force` on the worktree path while preserving the task branch; ELSE IF `pruneWorktrees` is called THEN run `git worktree prune`.

- Scope and Protected File Enforcement:
  - IF protected file hashing is initiated before worker starts THEN compute SHA-256 for all existing files matching `spec.protected` globs and record non-existent paths; ELSE skip empty protected sets.
  - IF after worker session completes any file matching `spec.protected` has a different SHA-256 hash OR was created when absent OR was deleted THEN flag `protectedModified` and set failure class `protected_modified`.
  - IF worktree status (`git status --porcelain`) reveals changed or untracked paths THEN test each path against `spec.write` and `spec.create` globs; IF any path matches neither write nor create THEN record it in `violations`.
  - IF `violations` exist AND `git.on_scope_violation === "revert"` THEN revert tracked out-of-scope files via `git checkout -- <path>`, delete untracked out-of-scope files, and log `scope_violation`; ELSE IF `violations` exist AND `git.on_scope_violation === "fail"` THEN retain changes and set failure class `scope_violation`.
  - IF no protected modifications and no violations occur (or all out-of-scope files were cleanly reverted) THEN mark scope check clean (`ok: true`).

- Engine Commits and Diff Generation:
  - IF scope check passes AND verification passes THEN stage strictly allowed paths matching `spec.write` and `spec.create` pathspecs (`git add -- <pathspec>`) and create commit with author `substrate-engine`; ELSE do not commit.
  - IF worker process attempts to invoke git commit, push, checkout, reset, rebase, or clean THEN engine denies the operation (workers never commit).
  - IF `generateDiff` is called for a failure packet THEN run `git diff --stat` and `git diff` against base branch; IF diff byte length exceeds cap THEN truncate diff and set `truncated: true`; ELSE set `truncated: false`.

- Verify Runner and Sandbox Execution:
  - IF `runVerify` is called THEN execute each command in `spec.verify` in the specified working directory.
  - IF `settings.sandbox.enabled` is true AND platform is Linux AND `bwrap` is available THEN wrap command execution with `bwrap` using `--ro-bind / /`, `--bind <worktree> <worktree>`, writable `/tmp`, `--die-with-parent`, and IF `sandbox.network === "deny"` THEN append `--unshare-net`; ELSE IF sandbox is disabled or unavailable THEN execute command directly.
  - IF verify command is spawned THEN start detached process group with scrubbed environment allowlist and start timer for `timeout_s`.
  - IF execution time exceeds `timeout_s` THEN kill entire process group with `SIGKILL`, set `timed_out: true`, and record null or signal exit code; ELSE record actual `exit_code`.
  - IF stdout or stderr stream exceeds tail cap (≤ 8 KB) THEN keep the tail window and set `truncated: true`; ELSE preserve full stream and set `truncated: false`.
  - IF all verify commands exit 0 and none timed out THEN mark `isAllPassed: true`; ELSE mark `isAllPassed: false`.

- Merger, Integration Gate, Bisect, and Checkpoints:
  - IF batch merge starts THEN order passed tasks deterministically (topological dependency order, then lexicographical by `TaskId`).
  - IF preflight is run for task branch THEN execute `git merge-tree --write-tree --name-only <run-branch> <task-branch>`; IF exit code is 1 (conflict) THEN parse conflicting files and mark task `FAILED(merge_conflict)` without touching working tree; ELSE mark preflight clean and proceed.
  - IF preflight passes THEN merge task branch into run branch with `git merge --no-ff`; record intermediate tree SHA.
  - IF all batch tasks merge THEN execute `manifest.integration_verify` in integration worktree; IF all commands exit 0 THEN record run branch SHA as checkpoint and return `ok: true`; ELSE trigger bisection.
  - IF integration verify fails THEN reset run branch to pre-batch checkpoint (`git reset --hard <checkpoint>`), re-merge batch tasks one-by-one in deterministic order, running `integration_verify` after each; IF a task causes integration verify to fail THEN isolate that task as culprit, reset run branch to state before culprit, and emit `FailurePacket(integration_failed)`.
  - IF `rollbackCheckpoint` is requested THEN reset run branch to specified checkpoint commit SHA.

## Invariants

- Branch namespace separation: run branch is always `substrate/runs/<run_id>` and task branch is always `substrate/tasks/<run_id>/<task_id>-g<generation>` to eliminate Git D/F ref conflicts.
- Workers never commit: all git staging and commits are executed solely by the engine using explicit pathspecs.
- Worktree isolation: untracked files (such as `node_modules`) are never shared between worktrees; each task worktree runs isolated setup.
- Excluded paths: `.substrate/worktrees/` and `.substrate-task/` are always registered in `.git/info/exclude`.
- Strict protected immutability: any alteration to files matching `protected` globs results in `protected_modified`, which is fatal and never auto-reverted.
- Pure preflight: `git merge-tree --write-tree` performs in-memory conflict detection without modifying worktrees or index locks.
- Deterministic bisection: batch merges and bisection follow fixed topological-then-TaskId ordering; run branch is never left in a red or broken state.
- Acceptance authority: a task passes verification if and only if every command in `spec.verify` exits with code 0 within its timeout.
- Host safety: verify runner scrubbed environment strips credentials, secrets, and model API tokens from worker subprocesses.
- User branch isolation: the user's base branch is never written or merged into without an explicit external gate.

## Edge cases

- Untracked file created outside create globs: IF `on_scope_violation === "revert"` THEN unlinked; IF `on_scope_violation === "fail"` THEN retained and task marked `scope_violation`.
- Protected file created when initially absent: detected by hash comparison and rejected as `protected_modified`.
- Command timeout in verify runner: process group killed via `SIGKILL` to negative PID (`-pid`) to eliminate runaway child processes.
- High-volume stdout/stderr in verify command: sliding tail buffer caps output at 8 KB without exceeding memory limits.
- Merge conflict on one task in batch: caught in preflight without generating conflict markers or interrupting previously merged tasks.
- Single-task batch fails integration verify: immediately identified as culprit without intermediate bisection steps.
- Stale worktree directory from crashed previous run: detected and cleaned prior to worktree allocation.
- Setup command failure: halts worktree initialization and logs diagnostic before any worker is spawned.
- Bubblewrap missing on Linux: returns false for `isAvailable()` and falls back or reports diagnostic per configuration without engine crash.

## Guardrails

- No implementation bodies in spec; all interfaces are pure TypeScript declarations matching Appendix A types.
- Every code block is strictly 12 lines or fewer.
- No writes outside `src/git/**`, `src/verify/**`, and test integration directories.
- Protected files `src/contracts/**` and `src/util/**` are strictly read-only.
- Subprocesses spawned with scrubbed environment stripping sensitive API keys (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, tokens).
- Worktrees and file operations must validate paths with `isSafePath` from `src/util/**`.
