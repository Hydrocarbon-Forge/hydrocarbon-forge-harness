## Objective

Implement comprehensive crash/resume chaos hardening tests and opt-in live harness smoke tests:
1. Crash and resume chaos testing (`test/integration/chaos/**`):
   - Kill at every event boundary (Scenario 11 of §14.5): Execute a standard multi-task run emitting sequence events $1 \ldots N$; for each boundary $k \in [1 \ldots N]$, interrupt/kill the engine immediately after event $k$ is written, resume via `Engine.resume(run_id)` or `substrate resume <run_id>`, and assert state is accurately reconstructed from event log replay, completing remaining tasks cleanly to final status `finished` with exit code 0.
   - Torn-tail recovery: Simulate abrupt termination during disk flush by appending incomplete JSON or corrupt bytes as the last line of `.substrate/runs/<run_id>/events.jsonl`; verify that the event store drops the torn tail, recovers the valid prefix, appends next events with valid sequence numbering, and resumes without crashing.
   - Double lock contention: Enforce `.substrate/state/<run_id>.lock` semantics; verify active lock rejection (concurrent engine instance exits with conflict error), stale lock reclamation (dead PID or expired heartbeat allows safe takeover), and simultaneous acquisition race resilience.
2. Live smoke testing on real installed harnesses (`test/live/**`):
   - Smoke test battery across available backends: Claude Code (`claude`), OpenCode (`opencode`), and Antigravity (`agy`).
   - Opt-in execution: Runs ONLY when `SUBSTRATE_LIVE=1` is explicitly set in environment; otherwise cleanly skipped by default in automated CI runs.
   - Per-harness live execution: Run a minimal task on the cheapest configured model tier with a strict budget cap (`max_usd: 0.10`) per §14.6, verifying structured output parsing, token/cost reporting, and workspace resource cleanup.
   - Credential safety: Verify that no secrets, API keys, or auth tokens are logged, stored, or leaked into event logs or test outputs (I12).

## Behavior

The chaos and live smoke suites execute according to the following decision trees:

1. Crash and resume at event boundary (Scenario 11 of §14.5):
   - For a deterministic multi-task scenario producing $N$ events $E_1 \ldots E_N$:
     - For each target sequence boundary $k \in \{1, \ldots, N\}$:
       - Run engine until event $E_k$ is written to `.substrate/runs/<run_id>/events.jsonl`.
       - Terminate the engine immediately after persisting $E_k$, simulating an ungraceful crash (SIGKILL).
       - Release process-level resources while preserving disk state (`events.jsonl`, run lock, and worktrees).
       - Invoke `Engine.resume(run_id, { cwd: repoRoot })`:
         - Read `.substrate/runs/<run_id>/events.jsonl` and replay all $k$ events through `reduce(state, event)`.
         - Derive next pending actions via `nextActions(state, settings)`.
         - IF event $k$ was before worktree creation (`task.ready`):
           - THEN resume creates the worktree and starts the worker session.
         - ELSE IF event $k$ was during task execution (`task.session.started`):
           - THEN resume detects unverified task and starts a fresh worker session or resumes backend session.
         - ELSE IF event $k$ was after verification passed (`task.passed`):
           - THEN resume avoids re-running verify commands and advances directly to batch merge preflight.
         - ELSE IF event $k$ was during or after batch merge (`batch.merged`):
           - THEN resume validates integration worktree state and dispatches integration verification without duplicate git commits.
         - Verify that final summary reaches `status === "finished"` with `exit_code === 0` and all tasks in state `PASSED`.

2. Torn-tail event log recovery:
   - Given an active run directory with $M$ valid persisted events:
     - IF simulating torn tail via `corruptEventLogTail(runDir, "truncated_json")`:
       - Append an unclosed JSON string (e.g. `{"v":1,"seq":M+1,"type":"task.`) to `.substrate/runs/<run_id>/events.jsonl`.
     - ELSE IF simulating garbage bytes:
       - Append arbitrary binary/corrupt text to the trailing line of `.substrate/runs/<run_id>/events.jsonl`.
     - Invoke `Engine.resume(run_id)` or `eventStore.readAll()`:
       - IF corrupt or truncated content is located exclusively on the final line:
         - THEN ignore and drop the trailing corrupt fragment.
         - Replay the preceding $M$ valid events through pure reducer.
         - Sequence counter for subsequent appended events resumes at $M + 1$.
       - ELSE (corruption detected on any non-trailing line):
         - THEN throw fatal corruption error and abort replay.
     - Resume execution to completion and verify final event log sequence monotonicity without syntax errors.

3. Concurrency lock contention:
   - When attempting to acquire `.substrate/state/<run_id>.lock`:
     - IF lock file already exists:
       - Read lock payload `{ pid, run_id, acquired_at, heartbeat_at }`.
       - IF `isPidAlive(pid)` is true AND `Date.now() - heartbeat_at <= staleTimeoutMs`:
         - THEN lock is active.
         - Refuse acquisition; return `false`.
         - Engine throws active lock error; no state or log files are altered.
       - ELSE (PID is dead OR `Date.now() - heartbeat_at > staleTimeoutMs`):
         - THEN lock is stale.
         - Overwrite lock file with current PID and fresh heartbeat timestamp; return `true`.
         - Resume engine execution and maintain periodic heartbeat.
     - ELSE (lock file does not exist):
       - THEN write lock file with current PID and fresh timestamp; return `true`.
     - In engine `finally` block:
       - Clear heartbeat interval timer and remove `.substrate/state/<run_id>.lock`.

4. Live smoke testing (`test/live/**`):
   - IF `process.env.SUBSTRATE_LIVE !== "1"`:
     - THEN skip all live smoke tests and emit notification: `Live smoke tests skipped: SUBSTRATE_LIVE=1 not set`.
   - ELSE (`SUBSTRATE_LIVE === "1"`):
     - For each backend in `["claude", "opencode", "agy"]`:
       - Query CLI availability via `detectInstalledHarness(backend)`:
         - IF CLI binary is not installed on system PATH or configured binary path:
           - THEN skip test suite for that backend with descriptive skip notice.
         - ELSE:
           - Execute `adapter.validateEnvironment()`.
           - IF environment is invalid or version pin mismatch detected:
             - THEN fail or warn with environment report diagnostics.
           - Spawn minimal smoke worker with cheapest model, strict timeout (`timeout_min: 2`), and cost cap (`max_usd: 0.10`).
           - Verify session produces valid `SessionResult` or `WorkerReport` with structured events.
           - Verify usage accounting: `usage.cost_usd <= 0.10` and `usage.input_tokens > 0`.
           - Verify clean tear-down of worktree, backend processes, and session directories.
           - Assert that no API secrets or auth tokens appear in console output, stderr, or event files (I12).

## Invariants

- I1 (Code owns control flow): Event log replay deterministically reconstructs state via pure reducer; crash-recovery decisions and branch merges are never delegated to an LLM.
- I2 (Workers never grade themselves): In live smoke runs, engine executes acceptance verify commands and owns verdicts; worker text claims of success are untrusted.
- I5 (Models are explicit): Live smoke tests always pass explicit `--model` flags targeting the cheapest tier configured in the routing table.
- I7 (Hard budgets everywhere): Live smoke runs enforce a hard $0.10 cost cap and process timeout; exceeding budget triggers immediate process-group SIGKILL.
- I11 (No trust in exit codes): Live smoke adapters parse structured result payloads and event streams; zero exit codes from CLI tools do not imply success without valid outputs.
- I12 (No credential handling): Engine and test suites never inspect, copy, persist, or log auth tokens; live tests assert zero credential leakage in traces and logs.
- Replay determinism: For any sequence $k \in [1 \ldots N]$, replaying $E_1 \ldots E_k$ yields an `EngineState` identical to the runtime state at boundary $k$.
- Lock exclusivity: At most one running engine instance holds an active, non-stale lock on `.substrate/state/<run_id>.lock` at any given time.
- Torn-tail resilience: Truncation of an uncommitted partial last line never causes corruption errors or prevents subsequent valid event appending.

## Edge cases

- Crash immediately after writing `task.verify.finished` but before `task.passed`: On resume, engine reads verify result, transitions task to `PASSED`, and proceeds to merge without re-running verify commands.
- Crash during batch merge: Git index lock or intermediate worktree state exists. On resume, engine cleans up stale git lock files, re-runs `git merge-tree` preflight, and safely finishes integration merge.
- Crash during L0 heal resume: On resume, backend session handle is reconnected or fresh heal attempt is initiated with attempt counter preserved.
- Event log ends with empty newlines or whitespace lines: Parser handles trailing whitespace gracefully, treating it as clean EOF rather than a torn tail.
- Last line is partially written JSON (e.g., `{"seq": 5, "type":`): Parser catches syntax error, recognizes it is the terminal line, discards it, and allows resume from event 4.
- Non-terminal line corruption (e.g., line 2 of 5 is corrupt JSON): Parser throws fatal `Corruption error` to prevent undefined state divergence.
- Stale lock with recycled active PID: If the OS re-assigns the recorded PID to an unrelated active process, heartbeat timestamp age check (`> 30000 ms`) correctly identifies the lock as stale and permits recovery.
- Simultaneous lock acquisition race: When two processes execute `acquire()` concurrently, file write/check atomicity ensures exactly one succeeds and the other receives `false`.
- Live harness CLI missing or unauthenticated: If CLI is installed but user is unauthenticated, live test surfaces auth error cleanly without infinite retry or hang.
- Rate limit encountered in live test: If real provider returns rate limit HTTP 429, adapter maps error to `rate_limited` and engine pauses or backs off cleanly.

## Guardrails

- Cost guardrail: Live smoke tests MUST set `max_usd: 0.10` and `timeout_min: 2` (or `timeout_ms: 120000`). If budget is exceeded, budget governor terminates process immediately.
- CI safety: All live smoke test files under `test/live/**` MUST default to skipped unless environment variable `SUBSTRATE_LIVE=1` is explicitly set.
- Repository isolation: Chaos tests MUST execute within disposable temporary git repositories created via test helpers and MUST NEVER modify the working Substrate repository.
- File boundary restriction: P6.1 creates files ONLY in `test/integration/chaos/**` and `test/live/**`. Files in `src/contracts/**` and `src/util/**` are `protected` and must remain untouched.
- Process group cleanup: Chaos tests that simulate abrupt termination MUST send `SIGKILL` to the process group (`-pid`) to avoid leaking zombie child processes.

## Out of scope

- Interactive TUI chaos testing (covered in Phase 5 / P5.3).
- Randomized property fuzzing with infinite permutations (P6.1 focuses deterministically on all discrete event boundaries $1 \ldots N$ of multi-task scenarios).
- Modifying engine, reducer, or store source code (P6.1 is class `test`; issues discovered during hardening are tracked as defects or follow-up tasks).
- Benchmarking model output quality or multi-arm comparison (scheduled for Phase 6 / P6.3).
- Bubblewrap sandbox security auditing and secret pattern scrubbing (scheduled for Phase 6 / P6.2).
