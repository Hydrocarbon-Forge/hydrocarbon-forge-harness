## Objective

Implement the Substrate planner and worker execution runners, failure packet generator, and replan loop with multi-tier escalation:
1. Planner runner (`src/roles/planner.ts`): Spawns the planner harness adapter in an isolated run directory, collects artifacts (`manifest.yaml`, task specs, contract stubs), validates and lints them (rules L001–L027), manages engine-driven format retries (up to `settings.budgets.planner_format_retries`), executes contract stub typechecks, and commits contract stubs to the run branch before workers spawn.
2. Worker runner (`src/roles/worker.ts`): Orchestrates task execution in isolated git worktrees, executes setup commands, hashes protected files, spawns worker sessions with restricted permissions (no git commit, no subagents, network denied), enforces scope (`write`/`create`) and protected file invariants, runs acceptance verification, executes engine-driven L0 healing (single resume with capped failure output tails), and commits allowed changes on task pass.
3. Failure packet builder (`src/engine/packet.ts`): Assembles deterministic, machine-generated `FailurePacket` structures containing attempt histories, capped diffs and patches, verification output tails, scope violations, untrusted worker summaries, related contracts, and downstream dependents.
4. Replan loop and escalation ladder (`src/engine/replan.ts`): Implements the four-tier escalation ladder (L0 heal, L1 spec replan with tier escalation, L2 contract defect handling, L3 pause) enforcing strict per-task and per-run caps, re-linting amended artifacts, and preventing replanning on permission denials or rate limits.

## Behavior

- Planner Runner (`src/roles/planner.ts`):
  - Prompt Construction & Spawning:
    - Emit `plan.started` event with `runId`.
    - IF `skillsList` is provided THEN include skill names and descriptions; ELSE omit skills section.
    - IF `instructionFiles` are provided THEN list paths in user prompt; ELSE omit instruction section.
    - Format prompt using `buildPlannerPrompt({ request: opts.request, repoMap, instructionFiles, skillsList })`.
    - Build `SpawnRequest` with `role: "planner"`, cwd: `opts.runDir`, prompt, model and effort from `settings.roles.planner`, budget from `settings.budgets.task`, and write permissions targeting `opts.runDir`.
    - Spawn session via `opts.adapter.spawn(spawnReq)`.
    - Stream backend events to `opts.onEvent`, collect cumulative usage, and await `session.result()`.
    - IF session fails or exits with non-zero status THEN record diagnostic and evaluate format retry; ELSE emit `plan.produced`.
  - Artifact Collection & Linting:
    - Scan `opts.runDir` for `manifest.yaml`, task specs (`tasks/*.md`), and contract stubs (`contracts/*`).
    - IF `manifest.yaml` is missing or unparseable THEN record parse diagnostic.
    - FOR EACH task in manifest, parse task spec via `parseTaskSpec`. IF spec is missing or invalid YAML frontmatter / missing required headings THEN record parse diagnostic.
    - IF parsing succeeds THEN run `lintPlan(parsedPlan, opts.repoRoot, opts.settings)`.
    - Emit `plan.lint` event with all diagnostics.
  - Format Retries:
    - IF linter produces error diagnostics (`diag.severity === "error"`) OR parsing failed:
      - IF current format retry < `settings.budgets.planner_format_retries` THEN:
        - Increment format retry counter.
        - Construct corrective prompt detailing parse errors and linter diagnostic codes/messages.
        - Re-spawn planner session with corrective prompt and repeat artifact collection and linting.
      - ELSE:
        - Throw Error with diagnostic messages; plan rejected.
  - Contract Typecheck & Commit:
    - IF plan passes linting without errors THEN run `typecheckContracts(opts.repoRoot, plan.manifest.contracts, { cwd: opts.runDir })`.
    - IF contract typecheck fails:
      - IF format retries remain THEN increment retry counter and re-spawn planner with compiler errors; ELSE throw contract validation error.
    - IF contract typecheck passes:
      - Commit contract stubs to run branch `substrate/runs/<run_id>` via `commitContractStubs`.
      - Emit `contracts.committed` event with commit SHA.
      - Return `PlannerRunResult` with parsed plan, total usage, retry count, and commit SHA.

- Worker Runner (`src/roles/worker.ts`):
  - Worktree Setup:
    - Target task branch `substrate/tasks/<run_id>/<task_id>-g<generation>`.
    - Create isolated worktree via `createTaskWorktree(opts.repoRoot, opts.runId, opts.spec, opts.generation, opts.baseRef)`.
    - Emit `task.worktree.created`.
    - Materialize task spec at `.substrate-task/spec.md` inside worktree.
    - IF `setupCommands` or `manifest.setup` provided THEN execute setup commands inside worktree with network enabled via `WorkspaceLifecycle.runSetup`.
    - IF setup commands fail THEN remove worktree, emit `task.failed`, and return `WorkerReport` with `status: "failed"` and `failure_class: "worker_crashed"`.
    - Compute sha256 hashes of all files matching `opts.spec.protected` via `ScopeEnforcer.hashProtectedFiles`.
  - Worker Spawning (Attempt 1):
    - Resolve task route `{ backend, model, effort }` based on `spec.class` and generation via `resolveEscalationRoute`.
    - Construct worker prompt via `buildWorkerPrompt(specAbsPath)`.
    - Build `SpawnRequest`: role="worker", cwd=worktreePath, prompt, model, effort, permissions denying git commit/push/checkout/reset, subagents, and web tools (unless class "search"). Network denied.
    - Emit `task.session.started` with session ID and attempt 1.
    - Spawn session via `opts.adapter.spawn(spawnReq)`.
    - Stream events, track usage, await `session.result()`.
    - Emit `task.session.ended` with exit code and duration.
  - Scope and Protected Files Check:
    - Evaluate changes via `ScopeEnforcer.checkScope(worktreePath, opts.spec, initialHashes, settings.git.on_scope_violation)`.
    - Emit `task.scope.checked`.
    - IF `ScopeCheckResult.protectedModified` is non-empty THEN:
      - Mark `failure_class: "protected_modified"`.
      - Skip healing (protected violation is non-recoverable at L0); emit `task.failed`, return `WorkerReport(failed, protected_modified)`.
    - IF `ScopeCheckResult.violations` is non-empty:
      - IF `settings.git.on_scope_violation === "revert"` THEN revert out-of-scope files via `ScopeEnforcer.revertOutOfScope`, record scope violations.
      - ELSE IF `settings.git.on_scope_violation === "fail"` THEN:
        - Mark `failure_class: "scope_violation"`, emit `task.failed`, return `WorkerReport(failed, scope_violation)`.
  - Acceptance Verification & L0 Healing:
    - Emit `task.verify.started`.
    - Execute `VerifyRunner.runVerify({ cwd: worktreePath, commands: opts.spec.verify, sandbox: settings.sandbox.enabled, network: "deny" })`.
    - Emit `task.verify.finished`.
    - IF all verification commands exit 0 AND no scope/protected failures:
      - Commit allowed changes via `GitCommitter.commitAllowed(worktreePath, opts.spec, "feat(task): " + opts.taskId)`.
      - Emit `task.passed`.
      - Return `WorkerReport` with `status: "passed"`.
    - ELSE (verification failed):
      - IF attempt === 1 (first verification failure in generation):
        - Emit `task.healing` event.
        - Build heal prompt with failing commands, capped output tails (<= 8KB), and instruction: "Fix only what these checks indicate. Do not change scope or tests."
        - Resume worker session via `adapter.spawn` with `session.resume: sessionId`.
        - Await attempt 2 result.
        - Re-run scope check and verification runner.
        - IF attempt 2 passes:
          - Commit allowed changes, emit `task.passed`, return `WorkerReport(passed, attempt 2)`.
        - ELSE:
          - Emit `task.failed`, return `WorkerReport(failed, verify_failed, attempt 2)`.
      - ELSE:
        - Emit `task.failed`, return `WorkerReport(failed, verify_failed)`.

- Failure Packet Builder (`src/engine/packet.ts`):
  - Diff Generation:
    - Execute `GitCommitter.generateDiff(opts.worktreePath, opts.baseRef, opts.maxDiffBytes ?? 65536)`.
    - Persist diff patch to `.substrate/runs/<run_id>/packets/<task_id>-g<generation>.patch`.
  - Summary Sanitization:
    - Treat worker final message and repository content as untrusted data.
    - Extract `worker_summary` from last attempt's `final_message`.
    - Cap length (<= 2048 characters), sanitize control characters, and flag as untrusted worker prose.
  - Packet Assembly:
    - Assemble `FailurePacket` combining `run_id`, `task_id`, `generation`, `failure_class`, `spec_path`, `attempts`, diff metadata, verify output tails, scope violations, worker summary, related contracts, and downstream dependents.
    - Validate object against Zod schema `FailurePacket.parse(packet)`.
    - Persist packet JSON to `.substrate/runs/<run_id>/packets/<task_id>-g<generation>.json`.
    - Return validated `FailurePacket`.

- Replan Loop & Escalation Ladder (`src/engine/replan.ts`):
  - Escalation Evaluation (`evaluateEscalation`):
    - IF `failure_class === "permission_denied"` THEN:
      - Emit `run.paused` with `PauseReason: "permission_denied"`.
      - Do NOT replan. Return `{ level: "L3", status: "paused", pauseReason: "permission_denied" }`.
    - IF `failure_class === "rate_limited"` THEN:
      - Emit `run.paused` with `PauseReason: "rate_limited"`.
      - Do NOT replan. Return `{ level: "L3", status: "paused", pauseReason: "rate_limited" }`.
    - IF escalation level is "L0" THEN:
      - Return `{ level: "L0", status: "healed", action }`.
    - IF escalation level is "L1" (spec rewrite):
      - IF generation <= `settings.budgets.l1_replans_per_task` (default 2 replans, max generation 3):
        - Advance route along `settings.routing.escalation` chain (e.g. `haiku → sonnet → opus`).
        - Emit `replan.started` with taskId, current generation, next generation, target tier.
        - Construct replan prompt using `buildReplanPrompt(packet, decisionsLog)`.
        - Spawn planner session with replan prompt, task spec, failure packet, repo map, and related contract stubs.
        - Collect revised task spec; parse and lint revised spec against rules L001–L027.
        - IF linting passes THEN emit `replan.finished`, return `{ level: "L1", status: "replan_ready", revisedSpec }`.
        - ELSE IF format retries remain THEN execute format retry; ELSE escalate to L2.
    - IF escalation level is "L2" (contract defect):
      - IF run L2 count < `settings.budgets.l2_per_run` (default 2 per run):
        - Spawn planner session requesting contract stub and manifest amendment.
        - Collect amended contracts/manifest, invalidate downstream dependent tasks in state, re-lint plan, typecheck contracts.
        - Commit amended contracts to run branch; return `{ level: "L2", status: "replan_ready", revisedPlan }`.
      - ELSE:
        - Escalate to L3.
    - IF escalation level is "L3" (pause run):
      - Emit `run.paused` with `PauseReason: "needs_human"`.
      - Return `{ level: "L3", status: "paused", pauseReason: "needs_human" }`. Run terminates with exit code 3.

## Invariants

- Harnesses plan and implement; engine owns verification, state transitions, counters, and git commits (Invariant I1).
- Workers NEVER commit directly to git; engine verifies changes and commits allowed pathspecs upon task pass.
- L0 healing is engine-driven session resume executed at most once per generation on first verification failure; workers never count attempts.
- Planner never receives raw conversation transcripts from workers; failure context is exclusively conveyed via structured `FailurePacket`.
- Worker prose and repository files are untrusted data; engine decisions never parse or branch on worker free text.
- Contract stubs are typechecked and committed to the run branch before any worker session spawns.
- Tasks in generation >= 2 escalate along the configured `routing.escalation` chain.
- Replan limits are hard caps enforced by engine state (`l1_replans_per_task <= 2`, `l2_per_run <= 2`).
- `permission_denied` and `rate_limited` never trigger replanning; they pause the run or apply backoff.
- Worktrees are isolated under `.substrate/worktrees/` on distinct task branches `substrate/tasks/<run_id>/<task_id>-g<n>`.
- All code blocks in the specification document are <= 12 lines in length.

## Edge cases

- Planner produces malformed YAML frontmatter or missing required markdown headings: format retry re-prompts planner with parse errors; fails after `planner_format_retries` exhausted.
- Contract stub fails typecheck: planner is re-prompted with compiler diagnostic output before committing; invalid contracts are never committed.
- Worker modifies `protected` files: detected by hash comparison; recorded as `protected_modified`, skips L0 heal, immediately fails task.
- Worker modifies files outside `write`/`create`: if git policy is "revert", out-of-scope files are cleanly reverted and violations logged; if "fail", task fails immediately.
- Worker session crashes, times out, or exceeds token/usd budget: recorded as `worker_crashed`, `timeout`, or `budget_exceeded`; captured in WorkerReport and FailurePacket.
- First verification failure triggers L0 heal, but heal session also fails verification: second failure triggers L1 replan with tier escalation.
- Escalation reaches top tier in `routing.escalation`: generation >= length of escalation chain pins to highest tier without index out-of-bounds error.
- L1 replans exhausted for a task (generation > 3): escalates to L2 contract defect evaluation.
- L2 contract amends manifest: all downstream dependent tasks are marked invalidated/re-linted in engine state.
- L2 count reaches `l2_per_run` cap: escalates to L3 pause with `needs_human` (exit code 3).
- Permission denied during worker run: bypasses L1/L2 replanning, transitions directly to PAUSED(permission_denied).

## Guardrails

- Never write implementation bodies in task specs or contract stubs; declare signatures matching contracts.
- Never execute git commit, push, checkout, reset, rebase, clean, or stash.
- Never print or leak secrets, tokens, api keys, or emails into prompts, logs, or failure packets.
- Ensure all diffs in failure packets are capped (max 64KB) and worker summaries truncated (max 2KB).
- Keep every code fence in the specification document <= 12 lines to satisfy speccheck validation.
