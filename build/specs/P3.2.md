## Objective

Implement the Claude adapter package for Substrate: a stream normalizer (`src/backends/normalize/claude.ts`) that transforms Claude Code headless `stream-json` NDJSON events into authoritative `BackendEvent` objects and extracts structured `SessionResult` records (including token usage, reported cost, tool call/results, and permission denials); a harness adapter (`src/backends/adapters/claude.ts`) satisfying `HarnessAdapter` that builds complete headless CLI invocations, enforces environment scrubbing, manages process isolation via process groups, persists raw streams to `raw/<session_id>.ndjson`, and validates the installed CLI against the pinned version 2.1.301; a unit golden test suite (`test/unit/backends/normalize-claude.test.ts`) driven by real captured fixtures from `test/fixtures/backends/claude/`; and an integration test suite (`test/integration/backends/claude.test.ts`) executing the shared adapter conformance battery against the Claude adapter.

## Behavior

- CLI Invocation & Argument Synthesis (`src/backends/adapters/claude.ts`):
  - Headless Run & Output Format:
    - IF building arguments for `spawn(req)` THEN prepend `-p` followed by `req.prompt`.
    - IF headless stream output is required THEN append `--output-format stream-json` and `--verbose`.
  - Model & Effort:
    - IF `req.model` is specified THEN append `--model` followed by `req.model`.
    - IF `req.effort` is specified THEN append `--effort` followed by `req.effort`.
    - ELSE omit `--effort`.
  - Session Identity & Continuation:
    - IF `req.session?.resume` is present THEN append `--resume` followed by `req.session.resume`.
    - ELSE IF `req.session?.id` is present THEN append `--session-id` followed by `req.session.id`.
    - ELSE generate a new UUIDv4 session identifier and append `--session-id` followed by the generated ID.
  - Permission Gating & Tool Restrictions:
    - IF configuring permissions THEN append `--permission-mode dontAsk` and `--permission-prompts none`.
    - IF `req.permission.allow` contains non-empty list of tool names THEN append `--allowedTools` followed by comma-joined string.
    - IF configuring disallowed tools THEN append `--disallowedTools` with `Agent` (headless subagents denied per §10/§11.2) combined with any tool names in `req.permission.deny`.
  - Native Budget Cap:
    - IF `req.budget.max_usd` is defined and > 0 THEN append `--max-budget-usd` followed by `req.budget.max_usd.toString()`.
    - ELSE omit `--max-budget-usd`.

- Environment Scrubbing (`src/backends/adapters/claude.ts`):
  - Variable Allowlisting:
    - IF creating environment for child process THEN initialize allowlist with essential system variables (`PATH`, `HOME`, `USER`, `SHELL`, `LANG`, `LC_ALL`, `TERM`, `TMPDIR`).
    - IF `req.env` supplies additional environment variables THEN merge them into scrubbed environment.
    - IF parent process environment contains arbitrary or secret-bearing variables outside allowlist THEN exclude them.

- Raw Stream Persistence (`src/backends/adapters/claude.ts`):
  - Directory & File Initialization:
    - IF session is spawned THEN ensure directory `<req.cwd>/raw` exists (creating via `mkdirSync(..., { recursive: true })` if absent).
    - IF stdout chunks are received from supervised process THEN pipe or write raw bytes directly to `<req.cwd>/raw/<session_id>.ndjson`.
    - IF raw write stream encounters an error THEN log error without terminating session stream processing.

- Process Supervision & Session Handle (`src/backends/adapters/claude.ts`):
  - Process Spawning:
    - IF `spawn(req)` is invoked THEN spawn process using `spawnSupervisedProcess` with `options.command` set to `this.options.bin ?? "claude"`, synthesized arguments, working directory `req.cwd`, scrubbed environment, and timeout `req.budget.timeout_ms`.
    - IF process spawns successfully THEN return `SessionHandle` containing process PID, async iterable `events`, `result()`, and `kill()`.
  - Termination & Cancellation:
    - IF `handle.kill(reason)` is invoked THEN forward call to `proc.kill(reason)` to terminate process group using staged `SIGTERM` followed by `SIGKILL` escalation.
    - IF session is terminated via `kill` THEN ensure resolved `SessionResult` records `killed_for: reason` and `ok: false`.

- Environment Validation (`src/backends/adapters/claude.ts`):
  - Version Check:
    - IF `validateEnvironment()` is invoked THEN execute `<bin> --version` with timeout.
    - IF executable is missing (ENOENT) OR command fails with non-zero exit THEN return `EnvReport` with `ok: false`, `pin_matches: false`, and `problems: ["Claude CLI binary not found or failed to execute"]`.
    - ELSE IF command succeeds THEN extract semver version string from output.
      - IF extracted version matches `CLAUDE_VERSION_PIN` ("2.1.301") THEN return `EnvReport` with `ok: true`, `pin_matches: true`, and empty `problems`.
      - ELSE return `EnvReport` with `ok: true`, `pin_matches: false`, and `problems: ["Installed version <version> differs from pinned version 2.1.301"]`.

- Event Normalization (`src/backends/normalize/claude.ts`):
  - Session Initialization:
    - IF raw event has `type: "system"` and `subtype: "init"` THEN emit `BackendEvent` of type `session.started` with `session_id`.
  - Assistant Text & Tool Invocations:
    - IF raw event has `type: "assistant"` with `message.content` array THEN iterate content blocks:
      - IF block has `type: "text"` AND non-empty string THEN emit `BackendEvent` of type `assistant.text` with `text: block.text`.
      - IF block has `type: "tool_use"` THEN emit `BackendEvent` of type `tool.call` with `id: block.id`, `name: block.name`, and `input_summary: JSON.stringify(block.input ?? {})`.
      - IF block has `type: "thinking"` THEN skip block without emitting text event.
  - Tool Execution Results:
    - IF raw event has `type: "user"` with `message.content` array containing `type: "tool_result"` blocks THEN iterate blocks:
      - Emit `BackendEvent` of type `tool.result` with `id: block.tool_use_id`, `ok: !block.is_error`, and `output_summary: typeof block.content === "string" ? block.content : JSON.stringify(block.content ?? "")`.
  - Permission Denials:
    - IF raw event has `type: "system"` and `subtype: "permission_denied"` THEN emit `BackendEvent` of type `permission.denied` with `tool: raw.tool_name` and `reason: raw.message`.
  - Rate Limiting:
    - IF raw event has `type: "rate_limit_event"`:
      - IF `rate_limit_info.status === "allowed"` THEN skip event without error.
      - ELSE emit `BackendEvent` of type `error` with `kind: "rate_limit"` and descriptive `message`.
  - Result Event & Usage:
    - IF raw event has `type: "result"`:
      - Parse token counts from `raw.usage`: `input_tokens`, `output_tokens`, `cache_creation_input_tokens` (mapped to `cache_write_tokens`), `cache_read_input_tokens` (mapped to `cache_read_tokens`), and `output_tokens_details.thinking_tokens` (mapped to `reasoning_tokens`).
      - IF `raw.total_cost_usd` is a finite number THEN record `cost_usd: raw.total_cost_usd` with `cost_source: "reported"`.
      - ELSE record `cost_usd: 0` with `cost_source: "computed"`.
      - Emit `BackendEvent` of type `usage` with constructed `UsageRecord` and `cumulative: true`.
      - IF `raw.permission_denials` contains non-empty entries THEN emit `BackendEvent` of type `permission.denied` for each entry not previously emitted.
      - IF `raw.subtype === "success"` AND `!raw.is_error` THEN emit `BackendEvent` of type `session.result` with `ok: true`, `stop_reason: raw.stop_reason`, `final_text: raw.result ?? ""`, `usage`, and `exit_code: 0`.
      - ELSE IF `raw.subtype === "error_max_budget_usd"` THEN emit `BackendEvent` of type `session.result` with `ok: false`, `stop_reason: "budget_exceeded"`, `final_text: raw.result ?? ""`, `usage`, and `exit_code: 1`.
      - ELSE emit `BackendEvent` of type `session.result` with `ok: false`, `stop_reason: raw.subtype ?? "error"`, `final_text: raw.result ?? ""`, `usage`, and `exit_code: 1`.

- Session Result Synthesis (`src/backends/normalize/claude.ts`):
  - Result Aggregation:
    - IF `session.result` event is found in normalized events THEN assemble `SessionResult` using event `ok`, `session_id`, `final_text`, `usage`, exit code, aggregated `denials`, and optional `killed_for`.
    - ELSE IF process terminated without `session.result` event:
      - IF `killedFor` is defined THEN assemble `SessionResult` with `ok: false`, `killed_for: killedFor`, `final_text: ""`, default zero usage record, and exit code.
      - ELSE assemble `SessionResult` with `ok: false`, `final_text: "Process exited unexpectedly without session result"`, default zero usage record, and exit code.

## Invariants

- Structured result over exit code (Plan §11.1 requirement 2 / invariant I11): adapter never uses process exit code alone to determine success; success is evaluated strictly via structured result event.
- Explicit model and effort (Plan §11.1 requirement 1 / invariant I5): adapter always passes `--model` explicitly and `--effort` when provided.
- Raw stream persistence (Plan §11.1 requirement 3): child process stdout is written byte-for-byte to `raw/<session_id>.ndjson` for auditability and replay.
- Tool denial capture (Plan §11.1 requirement 4): all tool permission denials from stream events and `result.permission_denials` are captured in `SessionResult.denials`.
- Native subagent gating (Plan §10, §11.2): `Agent` tool is always included in `--disallowedTools` to prevent unsupervised background subagents.
- Process group isolation: child processes are spawned in detached process groups and terminated via negative PID (`-pgid`) with staged `SIGTERM` to `SIGKILL` escalation.
- Strict contract adherence: all normalized events satisfy `BackendEvent` Zod schema; all results satisfy `SessionResult` Zod schema; adapter exposes capabilities satisfying `Capabilities` schema.
- Import boundaries: `src/backends/adapters/claude.ts` and `src/backends/normalize/claude.ts` import strictly from `src/contracts/**`, `src/util/**`, and sibling `backends` modules. They never import from `engine`, `git`, `spec`, `verify`, `roles`, `config`, `ledger`, `cli`, or `tui`.

## Edge cases

- Abnormal child termination before result: child process exits prematurely (e.g. SIGKILL, crash, or OOM); adapter handles missing result event, emits typed crash/protocol error, and returns `SessionResult` with `ok: false`.
- Tool denial under `dontAsk` mode with exit 0: Claude denies command execution in `dontAsk` mode, returns `result.subtype: success` with `permission_denials` array, and exits 0; adapter records denial in `denials` array and surfaces denial events.
- Budget overshoot with exit 1: Claude halts execution upon reaching `--max-budget-usd`, writes `error_max_budget_usd` result payload, and exits 1; adapter extracts full usage and marks `ok: false` with budget reason.
- Allowed rate limit notifications: Claude streams periodic `rate_limit_event` items with `status: "allowed"`; normalizer ignores these items without triggering false rate limit errors.
- Cryptographic thinking signatures: Claude output containing `thinking` content blocks is ignored for `assistant.text` events, while thinking token metrics are accumulated in `UsageRecord.reasoning_tokens`.
- Missing or null cost fields: when `total_cost_usd` is null or omitted in the result payload, adapter marks `cost_source: "computed"` and computes cost if pricing table is supplied or defaults to 0.
- Raw output directory creation race: multiple concurrent sessions safely create `raw/` directory via recursive directory creation without failing if already present.
- Process exit during kill signal: if process exits cleanly before `SIGKILL` escalation timer elapses, pending kill timers are cleared without uncaught rejections.

## Open questions

- Does Claude Code headless support a dedicated flag for structured JSON schema validation? As of Claude Code 2.1.301, structured schema adherence in headless mode is enforced through prompt guidance and tool definitions rather than a native `--json-schema` argument, so `capabilities.structured_output` is declared `false`.
- Should `raw/<session_id>.ndjson` persistence default to `req.cwd/raw` or an engine-level artifact directory? The adapter persists to `join(req.cwd, "raw", `${sessionId}.ndjson`)`, ensuring directory creation if missing.
