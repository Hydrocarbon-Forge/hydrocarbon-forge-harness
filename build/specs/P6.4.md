## Objective

Deliver comprehensive project documentation, documentation verification tooling, and packaging automation for Substrate v0.3:
1. Root documentation (`README.md`):
   - Architecture overview: Deterministic orchestration engine driving external peer agent harnesses (Claude Code, OpenCode, Antigravity) without privileged backends.
   - Core subsystem summary: State core (JSONL event log, DAG scheduler, ladder, ledger), Git workspace (worktrees, scope checker, merge gate), Backends (process supervisor, normalizers, adapters), Roles (governor front door, planner, workers, reviewer), Surface (headless CLI & interactive TUI).
   - Quickstart guide: System prerequisites (Node >= 22, Git, installed harnesses), installation, initialization (`substrate init`), health check (`substrate doctor`), and first run.
   - CLI usage guide: Interactive and headless modes (`-p`/`run`), common execution flags, session continuation.
   - Configuration summary: Precedence chain, basic JSONC configuration layout, routing table, and budgets.
   - Benchmark summary: Overview of Arms A–D and evaluation commands (`substrate bench`).
2. Configuration reference (`docs/reference/config.md`):
   - Full `settings.json` schema documenting all keys in `Contracts.Settings` (`backends`, `roles`, `routing`, `pricing`, `budgets`, `concurrency`, `permissions`, `sandbox`, `git`, `instructions`, `execution`, `hooks`).
   - Resolution precedence hierarchy: defaults < user config < project config < local config < CLI settings file < environment variables (`SUBSTRATE_*`) < CLI flags.
   - Environment variables reference: `SUBSTRATE_LIVE`, `SUBSTRATE_SETTINGS`, `SUBSTRATE_CONFIG_DIR`, `SUBSTRATE_PROJECT_DIR`, `SUBSTRATE_PERMISSION_MODE`, `SUBSTRATE_MAX_BUDGET_USD`, `SUBSTRATE_OUTPUT_FORMAT`, `SUBSTRATE_MODEL`, `SUBSTRATE_WORKER_MODEL`.
   - Object merging rules vs array/scalar replacement semantics.
3. CLI reference (`docs/reference/cli.md`):
   - Comprehensive reference of all 20 CLI subcommands: `run`, `plan`, `resume`, `status`, `tasks`, `cost`, `report`, `verify`, `merge`, `undo`, `discard`, `models`, `agents`, `backends`, `sessions`, `config`, `doctor`, `init`, `bench`, `agents-import`.
   - Global and governance flags: `-p`/`--print`, `--output-format`, `--model`, `--worker-model`, `--effort`, `--session-id`, `--resume`, `-c`/`--continue`, `--fork-session`, `--mode`, `--no-governor`, `--permission-mode`, `-w`/`--worktree`, `--max-budget-usd`, `--timeout`, `--sandbox`, `--settings`, `--allowed-tools`, `--disallowed-tools`.
   - Standard exit codes: 0 (success), 1 (run failure), 2 (usage/config error), 3 (needs human), 4 (budget exhausted), 130 (SIGINT), 143 (SIGTERM).
4. Adapter development guide (`docs/reference/adapters.md`):
   - Harness adapter architecture, protocol, and symmetric peer philosophy.
   - Interface contracts: `HarnessAdapter`, `Capabilities`, `SpawnRequest`, `SessionHandle`, `BackendEvent`, `SessionResult`.
   - Mandatory adapter obligations (§11.1): Explicit model/effort passing, structured result parsing, raw stream persistence, normalized denial reporting, computed cost fallbacks, session resume, worktree isolation, env scrubbing, version pin verification, concurrency limits.
   - Conformance testing and `FakeAdapter` integration.
5. Documentation integrity checker (`scripts/docs-check.mjs`):
   - Validates existence of all required documentation files and anchors.
   - Validates all relative links across documentation markdown files.
   - Verifies 100% CLI command coverage against `src/cli/registry.ts` and command modules.
   - Verifies 100% configuration key coverage against `Contracts.Settings`.
   - Exits 0 on clean pass; exits 1 with line-numbered diagnostic errors on failure.
6. Packaging and bundling script (`scripts/bundle.mjs`):
   - Standalone bundle compilation using `esbuild` targeting Node 22 ESM.
   - Verifies packaging prerequisites and bundle integrity.
   - Ensures successful `npm pack --dry-run` package generation.

## Behavior

- Root documentation (`README.md`):
  - IF a user opens `README.md` THEN present:
    - High-level architecture overview highlighting multi-harness orchestration without privileged backends.
    - Prerequisites: Node.js >= 22, Git >= 2.30, and at least one CLI backend (`claude`, `opencode`, or `agy`).
    - Quickstart workflow: `npm install` -> `bin/substrate.mjs init` -> `bin/substrate.mjs doctor` -> `bin/substrate.mjs "Goal"`.
    - CLI usage examples contrasting interactive TUI mode with headless `-p` execution.
    - Configuration summary referencing `.substrate/settings.json` and precedence hierarchy.
    - Benchmark summary referencing Arms A–D and `substrate bench`.
  - ELSE provide links to comprehensive deep-dive guides under `docs/reference/`.

- Configuration reference (`docs/reference/config.md`):
  - IF describing configuration resolution THEN document the strict 7-layer precedence order:
    - Layer 1: Embedded default settings (`DEFAULT_SETTINGS`).
    - Layer 2: User global settings (`~/.config/substrate/settings.json`).
    - Layer 3: Project repository settings (`.substrate/settings.json`).
    - Layer 4: Project local overrides (`.substrate/settings.local.json`).
    - Layer 5: Explicit settings file supplied via `--settings <file>`.
    - Layer 6: Environment variables (`SUBSTRATE_*`).
    - Layer 7: Command-line execution flags (e.g., `--model`, `--max-budget-usd`, `--permission-mode`).
  - IF merging settings objects THEN:
    - Plain objects merge recursively key-wise.
    - Primitives, arrays, and `pricing` replace completely.
  - IF evaluating environment variables THEN document:
    - `SUBSTRATE_LIVE`: Boolean ("1") enabling opt-in live harness calls.
    - `SUBSTRATE_SETTINGS`: Path string to settings JSONC file.
    - `SUBSTRATE_CONFIG_DIR`: Path string overriding `~/.config/substrate`.
    - `SUBSTRATE_PROJECT_DIR`: Path string overriding project root directory.
    - `SUBSTRATE_PERMISSION_MODE`: String literal overriding permission mode.
    - `SUBSTRATE_MAX_BUDGET_USD`: Numeric string overriding run budget cap.
    - `SUBSTRATE_OUTPUT_FORMAT`: String literal overriding output format.
    - `SUBSTRATE_MODEL`: String overriding primary planner/solo model.
    - `SUBSTRATE_WORKER_MODEL`: String overriding worker model across routes.

- CLI reference (`docs/reference/cli.md`):
  - IF documenting CLI subcommands THEN specify syntax, arguments, options, and behaviors for all 20 subcommands:
    - `run`: Headless execution of a goal prompt.
    - `plan`: Plan, lint, and cost estimation without worker dispatch.
    - `resume`: Resume paused or interrupted run from event log.
    - `status`: Show run state, task breakdown, and failure counts.
    - `tasks`: Detailed inspection of individual tasks and worktrees.
    - `cost`: Usage ledger cost breakdown by role, model, and task.
    - `report`: Output run summary report in text or JSON.
    - `verify`: Re-run acceptance verify commands in task worktree.
    - `merge`: Apply completed run branch into working branch.
    - `undo`: Revert the most recently merged run batch.
    - `discard`: Cancel and delete a run branch and worktrees.
    - `models`: List configured models, pricing, and routing mappings.
    - `agents`: List registered agent definitions and roles.
    - `backends`: Display adapter capabilities, version pins, and CLI status.
    - `sessions`: List interactive and headless sessions.
    - `config`: Inspect or set settings key-value pairs (`get`, `set`, `list`).
    - `doctor`: Verify environment health, version pins, and dependencies.
    - `init`: Scaffold `.substrate/` configuration directory and template.
    - `bench`: Run benchmark suites across comparison Arms A–D.
    - `agents-import`: Import agent definitions from Claude Code or OpenCode.
  - IF documenting exit codes THEN document exact exit code mappings:
    - `0`: Success.
    - `1`: Run failure (verify failed, spec error, crash).
    - `2`: Usage or configuration error.
    - `3`: Needs human intervention (gate approval, denial, escalation).
    - `4`: Budget exhausted (USD, token, or timeout cap).
    - `130`: SIGINT interruption.
    - `143`: SIGTERM termination.

- Adapter reference (`docs/reference/adapters.md`):
  - IF documenting adapter requirements THEN detail:
    - The `HarnessAdapter` interface and lifecycle methods (`validateEnvironment`, `spawn`).
    - The `Capabilities` contract specifying feature flags and version pins.
    - The streaming event contract `BackendEvent` and `SessionHandle`.
    - The 11 core adapter obligations defined in §11.1.
    - The conformance test suite structure (`test/conformance/suite.ts`) and test runner.
    - The `FakeAdapter` reference implementation and scenario scripting.

- Documentation check script (`scripts/docs-check.mjs`):
  - IF `npm run docs:check` is executed THEN:
    - Step 1: Verify presence of all expected markdown documents (`README.md`, `docs/reference/config.md`, `docs/reference/cli.md`, `docs/reference/adapters.md`).
    - Step 2: Parse markdown AST or regex tokens to extract all relative links and verify that target files and anchors exist on disk.
    - Step 3: Scan `src/cli/registry.ts` and `src/cli/commands/*.ts` (or query CLI registry) to extract all command names; verify that each command name has a dedicated section in `docs/reference/cli.md`.
    - Step 4: Scan `Contracts.Settings` keys and verify that each top-level key is documented in `docs/reference/config.md`.
    - Step 5: Verify markdown code block fences are closed and contain valid language tags.
    - IF any diagnostic error is found THEN print line-numbered error diagnostics to stderr and exit 1.
    - ELSE print confirmation notice and exit 0.

- Bundle script (`scripts/bundle.mjs`):
  - IF `npm run bundle` is executed THEN:
    - Step 1: Invoke `esbuild.build` targeting Node 22 ESM with entrypoint `bin/substrate.mjs` or `src/cli/index.ts`.
    - Step 2: Mark node built-ins (`node:*`) and binary packages as external.
    - Step 3: Emit bundled artifact to `dist/substrate.mjs` with executable banner `#!/usr/bin/env node`.
    - Step 4: Verify output bundle exists, has non-zero size, and passes syntax verification via `node --check dist/substrate.mjs`.
    - Step 5: Print bundle summary (path, byte size, build duration) and exit 0.
    - ELSE IF build fails THEN report error to stderr and exit 1.

- Packaging verification (`npm pack --dry-run`):
  - IF `npm pack --dry-run` is executed THEN:
    - Validate that tarball contains all necessary runtime files (`bin/`, `dist/` or `src/`, `package.json`, `README.md`, `LICENSE` if present).
    - Validate that no unauthorized test artifacts, scratch directories, or temp files are included.
    - Exit 0 upon successful dry-run tarball assembly.

## Invariants

- Document accuracy: All documented commands, options, configuration keys, and adapter behaviors must match codebase implementations exactly.
- Link integrity: Every relative file link and anchor in documentation must resolve to a valid existing file and heading.
- Zero undocumented CLI commands: Every command in `src/cli/commands/` and `src/cli/registry.ts` must have a documented entry in `docs/reference/cli.md`.
- Zero undocumented configuration keys: Every key in `Contracts.Settings` must have a documented entry in `docs/reference/config.md`.
- Clean boundary enforcement: Docs check and bundle scripts must not import prohibited internal layers or violate `scripts/check-boundaries.mjs`.
- Secret privacy (I12): No secret tokens, credentials, or actual API keys may appear anywhere in documentation, example configs, or bundle outputs.
- Deterministic bundling: Packaging scripts must produce consistent, reproducible output without side effects on Git working tree.

## Edge cases

- Missing documentation file: `scripts/docs-check.mjs` reports missing file path and exits 1 immediately.
- Broken markdown anchor link (e.g., `[label](#missing-heading)`): `scripts/docs-check.mjs` validates target heading exists and reports error if missing.
- New subcommand added to CLI registry: `scripts/docs-check.mjs` catches the discrepancy and demands documentation before passing.
- New configuration key added to `Contracts.Settings`: `scripts/docs-check.mjs` flags the undocumented setting key.
- Missing `dist/` directory during bundling: `scripts/bundle.mjs` creates output directory recursively prior to writing bundle.
- Bundle output fails syntax check: `scripts/bundle.mjs` removes corrupt output and exits 1 with compiler diagnostics.
- Dry-run packaging includes prohibited paths: `npm pack --dry-run` flags unexpected entries via package files filter.
