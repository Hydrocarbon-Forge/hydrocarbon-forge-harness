## Objective

Provide the dependency-free foundation every later package builds on: Appendix A contracts as zod schemas with inferred types plus generated JSON Schema files; pure `util` helpers (ids, safe paths, glob matching, byte caps/tails, redaction, time); `config` loading/merging (JSONC, precedence, env plus flag overlay, permission-rule parser); and the definitions loader (agents with commands/skills discovery stubs). No engine, store, git, verify, backend, role, CLI, or TUI logic.

## Interface

Contract schemas: `src/contracts/**` MUST export one zod schema per Appendix A declaration, with inferred types re-exported under the exact same names. No renamed or added contract types. Authoritative declarations live in Appendix A; this package covers all of them, grouped here as names plus kinds only (see Behavior for acceptance rules):

- Identifiers and enums: RunId, TaskId, SessionId, BackendName, Effort, RoleName, TaskClass, PermissionMode, PauseReason, FailureClass (all string literal or alias types).
- Planner artifacts: Command, Budget, Manifest, TaskSpecFrontmatter (object shapes; TaskSpec body headings fixed by the plan).
- Results: VerifyResult, UsageRecord, WorkerReport, FailurePacket, Diagnostic (object shapes with capped and truncated flags where the plan marks them).
- Backend layer: BackendEvent, Capabilities, SpawnRequest, SessionResult, SessionHandle, EnvReport, HarnessAdapter (event union plus object shapes; kill reasons budget, timeout, cancel).
- Settings: Settings, Route, PricingTable (nested config shapes; PricingTable holds asOf, sources, models).
- Engine API: RunOptions, RunSummary, Engine, EngineEvent (call shapes plus versioned event envelope).
- Strategy seam and governor: ExecutionStrategy, GovernorTool, RoutingDecision (reserved direct versus dispatcher plus the fixed typed tool set).

- `src/util/**`: pure helpers only, grouped by capability: ids (RunId plus TaskId shapes); safe paths (repo-contained checks); glob matching; byte caps and tail truncation; secret redaction; time (ISO timestamps). No invented contract names.
- `src/config/**`: settings loader and merger with JSONC tolerance; precedence chain; env plus flag overlay; permission-rule parser (Claude syntax, deny over ask over allow); definitions loader for agents plus discovery stubs for commands and skills.
- `scripts/export-schemas.mjs`: regenerates one JSON Schema per contract into `contracts/*.schema.json`; used by `npm run export-schemas`.
- `contracts/*.schema.json`: generated output, committed.
- Tests under `test/unit/contracts/**`, `test/unit/util/**`, `test/unit/config/**` are written first by the test-writer and are protected for the implementer.

## Behavior

- Contracts:
  - IF input validates against Appendix A shape THEN accept and infer the exact declared type; ELSE reject with a zod issue (no silent coercion, no extra keys unless the declaration allows them).
  - IF `scripts/export-schemas.mjs` runs THEN every Appendix A declaration gets a current `contracts/*.schema.json`; ELSE the build does not claim schemas are current.
  - IF a schema name or field differs from Appendix A THEN fail (planner declaration wins; do not rename).
- Util:
  - ids: IF asked for a RunId THEN return `"r_"` plus 12 base32 chars; IF asked for a TaskId THEN enforce the declared pattern (else reject).
  - safe paths: IF path is absolute OR contains `..` OR escapes the repo root (including symlink escape where checkable) THEN reject; ELSE accept.
  - glob match: IF pattern matches per the project's glob semantics THEN report match; ELSE report non-match (matching is pure, no filesystem writes).
  - byte caps/tails: IF output exceeds the cap THEN keep the tail (heal-prompt tails at most 8 KB per plan §9), set `truncated: true`; ELSE keep whole output with `truncated: false`.
  - redaction: IF text matches a secret pattern or denylisted env value THEN replace with a placeholder; ELSE pass through; never log the secret itself.
  - time: IF a timestamp is produced THEN emit ISO-8601 UTC (`EngineEvent.ts`, `UsageRecord.at`).
- Config:
  - loading: IF a settings file has comments or trailing commas THEN still parse as JSONC; ELSE parse as strict JSON.
  - precedence (low to high): user `~/.config/substrate/` THEN project `.substrate/` THEN `.substrate/settings.local.json` THEN `--settings` THEN flags; IF same key set twice THEN higher wins (objects merge, scalars and arrays replace — see Open questions).
  - overlay: IF env or flag provides a value THEN validate it against `Settings` and overlay; ELSE leave file value.
  - permission rules: full Claude `Tool(spec)` matcher covering at least the plan §4.4 forms (`Bash(git *)`, `Edit(src/**)`, `mcp__s__t`): IF a tool matches deny THEN deny; ELSE IF matches ask THEN ask (workers treat ask as deny downstream); ELSE IF matches allow THEN allow; ELSE default-deny for worker-dangerous tools.
- Definitions loader:
  - agents: IF frontmatter has `name`, `description`, `role` THEN load with optional `backend`, `model`, `effort`, `tools`, `disallowedTools`, `permissionMode`, `maxTurns`, `budget`; ELSE reject the file. Precedence: project `.substrate/agents/` over user `~/.config/substrate/agents/` over built-in `assets/agents/`.
  - commands/skills: IF discovery stub runs THEN return plain structural summaries only (not Appendix A schemas, which define none for these): command `description`/`argument-hint`/`model?`; skill `name`/`description`; ELSE do not read bodies (progressive disclosure). Never read foreign `.claude/` or `.opencode/` dirs implicitly.

## Invariants

- `contracts` and `util` import nothing internal except each other; `config` loader imports only `contracts` and `util` (boundary script enforces).
- Contracts are code: every Appendix A name exists once as a zod schema with its inferred type; JSON Schemas are generated, never hand-edited.
- No model calls, no filesystem writes outside the caller's explicit paths, no git operations, no credential reading/copying/logging in this package.
- Tests under `test/unit/**` for this package are protected once written: the implementer must not edit them to pass.

## Edge cases

- Empty or missing settings file THEN use defaults; malformed JSONC THEN error naming file and position, not a silent default.
- Unknown settings keys THEN error (do not silently ignore typos).
- `routing.escalation` chain present alongside `Record<TaskClass, Route>` map THEN preserve it through load/merge without validating it as a task class.
- Empty `pricing.models` before P0.5 lands THEN accept as valid (Appendix A declares `models` as an open record, so an empty record holds the shape); still require `asOf`, `sources`, `models`; do not invent prices.
- Glob matching dotfiles, empty patterns, and `**` across separators THEN follow documented glob semantics deterministically.
- Redaction overlapping patterns and binary/non-UTF8 input THEN still bounded and non-crashing; redaction never throws on untrusted bytes.
- Byte cap of zero or negative THEN treat as reject configuration, not as "keep everything".
- Agent file with missing `role` or unknown `role` value THEN reject that file only; other definitions still load.
- Duplicate agent/command/skill names across precedence layers THEN higher-precedence layer wins; duplicates within one layer THEN error.

## Guardrails

- Read-only outside `create` set; never touch `src/engine/**`, `src/store/**`, `src/git/**`, `src/verify/**`, `src/backends/**`, `src/roles/**`, `src/cli/**`, `src/tui/**`, credentials, or foreign definition dirs.
- Do not add npm dependencies without a decision-log entry; prefer the pinned stack (`zod`, `yaml`, `picomatch` per plan).
- Do not write implementation bodies for other packages' contracts (e.g. no reducer, no adapter, no spawn logic); no `git commit/push/checkout/reset/rebase/clean/stash`.
- Keep every helper pure and bounded: cap bytes, cap tails, cap log output; scrub env before logging.
- Regenerate (do not hand-edit) `contracts/*.schema.json` via `scripts/export-schemas.mjs`.
- Tests-first: tests fail at base, then implementation makes them pass; implementer does not modify protected tests.
