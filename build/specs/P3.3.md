## Objective

Implement the Substrate backend adapter for OpenCode (pinned version 2.0.21). This package provides: an NDJSON stream normalizer that parses OpenCode JSON events into canonical Substrate `BackendEvent` objects and handles missing `step_finish` events gracefully; per-run configuration generation supporting v2 agent permissions and dynamic local llama.cpp custom provider configuration (no API key, 65536k context limit); the `OpenCodeAdapter` class implementing the authoritative `HarnessAdapter` interface; a deterministic OpenCode fake dialect generator for the fake harness; and full unit and integration test coverage verifying golden fixtures and adapter conformance.

## Behavior

- OpenCode Normalizer (`src/backends/normalize/opencode.ts`):
  - Session Start & Identifier Capture:
    - IF `options.fallbackSessionId` is provided THEN record it as active session identifier.
    - IF incoming raw event has `sessionID` property THEN record `raw.sessionID` as active session identifier.
    - IF no `session.started` event has yet been emitted THEN yield `{ type: "session.started", session_id: activeSessionId }`.
  - Event Transformation:
    - IF `raw.type === "step_start"` THEN:
      - IF session has not started THEN yield `session.started`; ELSE ignore step boundary.
    - IF `raw.type === "text"` THEN:
      - IF `raw.part.text` is a string THEN:
        - IF `raw.part.text` contains model refusal text indicating denied tools (e.g. matching "no shell/bash tool is available" or configured denied tools) THEN yield `{ type: "permission.denied", tool: detectedTool, reason: raw.part.text }`.
        - Yield `{ type: "assistant.text", text: raw.part.text }`.
    - IF `raw.type === "tool_use"` THEN:
      - IF `raw.part.type === "tool"` THEN:
        - Yield `{ type: "tool.call", id: raw.part.id, name: raw.part.tool, input_summary: JSON.stringify(raw.part.state?.input ?? {}) }`.
        - IF `raw.part.state?.status === "completed"` THEN:
          - Yield `{ type: "tool.result", id: raw.part.id, ok: raw.part.state.metadata?.exit === 0 || raw.part.state.status === "completed", output_summary: String(raw.part.state.output ?? "") }`.
    - IF `raw.type === "step_finish"` THEN:
      - IF `raw.part.tokens` exists THEN:
        - Construct `UsageRecord` with `backend: "opencode"`, `model: options.model`, `input_tokens: raw.part.tokens.input ?? 0`, `output_tokens: raw.part.tokens.output ?? 0`, `reasoning_tokens: raw.part.tokens.reasoning`, `cache_read_tokens: raw.part.tokens.cache?.read`, `cache_write_tokens: raw.part.tokens.cache?.write`, `cost_usd: raw.part.cost ?? 0`, `cost_source: "reported"`, `at: ISO timestamp`.
        - Update cumulative usage totals and yield `{ type: "usage", record: usageRecord, cumulative: false }`.
    - IF `raw.type === "error"` THEN:
      - IF `raw.error.type === "provider.auth"` OR `raw.error.message` indicates 403 / unauthorized THEN yield `{ type: "error", kind: "auth", message: raw.error.message }`.
      - ELSE IF `raw.error.type` contains "rate-limit" OR `raw.error.message` indicates rate limit THEN yield `{ type: "error", kind: "rate_limit", message: raw.error.message }`.
      - ELSE IF `raw.error.type === "provider.no-route"` THEN yield `{ type: "error", kind: "crash", message: raw.error.message }`.
      - ELSE yield `{ type: "error", kind: "protocol", message: raw.error.message ?? "Unknown error" }`.
  - Stream Termination & Missing `step_finish` Recovery:
    - IF raw stream ends:
      - IF no `step_finish` was emitted during the session THEN:
        - Construct fallback `UsageRecord` with 0 tokens and cost (or compute from `options.pricingTable` if token counts are recoverable).
        - Record warning regarding missing `step_finish` on stdout.
      - Yield `{ type: "session.result", ok: !hasFatalError, final_text: accumulatedAssistantText, usage: finalUsageRecord, exit_code: processExitCode }`.

- Per-Run Config Generator (`src/backends/adapters/opencode.ts`):
  - Agent & Tool Restrictions:
    - IF `req.permission.deny` is non-empty THEN:
      - Map denied tools to OpenCode action names (`Bash` → `"shell"`, `Edit` → `"edit"`, `WebFetch` → `"webfetch"`, `WebSearch` → `"websearch"`).
      - Build v2 permissions list starting with `{ action: "*", resource: "*", effect: "allow" }` followed by `{ action: <deniedAction>, resource: "*", effect: "deny" }` entries.
    - ELSE build permissions list with default allow.
    - Generate unique agent name and write `.opencode/agents/<agentName>.md` with YAML frontmatter containing `mode: "primary"`, `steps: 100`, `permissions: <list>`, and prompt body.
  - Local llama.cpp Provider Configuration:
    - IF target model or options configure a local endpoint THEN:
      - Construct custom provider entry under `provider.<id>` with `npm: "@ai-sdk/openai-compatible"`.
      - Set `options.baseURL` to configured endpoint (retrieved dynamically from settings/options, never committed).
      - Set no API key (omitted or empty string).
      - Set context window limit to 65536k (`limit: { context: 65536 }`).
    - Write generated configuration to temporary configuration directory.
  - Cleanup:
    - Return `GeneratedOpenCodeConfig` providing `cleanup()` callback that safely unlinks generated agent files and directories.

- OpenCode Adapter (`src/backends/adapters/opencode.ts`):
  - Capabilities Declaration:
    - Expose `name: "opencode"`, `version_pin: "2.0.21"`, `effort: true`, `structured_output: false`, `budget_flag: false`, `cost_reported: true`, `resume: true`, `permission_denial_signal: "none"`, `sandbox_flag: false`, `native_subagents_headless: false`, `max_concurrency: 2`.
  - Environment Validation:
    - IF `validateEnvironment()` is invoked THEN execute `opencode --version` via supervisor.
    - IF process exits non-zero OR binary not found THEN return `EnvReport` with `ok: false`, `pin_matches: false`, and problem description.
    - IF stdout contains `"2.0.21"` THEN return `EnvReport` with `ok: true`, `pin_matches: true`, `problems: []`.
    - ELSE return `EnvReport` with `ok: true`, `pin_matches: false`, and version drift warning in `problems`.
  - Invocation & Process Supervision:
    - IF `spawn(req)` is invoked THEN:
      - Call `generateOpenCodeRunConfig(req, options)` to produce temporary agent/provider configuration.
      - Build CLI arguments:
        - Always add `["run", "--standalone", "--format", "json"]`.
        - IF `req.effort` is provided THEN map effort to `#variant` suffix and append to model (e.g. `opencode/model#high`); ELSE pass `req.model`.
        - Add `["--agent", config.agentName]`.
        - IF `req.session?.resume` is present THEN add `["-s", req.session.resume]`.
        - ELSE IF `req.session?.id` is present THEN add `["-s", req.session.id]`.
        - IF `req.session?.fork` is true THEN add `["--fork"]`.
        - Add prompt string as final positional argument.
      - Invoke `spawnSupervisedProcess` with `command: "opencode"`, `args`, `cwd: req.cwd`, `env: req.env`, and `timeoutMs: req.budget.timeout_ms`.
      - Pipe stdout through `readNdjsonStream` and forward raw bytes to `raw/<session_id>.ndjson` sink.
      - Pipe parsed stream through `normalizeOpenCodeStream`.
      - Return `SessionHandle` with `pid`, `events` async iterable, `result()` promise resolving `SessionResult`, and `kill(reason)` terminating process group and executing `config.cleanup()`.

- OpenCode Fake Dialect (`test/fixtures/fake-harness/dialects/opencode.mjs`):
  - IF scenario is `"success"` THEN yield `step_start`, `text` with `"OK"`, and `step_finish` with tokens and cost 0.
  - IF scenario is `"edit_files"` THEN yield `step_start`, `tool_use` with `tool: "edit"` and completed state, and `step_finish`.
  - IF scenario is `"verify_fail_then_fix"`:
    - IF initial run (no `-s` resume) THEN yield `tool_use` writing broken code, exit 1.
    - ELSE IF resumed (`-s` present) THEN yield `tool_use` writing fix, `step_finish`, exit 0.
  - IF scenario is `"hang"` THEN sleep indefinitely without writing final events.
  - IF scenario is `"crash"` THEN exit abruptly with code 1.
  - IF scenario is `"soft_deny"` THEN yield `step_start`, `text` with refusal ("I can't run shell commands — no shell/bash tool is available in this session."), exit 0.
  - IF scenario is `"budget_overshoot"` THEN yield `step_start`, `step_finish` exceeding budget, exit 1.
  - IF scenario is `"rate_limit"` THEN yield `error` with `type: "provider.rate-limit"`, exit 1.
  - IF scenario is `"resume"` THEN echo resumed session ID and completed state, exit 0.

## Invariants

- Isolated standalone execution: all OpenCode CLI invocations pass `--standalone` to eliminate interference from background server daemons.
- Structured result authority: adapter outcome is never determined by exit code alone; validation requires structured `BackendEvent` stream and `SessionResult`.
- Process group supervision: all processes spawn with `detached: true` in their own process group and terminate via `-pgid`.
- Config confidentiality: local endpoint URLs, ports, and credentials are never hard-coded into repository files; they are injected dynamically through adapter options.
- Llama.cpp provider specification: local provider is configured with `@ai-sdk/openai-compatible`, no API key, and 65536k context limit.
- Missing `step_finish` safety: stream normalizer never hangs, crashes, or produces invalid results when a text-only turn omits `step_finish`.
- Non-destructive configuration lifecycle: per-run generated agent and provider files are cleaned up upon session completion.
- Boundary compliance: modules in `src/backends/**` only import from `src/contracts/**`, `src/util/**`, and Node standard libraries.

## Edge cases

- Text-only response missing `step_finish`: normalizer detects stream EOF, synthesizes fallback `UsageRecord`, and yields valid `session.result`.
- Tool denial without explicit denial event: normalizer detects model refusal phrases in `text` events and generates `permission.denied` events.
- Model variant formatting: `#variant` suffix is only appended when `req.effort` is specified and `req.model` does not already contain a variant.
- Premature process crash: if OpenCode exits before emitting `session.started`, adapter synthesizes `session.started` and `error` event with `kind: "crash"`.
- Bad model or route error: `provider.no-route` error events map to `crash` error kind and result in `ok: false`.
- Transient rate limiting or auth failure: provider 403 or rate limit errors map to typed `auth` or `rate_limit` error events.
- Empty or whitespace NDJSON chunks: skipped silently without disrupting event order.
- Concurrent sessions in single repository: per-run configs use uniquely generated agent names and isolated directories to prevent file collision.
- Process termination during active stream: `kill()` escalates from SIGTERM to SIGKILL, cleans up generated files, and sets `killed_for` on the result.
