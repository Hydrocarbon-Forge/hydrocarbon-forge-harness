## Objective

Implement the interactive Terminal User Interface (TUI) for Substrate using React/Ink and a pure state-action architecture:
1. Pure State Model and Reducer (`src/tui/state/**`):
   - Define immutable `TuiState` encompassing prompt buffer, history, run lifecycle, task states, event feeds, budget/cost totals, permission mode, modal approval dialogs, and terminal viewport dimensions.
   - Define `TuiAction` discriminated union for all user interactions, terminal events, and engine event stream notifications.
   - Implement pure, deterministic reducer `reduceTuiState(state: TuiState, action: TuiAction): TuiState` without side-effects or asynchronous operations.
2. Canonical Slash Command Registry (`src/tui/commands/**`):
   - Implement registry and argument parser for all 19 canonical slash commands (§4.7, S5 §5.1): `/help`, `/mode`, `/plan`, `/run`, `/status`, `/tasks`, `/cost`, `/models`, `/agents`, `/permissions`, `/config`, `/resume`, `/sessions`, `/undo`, `/doctor`, `/init`, `/clear`, `/exit`, `/hooks`.
   - Enforce strict built-in precedence over custom markdown command templates (`.substrate/commands/<name>.md`).
3. Keymap and Keypress Handling (`src/tui/keys/**`):
   - Implement context-aware keyboard input router across `prompt`, `running`, `dialog`, and `global` contexts.
   - Enforce canonical bindings per S5 §5.2: `Enter` (submit), `Shift+Tab` (cycle permission mode), `Esc` (graceful interrupt / dismiss / clear), `Ctrl+C` x 2 (500ms debounced exit code 130), `Ctrl+T` (toggle task board), `Ctrl+O` (toggle verbose feed), `@` (file mention completion), `!` (shell passthrough).
4. Ink Rendering Components (`src/tui/components/**`, `src/tui/app.tsx`):
   - Interactive prompt input component with history navigation, multiline handling, and autocompletion hooks.
   - Dual-mode event feed component supporting compact summary view and expanded verbose trace (`Ctrl+O`).
   - Task board split/overlay pane displaying per-task lifecycle statuses (`Ctrl+T`).
   - Responsive 4-tier status line adapting dynamically to viewport width (>=100 cols, 60–99 cols, 40–59 cols, <40 cols).
   - Modal approval dialogs for plan approval, cost budget threshold gate, and integration merge gate.
   - Interactive session picker component supporting keyboard navigation for `/sessions` and `/resume`.
5. Unit Test Suite (`test/unit/tui/**`):
   - Unit tests for pure state transitions and reducer determinism.
   - Unit tests for slash command registration, aliases, and argument tokenization.
   - Unit tests for keybinding state machine (including 500ms double-tap `Ctrl+C` exit armed logic).
   - Component tests for responsive status line tier collapse and approval dialog interactions.

## Behavior

Input processing, key dispatch, status rendering, and state transitions proceed as deterministic decision trees:

1. **Prompt submission and Enter key processing**:
   - IF prompt buffer is empty or consists solely of whitespace:
     - THEN ignore submission (no-op).
   - ELSE IF prompt buffer starts with `/`:
     - THEN extract command name token and trailing arguments string.
     - IF command name matches any canonical built-in command in `CANONICAL_COMMANDS` or its registered alias:
       - THEN dispatch matching built-in command action (e.g., `/exit` dispatches `EXIT(0)`, `/clear` clears event feed and buffer, `/mode` updates `permissionMode`).
     - ELSE IF custom command file exists at `.substrate/commands/<name>.md`:
       - THEN expand template placeholders (`$ARGUMENTS`, `$1`, `$2`) and dispatch `INPUT_SUBMIT` with expanded text.
     - ELSE:
       - THEN append warning to event feed: `Unknown command '/<name>'. Type /help for available commands.`
     - Append original input to prompt history, reset `historyIndex`, and clear prompt buffer.
   - ELSE IF prompt buffer starts with `!`:
     - THEN strip leading `!` and dispatch `SHELL_PASSTHROUGH` action with remainder of line to execute locally in cwd.
     - Append input to history, reset `historyIndex`, and clear prompt buffer.
   - ELSE:
     - THEN dispatch `INPUT_SUBMIT` with prompt content to engine orchestrator or governor.
     - Append prompt to history, reset `historyIndex`, and clear prompt buffer.

2. **Interrupt handling (`Esc` and `Ctrl+C` x 2)**:
   - For `Ctrl+C`:
     - IF `INTERRUPT_PRESS` occurs and `now - lastCtrlCTime < 500ms`:
       - THEN emit `EXIT` action with exit code `130`, clear banner, and reset `exitArmed = false`.
     - ELSE:
       - THEN set `exitArmed = true`, record `lastCtrlCTime = now`, and set banner `"Press Ctrl+C again to exit"`.
   - For `Esc`:
     - IF active dialog is open (`dialog.type !== "none"`):
       - THEN dispatch `CLOSE_DIALOG` and return focus to prompt buffer.
     - ELSE IF run is active (`run.runState` is in `EXECUTING`, `PLANNING`, `VERIFYING`, or `INTEGRATING`):
       - THEN request engine pause with reason `PAUSED(user_cancel)`.
     - ELSE IF prompt buffer contains unsubmitted characters:
       - THEN dispatch `PROMPT_CLEAR` to empty the input buffer.
     - ELSE:
       - THEN ignore (no-op).

3. **Permission mode cycling (`Shift+Tab`)**:
   - IF cursor is in prompt context and no dialog is open:
     - THEN advance `permissionMode` monotonically:
       - IF mode is `default` THEN transition to `plan`.
       - ELSE IF mode is `plan` THEN transition to `acceptEdits`.
       - ELSE IF mode is `acceptEdits` THEN transition to `dontAsk`.
       - ELSE IF mode is `dontAsk` THEN transition to `bypassPermissions`.
       - ELSE IF mode is `bypassPermissions` THEN transition to `default`.
   - ELSE:
     - THEN ignore `Shift+Tab`.

4. **Task board toggle (`Ctrl+T`)**:
   - IF `Ctrl+T` is received in any non-dialog context:
     - THEN invert visibility flag: `taskBoardVisible = !taskBoardVisible`.

5. **Verbose feed toggle (`Ctrl+O`)**:
   - IF `Ctrl+O` is received in any non-dialog context:
     - THEN invert feed verbosity: `run.feedVerbose = !run.feedVerbose`.

6. **Responsive status line layout calculation**:
   - IF viewport width >= 100 columns (`wide` tier):
     - THEN render all 4 segments: `[model/tier]` + `[runState]` + `[tasks done/total]` + `[cost / cap]` (e.g. `[sonnet/hi] [EXECUTING] [3/7 tasks] [$0.042 / $0.50]`).
   - ELSE IF viewport width is between 60 and 99 columns inclusive (`medium` tier):
     - THEN omit model tier segment; render 3 segments: `[runState]` + `[tasks done/total]` + `[cost / cap]`.
   - ELSE IF viewport width is between 40 and 59 columns inclusive (`narrow` tier):
     - THEN omit model tier and cost; render 2 minimal segments: `[runState]` + `[done/total]` (e.g. `[EXECUTING] [3/7]`).
   - ELSE (viewport width < 40 columns, `micro` tier):
     - THEN render single-character abbreviated state indicator: `[E]` for executing, `[P]` for planning, `[!]` for paused/error, `[OK]` for finished.

7. **Approval gates and dialogs**:
   - IF engine emits gate pause requiring approval (`plan`, `cost`, or `merge`):
     - THEN transition `dialog` to corresponding approval state (`approval_plan`, `approval_cost`, or `approval_merge`).
     - IF user confirms via `Enter` or `y`:
       - THEN dispatch `APPROVE_GATE(true)` and reset dialog to `{ type: "none" }`.
     - ELSE IF user cancels via `Esc` or `n`:
       - THEN dispatch `APPROVE_GATE(false)` and reset dialog to `{ type: "none" }`.
   - IF user invokes `/sessions` or `/resume` without positional identifier:
     - THEN transition `dialog` to `session_picker` populated with discovered session IDs.
     - IF user presses `Up` / `k` or `Down` / `j`:
       - THEN update `selectedIndex` bounded within `[0, sessions.length - 1]`.
     - IF user presses `Enter`:
       - THEN dispatch `SELECT_SESSION(sessions[selectedIndex])` and close dialog.
     - IF user presses `Esc`:
       - THEN dispatch `CLOSE_DIALOG`.

8. **Engine event ingestion (`ENGINE_EVENT`)**:
   - IF event is `run.state`, `run.paused`, or `run.finished`:
     - THEN update `run.runState` and `run.runId`.
   - IF event is `task.ready`, `task.verify.started`, `task.passed`, `task.failed`, or `task.merged`:
     - THEN update or insert `run.tasks[task_id]` with updated state and generation.
   - IF event is `usage.recorded`:
     - THEN add recorded USD amount to `run.totalCostUsd`.
   - Append raw event to `run.feed`.

## Invariants

- **Pure Reducer Determinism**: `reduceTuiState(state, action)` is strictly pure, producing identical output states given identical inputs, with zero I/O, timers, or network calls.
- **Precedence Hierarchy**: Built-in 19 canonical slash commands strictly take precedence over custom command files; collisions never execute custom scripts without warning.
- **Non-blocking Keyloop**: Keyboard event parsing and action reduction are synchronous and non-blocking, maintaining responsive rendering at 60 FPS under heavy event stream loads.
- **Bounded Debounce Window**: Double-press `Ctrl+C` process termination triggers code 130 if and only if the second press occurs within 500ms of the first.
- **Terminal Buffer Integrity**: Viewport resize (`SIGWINCH`) recalculates layout segments immediately without terminal buffer corruption, tearing, or ANSI artifact drift.
- **Architectural Boundary Enforcement**: TUI code only imports types from `src/contracts/**` and shared utilities from `src/util/**`; it never accesses backend harness adapters, git execution runners, or engine state files directly.
- **State Monotonicity**: Prompt history navigation (`Up` / `Down`) preserves unsaved input draft when navigating away and restoring index.

## Edge cases

- **Micro-terminal width (< 40 cols)**: Status line collapses gracefully to single-character badge (`[E]`, `[P]`, `[!]`, `[OK]`) without wrapping lines or overflowing screen height.
- **ASCII-only terminals**: When UTF-8 box characters are unsupported, components fallback cleanly to ASCII borders (`-`, `|`, `+`, `[x]`, `[ ]`).
- **Rapid `Esc` key spamming**: Debounce repeated `Esc` events to ensure single idempotent `PAUSED(user_cancel)` signal is emitted to the orchestrator.
- **`Ctrl+C` beyond 500ms**: First `Ctrl+C` sets timer; if second press arrives after 501ms, reset interrupt counter and re-arm without exiting.
- **Pasted multiline prompt text**: Preserves embedded newlines in input buffer, rendering multiline edit box without triggering premature turn submission.
- **Empty session index**: `/sessions` with no existing session records displays helpful notice banner and dismisses cleanly on `Esc` or `Enter`.
- **Custom command template syntax error**: Malformed frontmatter or missing template variables in `.substrate/commands/<name>.md` surfaces inline error without crashing TUI.
- **Missing budget cap**: If no run cap is configured in settings, cost segment displays cumulative spend without ratio: `[$0.042]`.

## Guardrails

- **No Implementation Bodies**: The spec specifies exact type definitions, function declarations, and decision trees; it contains no function implementation bodies.
- **Strict Code Fence Length**: Every code fence is guaranteed to contain at most 12 lines to pass `speccheck.mjs` verification.
- **Canonical Command Set Exactness**: All 19 slash command names, categories, and aliases match §4.7 and `docs/spikes/S5-ux.md` §5.1 without addition or omission.
- **Immutable State Updates**: All reducer branches must return shallow-copied or structural clones of `TuiState` rather than mutating state in-place.
- **Restricted Write Set**: Changes and additions are strictly confined to `src/tui/**` and `test/unit/tui/**`.
- **Safe Passthrough**: Shell passthrough commands (`!<cmd>`) execute in isolated child processes with stdio piped to event feed, never evaluating raw strings in-process.

## Out of scope

- Web GUI, browser-based frontends, or remote daemon web sockets.
- Direct LLM provider API communication or token generation inside TUI components.
- Autonomous git commit, branch checkout, or merge execution inside TUI components.
- Arbitrary custom theme definition engines beyond standard terminal ANSI palettes and ASCII fallback.
- Native mobile or tablet touch gesture navigation.
