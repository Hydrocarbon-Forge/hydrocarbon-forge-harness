## Objective

Implement lifecycle hooks, commands, skills semantics, and foreign agents import:
1. Lifecycle hooks runner and gate integration (`src/hooks/**`):
   - Implement the hooks runner supporting 8 standard events per §4.8: `PreRun`, `PostPlan`, `PreTask`, `PostTask`, `PreMerge`, `PostMerge`, `RunFinished`, `Notification`.
   - Deliver event context as serialized JSON on `stdin` to configured hook commands.
   - Enforce process exit semantics: exit `0` continues; exit `2` explicitly blocks execution with `stderr` feedback; other non-zero exits report hook execution errors.
   - Enforce process group isolation, execution timeout (`timeout_s`), and environment scrubbing.
   - Integrate with run gates: `PreRun` halts initialization; `PostPlan` blocks execution and feeds stderr back to the planner or pauses for human review; `PreMerge` blocks integration merges.
2. Commands semantics (`src/config/commands.ts`):
   - Discover and load Markdown prompt templates with YAML frontmatter (`description`, `argument-hint`, `model`) and template body containing `$ARGUMENTS`.
   - Enforce hierarchical resolution precedence (§4.3): project `.substrate/commands/` > user `~/.config/substrate/commands/` > built-in `assets/commands/`.
   - Expand command templates invoked via `/name <args>` or `substrate run "/name <args>"`, replacing `$ARGUMENTS` placeholders.
3. Skills semantics (`src/config/skills.ts`):
   - Discover `SKILL.md` definitions across project (`.substrate/skills/`), user (`~/.config/substrate/skills/`), and built-in (`assets/skills/`) paths.
   - Implement progressive disclosure (§4.3): provide only `name` and `description` to the Planner prompt; supply full markdown content on demand.
4. Agents import subcommand (`src/cli/agents-import.ts`):
   - Implement explicit foreign definition importer: `substrate agents import --from claude|opencode`.
   - Strictly uphold §4.3 invariant: foreign directories (`.claude/`, `.opencode/`) are never read implicitly during execution.
   - Convert foreign definitions into `.substrate/agents/<name>.md` with validated YAML frontmatter and Markdown system prompt bodies.
5. Verification suite:
   - Integration tests in `test/integration/hooks/**` verifying hooks execution, gate pausing, exit code 2 blocking, and timeouts.
   - Unit tests in `test/unit/config/commands.test.ts` verifying command discovery, precedence shadowing, and `$ARGUMENTS` expansion.

## Behavior

- Hook Execution and Process Supervision (`src/hooks/runner.ts`):
  - IF hook event is triggered (`event` in `PreRun`, `PostPlan`, `PreTask`, `PostTask`, `PreMerge`, `PostMerge`, `RunFinished`, `Notification`) THEN:
    - Look up configured hooks for `event` in `settings.hooks[event]`.
    - IF no hooks are configured for `event` THEN return empty result array immediately.
    - ELSE for each hook configuration `{ command, timeout_s }` in sequential order:
      - Spawn hook process via shell with detached process group.
      - Serialize event payload object to JSON and pipe into child process `stdin`, then close `stdin`.
      - Execute with scrubbed environment to prevent leaking secrets.
      - Monitor execution duration against `timeout_s ?? 30` seconds:
        - IF execution exceeds timeout THEN send `SIGTERM` to process group; after 500ms grace period send `SIGKILL`; record `timed_out: true`, `exit_code: null`, `blocked: false`.
      - Capture `stdout` and `stderr` streams with bounded tail caps (max 64KB).
      - Evaluate process exit code:
        - IF `exit_code === 0` THEN mark `blocked: false`.
        - ELSE IF `exit_code === 2` THEN mark `blocked: true`, capture `stderr` content as blocking feedback.
        - ELSE (exit code non-zero and not 2) THEN mark `blocked: false`, log error message to stderr.
      - IF hook is marked `blocked: true` AND `event` is a blocking gate point (`PreRun`, `PostPlan`, `PreTask`, `PreMerge`) THEN halt remaining hooks for this event and return immediately.
      - ELSE continue executing remaining hooks for this event.

- Gate Integration and Lifecycle Blocking (`src/hooks/gate.ts`):
  - `PreRun` Gate:
    - IF any `PreRun` hook returns `blocked: true` (exit code 2) THEN:
      - Abort run execution before setup or model invocation.
      - Output hook feedback from `stderr` to console.
      - Return exit code `3` (`needs_human`).
  - `PostPlan` Gate:
    - IF any `PostPlan` hook returns `blocked: true` (exit code 2) THEN:
      - Capture hook `stderr` feedback string.
      - IF permission mode is `dontAsk` THEN:
        - Emit diagnostic gate event; pass feedback back to planner for replan/repair retry (up to `planner_format_retries`); IF retries exhausted THEN pause run with reason `needs_approval` and exit `3`.
      - ELSE (interactive or human gated) THEN:
        - Pause run with reason `needs_approval` presenting hook feedback to user.
  - `PreTask` Gate:
    - IF any `PreTask` hook returns `blocked: true` (exit code 2) THEN:
      - Prevent worker spawn for this task generation.
      - Emit `task.blocked` engine event with hook feedback; pause run or mark task blocked.
  - `PreMerge` Gate:
    - IF any `PreMerge` hook returns `blocked: true` (exit code 2) THEN:
      - Halt batch merge into integration branch.
      - Record merge block in run state and emit diagnostic event with stderr feedback.
      - Pause run with reason `needs_approval`.
  - Non-Blocking Hooks (`PostTask`, `PostMerge`, `RunFinished`, `Notification`):
    - Run asynchronously or post-action without halting already committed transitions.
    - IF exit code 2 is returned THEN log diagnostic warning to stderr.

- Commands Semantics and Expansion (`src/config/commands.ts`):
  - Hierarchical Discovery Precedence:
    - Search directories in strict precedence order:
      - 1. Project directory: `<projectDir>/.substrate/commands/`
      - 2. User directory: `~/.config/substrate/commands/`
      - 3. Built-in directory: `<substrateRoot>/assets/commands/`
    - Scan each existing directory for `*.md` files.
    - Command name is derived from file basename excluding `.md`.
    - IF command name was already loaded from higher precedence tier THEN ignore lower tier definition (shadowing).
  - Frontmatter and Body Parsing:
    - Parse YAML frontmatter:
      - `description`: string summary of command function.
      - `argument-hint`: optional parameter hint string (e.g., `[file] [query]`).
      - `model`: optional model override string.
    - Extract template body (all markdown following frontmatter).
  - Template Expansion:
    - IF input prompt begins with `/<cmdName>` THEN:
      - Query command definitions for `<cmdName>`.
      - IF definition is found THEN:
        - Extract trailing argument text following `/<cmdName>` (trimmed).
        - IF template body contains `$ARGUMENTS` THEN replace all occurrences of `$ARGUMENTS` with the argument text (or empty string if no arguments supplied).
        - ELSE IF argument text is non-empty THEN append argument text to prompt body separated by space.
        - Return expanded prompt string and optional `model` override.
      - ELSE pass prompt through unchanged.
    - ELSE pass prompt through unchanged.

- Skills Semantics and Progressive Disclosure (`src/config/skills.ts`):
  - Hierarchical Discovery Precedence:
    - Search directories in strict precedence order:
      - 1. Project directory: `<projectDir>/.substrate/skills/`
      - 2. User directory: `~/.config/substrate/skills/`
      - 3. Built-in directory: `<substrateRoot>/assets/skills/`
    - Discover skills structured either as `<name>/SKILL.md` or `<name>.md`.
    - De-duplicate by skill name; project shadows user, user shadows built-in.
  - Frontmatter Parsing:
    - Parse YAML frontmatter:
      - `name`: string name (defaults to parent directory name if omitted in frontmatter).
      - `description`: string describing capability.
  - Progressive Disclosure:
    - When generating system prompt for Planner:
      - Output ONLY a concise catalog containing `name`, `description`, and `path`.
      - DO NOT include skill body contents in planner system prompt.
      - Format:
        ```markdown
        - <name>: <description> (path: <path>)
        ```
    - When Planner or Worker issues a read command for `<path>`:
      - Return full markdown body of `SKILL.md` on demand.

- Agents Import Subcommand (`src/cli/agents-import.ts`):
  - Execution Invocation:
    - Invoked as `substrate agents import --from <claude|opencode> [options]`.
    - Strict isolation: Foreign directories (`.claude/`, `.opencode/`) are NEVER scanned implicitly.
  - Source Parsing:
    - IF `--from claude` THEN:
      - Read definitions from `<sourceDir ?? ".claude/agents">/*.md`.
      - IF source directory does not exist THEN emit error to stderr, exit `2`.
      - For each markdown file:
        - Parse frontmatter: extract `name`, `description`, `tools`, `disallowedTools`, `model`, `permissionMode`.
        - Map `role`: IF specified and valid in `RoleName` THEN keep; ELSE default to `"worker"`.
        - System prompt body is preserved verbatim.
    - ELSE IF `--from opencode` THEN:
      - Read definitions from `<sourceDir ?? ".opencode/agents">` (`*.json` or `*.md`).
      - IF source directory does not exist THEN emit error to stderr, exit `2`.
      - Map OpenCode agent configuration into Substrate frontmatter (`name`, `description`, `model`, `role: "worker"`) and system prompt.
  - Destination Materialization:
    - Write converted definitions to `<targetDir ?? ".substrate/agents">/<name>.md`.
    - Ensure target directory exists (`mkdir -p`).
    - IF destination file exists AND `--overwrite` is not passed THEN skip file and record in skipped list.
    - ELSE IF `--dry-run` is passed THEN record conversion in report without writing to disk.
    - ELSE write formatted YAML frontmatter and markdown body to target file.
  - Validate Output:
    - Validate every imported agent definition against `AgentDefinition` schema.
    - Print summary table (imported, skipped, errors) to stdout; exit `0` on success, `1` on conversion errors, `2` on usage errors.

## Invariants

- Exit code 2 protocol: Process exit code `2` from any command hook indicates an explicit block with feedback on `stderr`; exit code `0` indicates continue; all other exit codes indicate command execution errors.
- Progressive disclosure: The Planner prompt receives exclusively skill `name` and `description` summaries; skill bodies are never preloaded into prompt tokens.
- Foreign directory isolation (§4.3): Foreign directories (`.claude/`, `.opencode/`) are never accessed or imported implicitly; conversion occurs only via explicit `substrate agents import`.
- Discovery precedence: Definitions in project directory (`.substrate/`) strictly override definitions in user directory (`~/.config/substrate/`), which override built-in defaults (`assets/`).
- Code fence line count: Every code fence within this specification document is strictly <= 12 lines in length.
- Architectural boundary integrity (§15): `hooks` and `config` modules may import `contracts` and `util`; `engine` must never import `hooks` or `cli`; `cli` may import `hooks` and `config`.
- Process group isolation: All hook child processes are spawned in detached process groups and killed on timeout via SIGTERM followed by SIGKILL.
- Pure template substitution: `$ARGUMENTS` in command templates is replaced without altering surrounding prompt syntax or leaving trailing unmatched tokens.

## Edge cases

- Hook process times out: Send `SIGTERM` to process group, wait 500ms grace period, send `SIGKILL`; record `timed_out: true`; evaluate gate as blocked or warning based on configuration.
- Hook process exits 2 with empty stderr: Generate synthetic feedback string: `"Hook command exited with code 2 but emitted no stderr"`.
- Hook command emits unbounded output: Buffer stdout and stderr with strict 64KB tail caps to avoid memory exhaustion.
- Non-existent hook command binary: Spawn failure captures error message; hook result marks `exit_code: 127`; report diagnostic error without crashing parent engine.
- Command template invoked without arguments: Replace `$ARGUMENTS` with empty string; trim excess consecutive whitespace.
- Command template without `$ARGUMENTS` token: Append user-provided arguments to template body separated by a space.
- Unknown hook event in settings: Log diagnostic warning and ignore entry without failing engine startup.
- Duplicate agent or skill names across tiers: Project-level definition silently shadows user-level and built-in definitions.
- Malformed YAML frontmatter in command or skill: Record parse error in loader diagnostic list, skip invalid file, and continue loading remaining valid definitions.
- Missing `SKILL.md` inside skill directory: Skip directory with diagnostic warning; continue scanning sibling directories.
- `agents import` destination already exists: If `--overwrite` is false, skip file with warning and record in skipped report; do not overwrite existing files without explicit flag.

## Guardrails

- Never write implementation bodies in task specs or contract stubs; declare signatures matching contracts.
- Never execute git commit, push, checkout, reset, rebase, clean, or stash.
- Never leak API keys, auth tokens, or passwords to hook child process stdin, stdout, stderr, or log files.
- Strictly adhere to §15 architectural boundaries: `engine` must never import `hooks` or `cli`.
- Keep every code block <= 12 lines to satisfy speccheck validation.

## Out of scope

- Interactive TUI slash commands dispatching (`src/tui/**`): Implemented in Phase 5, P5.3.
- Automatic background polling of foreign agent directories: Forbidden by §4.3.
- Webhook or remote network hooks execution: Only local shell commands are supported.
- Modifying engine internal reducer state directly from hooks: State mutations occur strictly through engine events.
