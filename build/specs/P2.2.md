## Objective

Implement the spec parser, ecosystem detection, contract stub typechecking, repository structural map generator, and deterministic plan linter (rules L001–L027) with extension hook points for semantic checks (S001–S004). This package validates planner artifacts (`manifest.yaml`, task specs, and contract stubs) before execution begins, enforcing schema conformance, dependency DAG validity, file scope isolation, budget boundaries, and type completeness.

## Behavior

- Spec and Manifest Parsing:
  - IF `manifest.yaml` content parses as valid YAML AND satisfies the `Manifest` schema THEN return `Manifest`; ELSE report an `L001` diagnostic containing parser or validation errors.
  - IF a task spec document begins with `---` frontmatter delimiter and ends with matching `---` delimiter THEN extract and parse YAML frontmatter against `TaskSpecFrontmatter`; ELSE report an `L001` diagnostic for malformed frontmatter.
  - IF frontmatter validates cleanly THEN parse remaining markdown body into section map keyed by markdown heading 2 (`## `); ELSE abort body parsing for that spec.
  - IF all required headings (`Objective`, `Interface`, `Behavior`, `Invariants`, `Edge cases`, `Guardrails`, `Out of scope`) are present with non-empty content THEN store sections in `ParsedTaskSpec.sections`; ELSE record an `L014` diagnostic for each missing or empty heading.
  - IF code fences (```) are encountered in markdown body THEN record their language, starting line, line count, and raw text in `ParsedTaskSpec.codeBlocks`; ELSE record empty code blocks.
  - IF `Interface` or `Behavior` sections contain placeholder tokens (`TODO`, `FIXME`, `TBD`, `...`, `<placeholder>`) outside code fences THEN record an `L013` error diagnostic; ELSE pass placeholder validation.

- Ecosystem Detection:
  - IF `package.json` or `tsconfig.json` exists in `repoRoot` THEN detect `"node-ts"`.
  - ELSE IF `pyproject.toml`, `setup.py`, `requirements.txt`, or `Pipfile` exists in `repoRoot` THEN detect `"python"`.
  - ELSE IF `Cargo.toml` exists in `repoRoot` THEN detect `"rust"`.
  - ELSE IF `go.mod` exists in `repoRoot` THEN detect `"go"`.
  - ELSE detect `"other"`.
  - IF `manifest.ecosystem` is omitted THEN allow runtime to default or suggest commands based on `detectEcosystem(repoRoot)`; ELSE respect explicit manifest setting.

- Contract Stub Typecheck:
  - IF `manifest.contracts.files` lists paths THEN verify each path exists within the repository or staged run directory; ELSE IF any path is missing THEN record an `L019` diagnostic.
  - IF `manifest.contracts.typecheck` contains commands THEN execute each command sequentially in `repoRoot` with specified timeouts and scrubbed environment; IF any command exits non-zero or times out THEN emit an `L018` diagnostic with exit code and tail-capped stderr/stdout; ELSE mark contract typecheck passed.
  - IF any task spec `Interface` references a contract path not declared in `manifest.contracts.files` or not found on disk THEN record an `L019` diagnostic.

- Repo Map Generation:
  - IF `generateRepoMap` is called THEN traverse `repoRoot` file tree, respecting `.gitignore`, excluding `.git/`, `.substrate/`, `node_modules/`, and binary files.
  - IF `maxDepth` is set AND current directory depth exceeds `maxDepth` THEN skip child directories; ELSE traverse directories up to `maxFiles` limit.
  - IF total accumulated characters exceed `maxBytes` (default 32 KB) THEN cap output string, append truncation notice, and return with `truncated: true`; ELSE return full map with `truncated: false`.

- Plan Linter Rules (L001–L027):
  - L001 (error): IF manifest or any spec frontmatter fails zod schema validation THEN emit `L001` diagnostic.
  - L002 (error): IF task ID fails regex `/^[A-Z][A-Za-z0-9_-]{0,31}$/` OR duplicate task IDs exist across manifest THEN emit `L002` diagnostic.
  - L003 (error): IF a spec file declared in `manifest.tasks` is missing on disk OR an orphan spec file exists in tasks directory not referenced by manifest THEN emit `L003` diagnostic.
  - L004 (error): IF any task's `depends_on` lists a task ID absent from `manifest.tasks` THEN emit `L004` diagnostic.
  - L005 (error): IF task dependency graph contains a directed cycle THEN emit `L005` diagnostic listing cyclic task IDs.
  - L006 (error): IF any path in `read`, `write`, `create`, `protected`, `contracts.files`, `verify.cwd`, or `setup.cwd` fails `isSafePath` (absolute, contains `..`, or escapes root) THEN emit `L006` diagnostic.
  - L007 (error): IF any pattern in `spec.write` matches no existing files at base in repository THEN emit `L007` diagnostic (use `create` for new files).
  - L008 (warn): IF two tasks ready at the same DAG layer have overlapping `write` or `create` patterns per `matchGlob` THEN emit `L008` diagnostic indicating auto-serialization.
  - L009 (error): IF a task's `write` or `create` patterns intersect another task's `protected` patterns (and task is not the authoring `tests` task) THEN emit `L009` diagnostic.
  - L010 (error): IF `spec.verify` is empty or missing THEN emit `L010` diagnostic.
  - L011 (error): IF binary in `verify.run` cannot be resolved on PATH or `verify.cwd` does not exist THEN emit `L011` diagnostic.
  - L012 (error): IF verify command references a test path not existing at base AND not created by an earlier dependency task THEN emit `L012` diagnostic.
  - L013 (error): IF placeholder tokens (`TODO`, `FIXME`, `TBD`, `...`, `<placeholder>`) appear in `Interface` or `Behavior` sections THEN emit `L013` diagnostic.
  - L014 (error): IF any required section (`Objective`, `Interface`, `Behavior`, `Invariants`, `Edge cases`, `Guardrails`, `Out of scope`) is missing or empty THEN emit `L014` diagnostic.
  - L015 (error): IF `spec.class` is not present in `settings.routing` THEN emit `L015` diagnostic.
  - L016 (error): IF `spec.budget` is missing OR `spec.budget.max_usd` exceeds `settings.budgets.task.max_usd` THEN emit `L016` diagnostic.
  - L017 (error): IF aggregate files matching `spec.read` exceed file count cap (default 50) or byte cap (default 500 KB) THEN emit `L017` diagnostic to split the task.
  - L018 (error): IF contract typecheck commands fail execution THEN emit `L018` diagnostic.
  - L019 (error): IF `Interface` section or `manifest.contracts.files` references non-existent contract files THEN emit `L019` diagnostic.
  - L020 (warn/error): IF code fence in spec contains implementation bodies (statements/braces) rather than declarations THEN emit `L020` diagnostic (severity per config).
  - L021 (warn): IF `manifest.integration_verify` is empty THEN emit `L021` diagnostic.
  - L022 (gate): IF estimated run cost exceeds `settings.budgets.approval_threshold_usd` THEN emit `L022` gate diagnostic.
  - L023 (warn/error): IF red-check mode is enabled AND verify command passes at base ref before modifications THEN emit `L023` diagnostic (error with `--red-check`, else warn).
  - L024 (warn): IF task with `class === "tests"` modifies non-test paths OR non-tests task modifies test paths THEN emit `L024` diagnostic.
  - L025 (warn): IF `manifest.budget.max_usd` exceeds `settings.budgets.run.max_usd` THEN emit `L025` diagnostic indicating budget clamping.
  - L026 (warn): IF total task count in `manifest.tasks` exceeds `max_tasks` (default 40) THEN emit `L026` diagnostic.
  - L027 (error): IF a path in `spec.protected` does not exist at base AND is not in `create` set of an earlier dependency task THEN emit `L027` diagnostic.

- Semantic Check Hook Points (S001–S004):
  - IF `options.semanticHook` is supplied THEN invoke `semanticHook.runSemanticChecks(plan, repoRoot)` asynchronously.
  - IF semantic hook returns diagnostics with codes `S001` (ambiguity), `S002` (missing edge cases), `S003` (contract mismatch), or `S004` (task too large) THEN append them to results with severity `"info"`; ELSE skip semantic evaluation.
  - Advisory semantic diagnostics NEVER cause `LintResult.ok` to become `false`.

- Diagnostics Aggregation:
  - IF any diagnostic has severity `"error"` THEN set `LintResult.hasErrors = true` and `LintResult.ok = false`.
  - IF any diagnostic has severity `"gate"` THEN set `LintResult.hasGates = true`.
  - IF no diagnostics have severity `"error"` THEN set `LintResult.hasErrors = false` and `LintResult.ok = true`.

## Invariants

- Linter checks L001–L027 are fully deterministic and run in code without network access or LLM invocation.
- All path validation uses `isSafePath` from `src/util/index.js`; no path inside manifest or specs may escape `repoRoot`.
- Parsing and linting are strictly read-only and never write or modify repository files or git branches.
- Contract typecheck stubs must compile cleanly (exit 0) before any worker is spawned (Invariant I3).
- Every Appendix C diagnostic code L001–L027 and S001–S004 is represented with its exact declared severity and shape.
- `src/spec/**` imports only from `src/contracts/**` and `src/util/**`, maintaining §15 architectural boundaries.

## Edge cases

- Empty manifest or empty spec files THEN flag `L001` schema error naming the empty file.
- Single-task manifest with self-dependency (`depends_on: [taskId]`) THEN detect cycle and emit `L005`.
- Disconnected components in dependency DAG THEN validate each component independently without error.
- Task spec containing markdown frontmatter fences (`---`) inside code blocks THEN parse only the true document header.
- Windows CRLF line endings (`\r\n`) in YAML or Markdown THEN normalize to LF transparently without altering line numbers.
- Unicode characters or special symbols in spec text THEN handle cleanly without UTF-8 encoding corruption.
- Broken symlinks or symlinks pointing outside the repository THEN detect via `isSafePath` and report `L006`.
- Large repositories exceeding 10,000 files during repo map generation THEN cap traversal at `maxFiles` without out-of-memory errors.
- Spec code fences containing only type signatures (`export interface`, `export type`) THEN pass `L020` check.
- `spec.write` glob patterns containing wildcards (`src/**/*.ts`) THEN expand against base tree to verify at least one file matches.

## Guardrails

- Never write to or mutate files outside the explicit test artifacts directory during test execution.
- Never execute git commands (`commit`, `push`, `checkout`, `reset`, `rebase`, `clean`, `stash`) within `src/spec/**`.
- Never expose or log private environment variables, auth tokens, or secrets during contract typecheck or linting.
- Keep every code fence in spec documentation <= 12 lines to satisfy automated speccheck verification.
- Unit tests under `test/unit/spec/**` must cover every individual lint rule L001–L027 with dedicated positive and negative cases.

- Planner spawning, artifact collection, and automated retry loop: handled in P4.2 (`src/roles/planner.ts`).
- Git worktree provisioning, branch management, merge preflight, and verify execution: handled in P2.1 (`src/git/**`, `src/verify/**`).
- Engine state machine reducer, scheduler action dispatch, and event logging: handled in P1.2 (`src/engine/**`, `src/store/**`).
- CLI commands (`substrate lint`, `substrate plan`): handled in P5.1 (`src/cli/**`).
- TUI screens and visual tree rendering: handled in P5.3 (`src/tui/**`).
