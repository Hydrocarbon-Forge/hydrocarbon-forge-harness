## Objective

Implement the complete Substrate Command Line Interface (CLI):
1. Binary dispatcher and CLI architecture (`bin/substrate.mjs`, `src/cli/**`): Replace the P0.1 stub with an executable Node entrypoint delegating to a self-registering command registry (`src/cli/registry.ts`), handling flag parsing per §4.1, signal trapping (SIGINT, SIGTERM), and prompt intake from positional arguments or stdin.
2. 18 Core Subcommands:
   - Execution & orchestration: `run`, `plan`, `resume`.
   - Inspection & telemetry: `status`, `tasks`, `cost`, `report`.
   - Workspace verification & lifecycle: `verify`, `merge`, `undo`, `discard`.
   - Configuration & system diagnostics: `models`, `agents`, `backends`, `sessions`, `config`, `doctor`, `init`.
   - Command modules self-register into `src/cli/registry.ts`; excludes `bench.ts` (Phase 6, P6.3) and `agents-import.ts` (Phase 5, P5.2).
3. Session index and persistence (`src/store/sessions.ts`): Manage `.substrate/sessions/<session_id>.json` records tracking session prompts, run IDs, modes, and timestamps; implement session resolution supporting `--resume <id>` (disambiguating session thread vs run replay), `-c`/`--continue` (most recent session in directory), and `--fork-session` (branching prompt history).
4. Output formatting and streaming (§4.6): Implement `text` (human summary), `json` (final summary object), and `stream-json` (NDJSON stream mapping engine events to schema-compliant types including `system.init`, `run.state`, `plan.ready`, `task.started`, `task.verified`, `task.failed`, `batch.merged`, `usage`, and final `result` event).
5. Exit codes: Enforce canonical exit codes per §4.6 (`0` success, `1` run failed, `2` usage/config error, `3` needs human/gate pause, `4` budget exhausted, `130` SIGINT, `143` SIGTERM).
6. Comprehensive test suite: Integration test battery (`test/integration/cli/**`) and session store unit tests (`test/unit/store/sessions.test.ts`).

## Behavior

- Entrypoint and Signal Trapping (`bin/substrate.mjs`, `src/cli/dispatcher.ts`):
  - IF CLI is invoked via `bin/substrate.mjs` THEN delegate to `runCli(process.argv.slice(2))` and terminate process with returned exit code.
  - IF process receives `SIGINT` (Ctrl+C) THEN:
    - Trigger `AbortController` signal to notify active engine and backend processes.
    - Emit cancellation message to stderr or NDJSON result event (`subtype: "error_failed"`, `is_error: true`).
    - Exit immediately with code `130`.
  - IF process receives `SIGTERM` THEN:
    - Abort active execution cleanly and release run locks.
    - Exit immediately with code `143`.

- Argument Parsing and Intake Routing (`parseCliArgs`, `src/cli/dispatcher.ts`):
  - Parse CLI flags using `node:util` `parseArgs` with strict flag definitions:
    - Booleans: `--print` (`-p`), `--continue` (`-c`), `--fork-session`, `--no-governor`, `--worktree` (`-w`), `--sandbox`.
    - Strings: `--output-format`, `--model`, `--worker-model`, `--effort`, `--session-id`, `--resume`, `--mode`, `--permission-mode`, `--settings`, `--max-budget-usd`, `--timeout`.
    - Arrays: `--allowed-tools`, `--disallowed-tools`.
  - Identify target subcommand:
    - IF first positional argument matches a registered command name or alias in `CommandRegistry` THEN select that subcommand and shift positional arguments.
    - ELSE IF `-p` or `--print` is provided OR first argument is not a known command AND prompt is provided THEN select default subcommand `run`.
    - ELSE IF no positional arguments are provided AND stdin is a TTY THEN:
      - In v0.1 headless build: display help and available subcommands, exit `0`.
    - ELSE (unrecognized command and no prompt) THEN print error to stderr, suggest valid commands, exit `2`.
  - Stdin Prompt Intake (`readStdinIfAvailable`):
    - IF positional arguments include a prompt THEN use the positional prompt string.
    - ELSE IF stdin is not a TTY (pipe or file redirect) THEN read complete UTF-8 stream from stdin.
      - IF stdin content trimmed is non-empty THEN use stdin as prompt string.
      - ELSE IF command requires a prompt (`run`, `plan`) THEN print error to stderr ("Error: prompt required on command line or stdin"), exit `2`.
    - ELSE IF command requires a prompt THEN print error to stderr ("Error: prompt required"), exit `2`.

- Flag Overlays & Configuration Integration (§4.1):
  - Load hierarchical settings via `loadSettings`:
    - 1. User config: `~/.config/substrate/settings.json`.
    - 2. Project config: `.substrate/settings.json`.
    - 3. Local project config: `.substrate/settings.local.json`.
    - 4. Custom settings file: IF `--settings <path>` is supplied, merge settings from `<path>`.
    - 5. Flag overrides:
      - IF `--permission-mode` is supplied THEN override settings permission mode; ELSE IF running headless (`run` or `-p`) without explicit flag THEN default to `dontAsk` (§4.4).
      - IF `--model` is supplied THEN override primary model (`roles.planner.model` in plan mode, `roles.worker.model` in solo mode).
      - IF `--worker-model` is supplied THEN override worker routing model for all task classes in `settings.routing`.
      - IF `--effort` is supplied THEN override effort for primary route.
      - IF `--allowed-tools` or `--disallowed-tools` are supplied THEN parse Claude-syntax rules and append to `settings.permissions.allow` or `settings.permissions.deny`.
      - IF `--max-budget-usd` is supplied THEN set `settings.budgets.run.max_usd`.
      - IF `--timeout` is supplied THEN set `settings.budgets.run.max_wall_min`.
      - IF `--sandbox` is supplied THEN set `settings.sandbox.enabled = true`.
      - IF `--no-governor` is supplied THEN record `noGovernor: true` in router flags.

- Session Index and Continuity (`src/store/sessions.ts`):
  - Storage location: `.substrate/sessions/<session_id>.json`.
  - Session Identity and Resolution:
    - IF `--session-id <id>` is provided THEN:
      - IF `.substrate/sessions/<id>.json` exists THEN load session record.
      - ELSE initialize new session record with id `<id>`.
    - ELSE IF `-c` or `--continue` is specified THEN:
      - Call `SessionStore.getLatest()`.
      - IF a previous session exists THEN load that session; ELSE print error ("No prior session found in this directory"), exit `2`.
    - ELSE IF `--resume <target>` is specified (or subcommand `substrate resume <target>`):
      - Call `resolveResumeTarget(target)`:
        - IF `<target>` matches `.substrate/sessions/<target>.json` THEN load session and select its most recent run ID.
        - ELSE IF `<target>` matches `.substrate/runs/<target>/` THEN select that run ID directly.
        - ELSE IF target is omitted THEN select most recent run of latest session, or latest run in `.substrate/runs/`; IF none found exit `2`.
    - ELSE IF `--fork-session` is specified THEN:
      - Resolve source session (via `-c`, `--resume`, or latest session).
      - Create new session record copying prompt history and mode, with fresh `sessionId` and current timestamp.
    - ELSE (fresh session) THEN:
      - Generate new random UUID or base32 session ID, initialize `.substrate/sessions/<session_id>.json` with mode, initial prompt, empty `runs` array.
  - Recording Runs:
    - Whenever `Engine.run` or `Engine.resume` initiates a run with `run_id`, call `SessionStore.addRun(sessionId, runId, prompt)`.
    - Atomically write updated session record to `.substrate/sessions/<session_id>.json`.

- Output Formatting & Streaming (§4.6):
  - Formatter selection:
    - IF `--output-format` is `"json"` THEN buffer summary and print a single structured JSON object on stdout upon completion.
    - ELSE IF `--output-format` is `"stream-json"` THEN:
      - Stream NDJSON events immediately to stdout.
      - Translate engine events to protocol types:
        - Engine start -> `system.init` (session_id, run_id).
        - State change -> `run.state` (state, ts).
        - Plan produced -> `plan.ready` (manifest summary, task count).
        - Task lifecycle -> `task.started`, `task.verified`, `task.failed`.
        - Merge lifecycle -> `batch.merged`.
        - Usage update -> `usage` (records, cost).
        - Terminal completion -> emit final `result` event mirroring Claude Code format:
          `{"type":"result","subtype":"success"|"error_failed"|"error_budget"|"error_needs_human","is_error":boolean,"session_id":string,"run_id":string,"num_tasks":number,"total_cost_usd":number,"usage":{"by_role":{...}},"duration_ms":number}`.
    - ELSE (default `"text"`) THEN:
      - Print interactive progress notices during run.
      - Upon completion print human-readable summary table: Run ID, Status, Tasks summary (Passed / Failed / Healed / Total), Total Cost ($USD), Duration (seconds), Branch name.

- Exit Code Enforcement (§4.6):
  - IF run finishes with status `"finished"` AND all tasks passed THEN return exit code `0`.
  - ELSE IF run finishes with status `"failed"` OR any task failed permanently THEN return exit code `1`.
  - ELSE IF command line arguments are invalid, configuration fails schema, or session is not found THEN return exit code `2`.
  - ELSE IF run pauses due to `needs_approval`, `permission_denied`, `needs_human`, or escalation L3 THEN return exit code `3`.
  - ELSE IF run pauses or fails due to `budget_exhausted` or budget overshoot THEN return exit code `4`.
  - ELSE IF interrupted by SIGINT (Ctrl+C) THEN return exit code `130`.
  - ELSE IF terminated by SIGTERM THEN return exit code `143`.

- Execution Subcommands:
  - `run` (`src/cli/commands/run.ts`):
    - Validate prompt intake; load settings and flag overlays; resolve or initialize session.
    - Construct `RunOptions` with `mode: flags.mode ?? "auto"`, `permission_mode: flags.permissionMode ?? "dontAsk"`.
    - Execute `Engine.run(opts)`; attach output formatter to `onEvent`; return mapped exit code.
  - `plan` (`src/cli/commands/plan.ts`):
    - Validate prompt intake; force `permission_mode: "plan"`; execute `Engine.run(opts)`.
    - Stop after manifest generation, linting, and cost estimation; return exit code `0` if plan is ready and lint passes, `1` if lint fails.
  - `resume` (`src/cli/commands/resume.ts`):
    - Resolve target run ID using `resolveResumeTarget`.
    - Invoke `Engine.resume(runId, opts)`; attach output formatter; return mapped exit code.

- Inspection Subcommands:
  - `status` (`src/cli/commands/status.ts`):
    - Resolve target run (explicit argument, or latest run); read `.substrate/runs/<run_id>/events.jsonl`.
    - Reduce events to current `EngineState`; display run state, pause reason, completed/in-flight tasks, and cumulative cost.
  - `tasks` (`src/cli/commands/tasks.ts`):
    - Read run state; display table of tasks: ID, Class, State, Generation, Attempt, FailureClass, and Verify status.
  - `cost` (`src/cli/commands/cost.ts`):
    - IF run ID argument is provided THEN read run usage and print cost breakdown per role and per model.
    - ELSE IF `--since <date>` is provided OR default THEN read `.substrate/ledger/usage.jsonl` and display aggregate spend over the window.
  - `report` (`src/cli/commands/report.ts`):
    - Read `.substrate/runs/<run_id>/`: manifest, events, packets, worker reports.
    - Print diagnostic report including goal, task DAG, replan iterations, failure packets, diff stat, and verify output tails.

- Workspace & Git Subcommands:
  - `verify` (`src/cli/commands/verify.ts`):
    - Locate task spec in latest run; find worktree at `.substrate/worktrees/<run_id>/<task_id>/`.
    - Run task's `verify` commands in worktree using verify runner; print stdout/stderr tails; exit `0` if all pass, `1` if any fail.
  - `merge` (`src/cli/commands/merge.ts`):
    - Check run state is finished and passed; checkout current git branch; merge run branch `substrate/runs/<run_id>` into current branch per gate rules (§4.4); exit `0` on clean merge, `1` on conflict.
  - `undo` (`src/cli/commands/undo.ts`):
    - Query last merged batch checkpoint from run events; revert run branch to prior batch checkpoint ref; exit `0`.
  - `discard` (`src/cli/commands/discard.ts`):
    - Acquire or force run lock; remove worktree directories under `.substrate/worktrees/<run_id>/`; delete run branch `substrate/runs/<run_id>`; exit `0`.

- Configuration & Discovery Subcommands:
  - `models` (`src/cli/commands/models.ts`):
    - Read resolved settings; display routing table: TaskClass -> Backend, Model, Effort, and escalation chain.
  - `agents` (`src/cli/commands/agents.ts`):
    - Scan agent definition paths (`.substrate/agents/`, `~/.config/substrate/agents/`, `assets/agents/`); display agent names, roles, models, and descriptions.
  - `backends` (`src/cli/commands/backends.ts`):
    - Instantiate each adapter (`claude`, `opencode`, `agy`, `fake`); invoke `validateEnvironment()`; display version pins, installed versions, and capabilities.
  - `sessions` (`src/cli/commands/sessions.ts`):
    - Read `.substrate/sessions/`; display table of sessions: SessionId, Created, Mode, Run count, and latest prompt.
  - `config` (`src/cli/commands/config.ts`):
    - Subcommands `get <key>`, `set <key> <val>`, `list`: inspect or update project `.substrate/settings.json`.
  - `doctor` (`src/cli/commands/doctor.ts`):
    - Check Node version (>= 22), git version, bubblewrap sandbox availability, harness CLI versions vs pins (§11.1), llama.cpp endpoint health.
    - Print diagnostic status table; return exit code `0` if all required checks pass, `1` if critical requirements fail.
  - `init` (`src/cli/commands/init.ts`):
    - Detect installed backends; generate initial `.substrate/settings.json`; create `.substrate/{sessions,state,runs,worktrees}` directories; append `.substrate/` entries to `.git/info/exclude`.

## Invariants

- Self-registering command architecture: every subcommand module in `src/cli/commands/` self-registers into `src/cli/registry.ts` via `registry.register(cmd)`.
- Boundary isolation: `src/cli/**` is a surface module and may import contracts, store, engine, config, backends, spec, git, verify, ledger, util; NO internal subsystem may import `src/cli/**` (§15).
- Excluded subcommands: `src/cli/bench.ts` is deferred to Phase 6 (P6.3); `src/cli/agents-import.ts` is deferred to Phase 5 (P5.2). Neither is included in P5.1.
- Exit codes strictly adhere to §4.6: `0` (success), `1` (run failed), `2` (usage/config error), `3` (needs human / gate pause), `4` (budget exhausted), `130` (SIGINT), `143` (SIGTERM).
- Headless default permission mode is `dontAsk` (§4.4) unless explicitly overridden by `--permission-mode`.
- Stream-json output emits strictly valid single-line NDJSON events, ending with a terminal `result` event matching Claude Code's result event schema.
- Resuming disambiguation: `--resume <id>` unambiguously checks `.substrate/sessions/<id>.json` first (session resume), then `.substrate/runs/<id>/` (run resume).
- Stdin prompt handling never hangs: when stdin is a TTY and no prompt is provided, CLI exits with usage code `2` rather than waiting indefinitely for input.
- Every code block within this specification is strictly <= 12 lines in length.

## Edge cases

- Empty prompt piped on stdin: `readStdinIfAvailable` trims input; IF empty string received, emit usage error to stderr and exit `2`.
- Conflicting session flags: IF both `--continue` and `--resume <id>` are passed on CLI, report mutual exclusivity error and exit `2`.
- Resuming an already finished run: `resume` checks run state; if already `finished` or `cancelled`, print summary and exit `0` without creating redundant effects loop.
- Non-existent session or run identifier: `resolveResumeTarget` reports clear error ("Neither session nor run found matching '<id>'") and exits `2`.
- `--continue` in clean directory with no prior sessions: exit `2` with error ("No prior session found in this directory").
- `--fork-session` without an active or specified session: exit `2` with error ("No session available to fork").
- Corrupted or invalid JSON in session file: log warning, ignore corrupted session file during list/getLatest, and prevent CLI crash.
- Stdin EOF during streaming output: formatters flush remaining buffers before process termination.
- Rapid double SIGINT: first SIGINT triggers graceful cancel; second SIGINT terminates process immediately with code `130`.
- Missing bubblewrap when `--sandbox` is enabled: `doctor` flags warning/error; verify runner reports sandbox configuration defect.
- Unrecognized subcommand: print error, suggest nearest matching subcommand or display help, exit `2`.

## Guardrails

- Never write implementation bodies in task specs or contract stubs; declare signatures matching contracts.
- Never execute git commit, push, checkout, reset, rebase, clean, or stash.
- Never print or leak secrets, api keys, tokens, or emails into CLI stdout, stderr, logs, or session records.
- Obey §15 architectural boundaries: `cli` is surface; no internal engine/store/backend module may import `cli`.
- Keep every code fence in the specification document <= 12 lines to satisfy speccheck validation.
