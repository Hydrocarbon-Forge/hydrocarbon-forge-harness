## Objective

Implement the Substrate roles foundation: built-in agent assets (`planner`, `worker`, `test-writer`, `reviewer`, `governor`), prompt builders for role execution and failure replanning, the governor front door providing an OpenAI-compatible client with tool calling and bounded intake, the fixed typed tool set (Appendix A), the rules-first router with escalation and route-to-outcome ledger, and advisory semantic linting (checks S001–S004).

## Behavior

- Built-in Agent Assets (`assets/agents/*.md`):
  - IF agent definitions are loaded by `loadAgentDefinitions` THEN discover `assets/agents/planner.md`, `worker.md`, `test-writer.md`, `reviewer.md`, and `governor.md`.
  - IF agent is `worker.md` THEN declare `role: worker`, set `omitClaudeMd: true` to suppress Claude Code markdown bloat, and body specifies task-spec focused unattended execution.
  - IF agent is `planner.md` THEN declare `role: planner`, and body instructs generating `manifest.yaml`, task specs, and contract stubs without implementation bodies.
  - IF agent is `test-writer.md` THEN declare `role: test-writer`, and body instructs authoring test files satisfying contract interfaces and acceptance criteria before worker implementation.
  - IF agent is `reviewer.md` THEN declare `role: reviewer`, and body instructs evaluating final patch diff against contracts and invariants.
  - IF agent is `governor.md` THEN declare `role: governor`, and body instructs acting as conversational front door, routing requests, asking clarifying questions, and invoking typed governor tools.

- Role Prompt Builders (`src/roles/prompts/**`):
  - Planner Prompt (`buildPlannerPrompt`):
    - IF `skillsList` is provided THEN disclose only skill names and descriptions (progressive disclosure); ELSE omit skills section.
    - IF `instructionFiles` are provided THEN include paths to instructions; ELSE omit instructions section.
    - IF `repoMap` is provided THEN include formatted structural repo map; ELSE emit placeholder indicating empty repo map.
    - Body strictly directs planner to author `manifest.yaml`, task specs with required headings, and contract stubs into run directory, forbidding implementation bodies.
  - Worker Prompt (`buildWorkerPrompt`):
    - Return exact canonical one-sentence prompt: `"Execute the task spec at <abs path>. Work only in the current directory. Do not run git commit/push/checkout/reset. Reply with one line: DONE or BLOCKED: <reason>."`
    - IF `specAbsPath` is relative or unsafe THEN throw error before producing prompt; ELSE format absolute path into template.
  - Test-Writer Prompt (`buildTestWriterPrompt`):
    - IF spec content and contract stubs are provided THEN format prompt with acceptance criteria from `verify` section and stub declarations; ELSE throw error for missing spec or contracts.
    - Instruct test-writer to create new test files only and forbid modifying application source code.
  - Reviewer Prompt (`buildReviewerPrompt`):
    - IF patch diff and contract list are provided THEN construct reviewer prompt containing diff statistics, patch lines, and contract expectations.
    - Instruct reviewer to verify invariants, scope isolation, and acceptance criteria satisfaction, emitting a structured review report.
  - Replan Prompt (`buildReplanPrompt`):
    - IF `packet.failure_class` indicates `verify_failed` THEN include failing verify command tail outputs, error codes, and patch diff.
    - ELSE IF `packet.failure_class` indicates `scope_violation` THEN list offending file paths and instruct narrowing worker scope.
    - ELSE IF `packet.failure_class` indicates `protected_modified` THEN list modified protected files and instruct preserving them byte-identical.
    - IF `decisionsLog` is provided THEN append prior planner decisions to maintain context across generations; ELSE omit decisions log.

- Governor Tools (`src/roles/governor-tools.ts`):
  - Tool Definitions:
    - Export OpenAI-compatible tool specifications for the 7 canonical tools: `start_run`, `plan_only`, `resume_run`, `run_status`, `show_cost`, `cancel_run`, `ask_user`.
    - IF tool name is unrecognized THEN throw validation error rejecting the tool call.
  - Tool Call Parsing and Validation (`parseGovernorToolCall`):
    - IF tool call is `start_run` AND `args.request` is a non-empty string THEN validate optional `mode` (`solo` | `plan`) and `permission_mode`; ELSE reject if request is missing.
    - IF tool call is `plan_only` AND `args.request` is a non-empty string THEN validate arguments; ELSE reject if request is missing.
    - IF tool call is `resume_run` AND `args.run_id` satisfies `RunId` regex THEN validate arguments; ELSE reject malformed `run_id`.
    - IF tool call is `run_status` OR `show_cost` THEN validate optional `run_id`; ELSE reject invalid `run_id` format if present.
    - IF tool call is `cancel_run` AND `args.run_id` satisfies `RunId` regex THEN validate arguments; ELSE reject malformed `run_id`.
    - IF tool call is `ask_user` AND `args.question` is non-empty THEN validate arguments; ELSE reject empty question string.

- Governor Front Door (`src/roles/governor.ts`):
  - Health Check (`checkGovernorHealth`):
    - IF endpoint is configured THEN perform HTTP GET to `${endpoint}/health` (or `/v1/models`) with timeout (default 10s per `Settings.roles.governor.timeout_s`).
    - IF response status is 200 within timeout THEN return `true`; ELSE return `false` without throwing or blocking.
  - Bounded Intake Calling (`callGovernorIntake`):
    - IF governor is disabled in settings OR `/health` check fails THEN bypass governor and fall through to deterministic rules/default `plan`.
    - IF governor is reachable THEN invoke OpenAI-compatible `/v1/chat/completions` with:
      - `messages`: system prompt from `assets/agents/governor.md` and user prompt.
      - `tools`: `GOVERNOR_TOOL_DEFINITIONS`.
      - `tool_choice`: `"auto"`.
      - `response_format`: `{ type: "json_schema", json_schema: RoutingDecisionSchema }`.
      - `chat_template_kwargs`: `{ enable_thinking: false }` (thinking disabled to prevent token exhaustion and empty responses).
    - IF response contains tool calls THEN parse each through `parseGovernorToolCall` and return in `GovernorIntakeResult.toolCalls`.
    - IF response asks a clarifying question (`ask_user` or `needs_clarification`) AND current turn count < `max_clarifying_turns` THEN return clarifying question to caller; ELSE finalize routing decision without further questions.
    - Governor permissions: Governor NEVER plans, NEVER implements, NEVER edits repo files, and NEVER mutates engine caps or verdicts.
  - Advisory Semantic Lint (`runGovernorSemanticLint`):
    - IF invoked by plan linter hook THEN issue OpenAI-compatible completion with `chat_template_kwargs: { enable_thinking: true }`.
    - Evaluate plan specs against S001 (ambiguity), S002 (missing edge cases), S003 (spec/contract mismatch), and S004 (task too large).
    - IF semantic deficiencies are detected THEN emit `Diagnostic` records with codes `S001`–`S004` and severity `"info"`; ELSE return empty diagnostic list.
    - Advisory semantic lint diagnostics NEVER cause `LintResult.ok` to fail.

- Rules-First Router (`src/roles/router.ts`):
  - Decision Priority (First Match Wins per §6.3):
    - Step 1 (Explicit Flags):
      - IF `flags.mode === "solo"` THEN return `{ mode: "solo", rationale: "Explicit --mode solo flag" }`.
      - IF `flags.mode === "plan"` THEN return `{ mode: "plan", rationale: "Explicit --mode plan flag" }`.
      - IF `flags.noGovernor === true` THEN bypass governor LLM and proceed to Step 2.
    - Step 2 (Deterministic Rules):
      - IF user prompt names a single existing file in repo AND contains a mechanical verb ("rename", "move", "delete", "remove", "bump", "format", "typo", "fix typo", "update dependency") THEN return `{ mode: "solo", task_class: "mechanical", rationale: "Deterministic match: single file with mechanical verb" }`.
    - Step 3 (Governor LLM):
      - IF `settings.roles.governor?.enabled` is `true` AND `checkGovernorHealth` succeeds within 10s THEN call `callGovernorIntake(prompt)`.
      - IF governor returns valid `RoutingDecision` THEN return that decision; ELSE fall through to Step 4.
    - Step 4 (Default Fallback):
      - Return `{ mode: "plan", planner_route: "default", rationale: "Default plan fallback" }`.
  - Route Resolution (`resolveTaskRoute`):
    - IF `generation === 1` THEN lookup `taskClass` in `settings.routing`; IF found return `Route`; ELSE throw or fallback to `"feature"`.
    - IF `generation >= 2` THEN check `settings.routing.escalation` array; advance model to the next tier along escalation chain (e.g. `haiku → sonnet → opus`); IF already at top tier THEN retain top tier model.
  - Route-to-Outcome Ledger (`appendRouteOutcome`):
    - When routing decision is made, create `RouteOutcomeRecord` recording `run_id`, `decision`, `rule_matched`, and `timestamp`.
    - When task finishes execution, record `outcome` (`passed`, `failed`, `healed`, `replanned`), `cost_usd`, and `duration_ms` to `.substrate/ledger/routes.jsonl` (or configured ledger store).

## Invariants

- Front door governor LLM calls are strictly read-only and non-authoritative; governor CANNOT plan, implement, edit repo files, or alter caps/verdicts (Invariant I1, §6.3).
- Thinking mode is explicitly disabled (`enable_thinking: false`) for governor tool calling and intake to prevent hidden reasoning token exhaustion.
- Thinking mode is enabled (`enable_thinking: true`) ONLY for advisory semantic lint (S001–S004).
- Advisory semantic lint checks S001–S004 are strictly informational and never fail plan validation (`severity: "info"`).
- Routing decision order is strictly prioritized: (1) explicit flags, (2) deterministic mechanical rules, (3) governor LLM, (4) default `plan` fallback.
- If governor is unreachable or times out (10s), the engine falls through to fallback without blocking or crashing (§6.3, A9).
- Clarifying questions by the governor are bounded by `max_clarifying_turns` (default 2); unbounded conversational loops are forbidden.
- Worker prompt builder emits the exact canonical one-sentence prompt string from §7.
- Escalation chain advances tasks with generation >= 2 up the configured escalation sequence.
- All code fences in spec are <= 12 lines in length.
- Module imports adhere strictly to §15 architecture boundaries (roles import contracts, util, config, spec, ledger; surface `cli`/`tui` never imported).

## Edge cases

- Governor endpoint unreachable / connection refused: `checkGovernorHealth` returns false within timeout, router smoothly falls through to default `plan`.
- Governor endpoint hangs / responds slowly: request times out at 10s and aborts via AbortController, router falls back to default `plan`.
- Governor returns invalid JSON or unparseable tool call arguments: parser catches error and falls back to deterministic/default routing.
- Governor calls `ask_user` when turn count >= `max_clarifying_turns`: intake rejects further clarification and forces routing decision or default `plan`.
- Prompt contains multiple files or complex multi-step verbs: deterministic rule does not match, routes to governor or `plan`.
- Prompt contains mechanical verb but no named file: deterministic rule does not match, routes to governor or `plan`.
- Task generation exceeds length of `settings.routing.escalation`: clamp model at highest available tier in chain without throwing out-of-bounds error.
- Worker prompt built with relative path: `buildWorkerPrompt` asserts absolute path or normalizes to absolute path using `path.resolve`.
- Replan prompt with missing `diff` or truncated patch: formats notice indicating diff truncation, preserving failure packet context.
- Missing `assets/agents/*.md` files: throws clear error naming missing built-in asset file.

## Guardrails

- Never write implementation bodies in task specs or contract stubs; declare signatures matching contracts.
- Never execute git commit, push, checkout, reset, rebase, clean, or stash.
- Never print or leak secrets, tokens, api keys, or emails into prompts, logs, or ledger records.
- Never allow governor to bypass engine verification, modify git trees, or approve plan gates.
- Keep every code fence in the specification document <= 12 lines to satisfy speccheck validation.
