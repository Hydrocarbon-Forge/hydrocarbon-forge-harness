## Objective
Replace the fake harness's scenario selection (the `FAKE_SCENARIO` environment variable and per-scenario switches) with a scenario file, and add three executables, `claude`, `opencode` and `agy`, that speak each real CLI's output dialect and really edit files in the current directory. After this WP, a test can run a fake executable in a temp directory, the scenario edits a file, and the file on disk changes. The engine must not fabricate edits; the fake does it. You change no file under `src/`.

## Interface
Scenario file: JSON at the path given by the environment variable `FAKE_SCENARIO_FILE`. Shape:
```json
{ "calls": [ { "edits": {"out.txt": "text"}, "append": {}, "reply": "OK",
  "usage": {"input": 100, "output": 20, "cache_read": 0, "cache_write": 0},
  "cost_usd": 0.0001, "exit_code": 0, "delay_ms": 0, "failure": null,
  "plan": {"files": {"manifest.yaml": "..."}} } ] }
```
All fields are optional except `calls`. `failure` is one of `null`, `crash`, `hang`, `rate_limit`, `permission_denial`. `plan.files` is written into the process cwd before any other step (used for a planner call; the file contents are whatever the test passes).

Files you create:
- `test/fixtures/fake-harness/scenario.mjs` exports `readScenario(file)`, `takeCall(file)` and `applyCall(call, cwd)`. Pure ES module, no dependencies beyond `node:fs` and `node:path`.
- `test/fixtures/fake-harness/dialects/claude.mjs` exports `runDialect(argv, env)`.
- `test/fixtures/fake-harness/bin/claude`, `bin/opencode`, `bin/agy`: extensionless executables. Each starts with `#!/usr/bin/env node`, has mode `0755`, and only calls `runDialect(process.argv.slice(2), process.env)` from its matching dialect file and then `process.exit` with the returned code.
- `test/conformance/fake-executables.test.ts` and `test/conformance/dialects.test.ts`.

Files you write: `dialects/opencode.mjs` and `dialects/agy.mjs` each gain an exported `runDialect(argv, env)`. Their existing `isMain` blocks and `FAKE_SCENARIO` behaviour stay, because `test/integration/backends/*.test.ts` run them directly and must keep passing.

## Behavior
1. `takeCall(file)` reads the counter file `<file>.state.json` (content `{"next": n}`, absent means 0), selects `calls[n]`, writes `{"next": n+1}` before returning, and returns `{call, index}`. Each invocation of any fake executable consumes exactly one call, including `--resume` invocations. If `n >= calls.length`, the executable writes `fake-harness: scenario has no call <n>` to stderr and exits 3.
2. If `FAKE_SCENARIO_FILE` is unset, or the file does not exist, the executable writes `fake-harness: FAKE_SCENARIO_FILE not set` (or `... not found: <path>`) to stderr and exits 3.
3. `applyCall(call, cwd)` writes each `edits` entry (create parent directories, UTF-8) and appends each `append` entry. A path that is absolute or contains a `..` segment makes it exit 3 with `fake-harness: unsafe path <path>`. `plan.files` is written the same way.
4. `failure` handling, applied after `applyCall`:
   - `crash`: write `fake-harness: simulated crash` to stderr, print nothing to stdout, exit 1.
   - `hang`: print nothing more and keep the process alive with `setInterval(() => {}, 1 << 30)`.
   - `rate_limit`: emit the dialect's error result (claude: a `result` with `is_error: true` and text containing `rate_limit`), exit 1.
   - `permission_denial`: claude emits a `system` event with `subtype: "permission_denied"` and a `result.permission_denials` entry; opencode emits only text with no tool event (S2: denials are invisible); agy emits `result.denied_actions` and writes the S3 stderr line `jetski: no output produced` followed by any text, exit 0.
5. Session ids. claude: `--session-id <id>` or `--resume <id>` is echoed on `system.init` and on `result`; if neither is given, use `crypto.randomUUID()`. If the given id is not a UUID, exit 1 with `Error: Invalid session ID. Must be a valid UUID.` (Verify first, see Notes.) opencode: `-s <id>` or `--session <id>` is echoed as `sessionID`, otherwise generate `ses_` plus 12 random base-36 characters. agy: `--conversation <id>` is echoed as `conversation_id` on `init` and on `result`, otherwise generate a UUID.
6. Dialect output. Copy the event shapes from the recorded fixtures listed in `read`: claude from `test/fixtures/backends/claude/success.ndjson` (`system/init`, `assistant` text, `result` with `usage` and `total_cost_usd`); opencode from `test/fixtures/backends/opencode/tool-call.ndjson` (`step_start`, `text`, `step_finish` with `part.tokens` `{input, output, reasoning, cache: {read, write}}`); agy from `test/fixtures/backends/agy/success.ndjson` (`init`, `step_update`, `result` with `usage`). `usage` in the scenario maps to the dialect's token fields. If opencode's call has `usage: null`, emit no `step_finish` (S2: this is the real behaviour). `reply` is the final text.
7. `cost_usd` (default `0.0001`) is reported only by claude (`total_cost_usd`). opencode and agy never report cost.
8. Exit codes: 0 on success, 1 for `crash`, `rate_limit` and the claude invalid-session case, 3 for scenario errors.
8a. `--version` (as the only argument) prints and exits 0 without reading the scenario: `2.1.301` for claude (the adapter's `CLAUDE_VERSION_PIN` in `src/backends/adapters/claude.ts`), `opencode 2.0.21` for opencode (the pin in `src/backends/adapters/opencode.ts`), `1.4.0` for agy (the pin in `src/backends/adapters/agy.ts`). The adapters run `--version` in `validateEnvironment`, so the pins must match or the environment check reports a pin mismatch.
9. Conformance tests (`test/conformance/dialects.test.ts`): for each dialect, run the executable with `execFileSync` (or `spawnSync`) in a temp dir, pipe stdout through the real normalizer (`normalizeClaudeStream`, `normalizeOpenCodeStream`, `normalizeAgyStream` in `src/backends/normalize/`), and assert that the emitted `usage` record has `input_tokens > 0` and `output_tokens > 0`, and that the `session.started` event's `session_id` equals the id passed in.

## Invariants
- The engine never writes a file on behalf of the fake. Every edit comes from `applyCall`.
- The counter is the only state the fake keeps. Deleting `<file>.state.json` restarts the scenario.
- Output is UTF-8 text, one JSON object per line on stdout, nothing on stdout for `crash` and `hang`.
- Each `bin/*` file works with no `.ts` loader, because the engine spawns it directly.

## Edge cases
- `calls` empty: the first invocation exits 3 with `no call 0`.
- A resumed session: `--resume` or `-s` or `--conversation` with a new prompt consumes the next call; the test relies on call index 1 being the fix attempt (fail then fix).
- Two invocations in parallel share one counter. Tests must run tasks one at a time (R0.3 sets `concurrency.workers` to 1).
- `edits` with a nested path (`src/a/b.txt`) creates the directories.
- `reply` missing: the final text is `DONE`.

## Guardrails
- Not done if the executables are reachable only from tests. The adapters must be able to spawn them through `backends.<name>.bin`; R0.3 wires that, and R0.2 must leave the `bin` files directly executable.
- No stubs, TODO, FIXME, placeholder bodies, hard-coded returns or mocks of the code under test. A dialect that prints a canned transcript without reading the scenario is not acceptable.
- Do not add a test-only branch to `src/`. The only fake-specific code is under `test/fixtures/fake-harness/`.
- Do not change the legacy `FAKE_SCENARIO` or `--scenario` behaviour of `cli.ts`, `index.ts`, `dialects/opencode.mjs` or `dialects/agy.mjs`, except to add `runDialect` exports.
- Do not write any IP address or port literal into the fixtures or scenarios. Use `http://fake.invalid` if a URL is needed.
- Do not edit `test/conformance/fake-adapter.ts`; `FakeAdapter` keeps using `cli.ts`.

## Out of scope
Any change under `src/`, the E2E driver (R0.3), the legacy scenario tests (R0.5), security (A6), and the governor (A2). Do not build any harness feature beyond what the scenario file describes.

## Notes for the implementer
- VERIFY FIRST: whether the real `claude` rejects a non-UUID `--session-id` with exit 1, by running `claude --session-id not-a-uuid -p hi; echo $?` if `claude` is installed. If it is not installed, implement the rule from Behavior 5 anyway and say so in the test name comment.
- The executables must be ESM. The repository `package.json` sets `"type": "module"`, so extensionless files under `test/fixtures/fake-harness/bin/` are read as ESM.
- `test/fixtures/fake-harness/cli.ts` runs `process.exit` at import time. Do not import it from the new files.
