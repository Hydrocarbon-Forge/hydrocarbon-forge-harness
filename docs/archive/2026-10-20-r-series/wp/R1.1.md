## Objective
Make `substrate` start and make Ctrl-C stop it cleanly. After this WP `node bin/substrate.mjs --help` exits 0, the bundle `dist/substrate.mjs` is the real CLI, and a SIGINT during a running task leaves no child process alive and records `run.paused` with reason `user_cancel`. You change no file under `src/backends/`, `src/roles/`, `src/git/`, `src/verify/` or `src/contracts/`.

## Interface
`src/cli/main.ts` is the bundle entry (`scripts/bundle.mjs` bundles it into `dist/substrate.mjs`). It calls `installSignalHandlers`, then `runCli(process.argv.slice(2), { signal })`, then `process.exit(code)`. Its exit code is `runCli`'s code, except that after a signal it is 130 for SIGINT and 143 for SIGTERM.

`src/cli/signals.ts` exports:
- `installSignalHandlers(opts: { controller: AbortController; write(text: string): void; exit(code: number): void }): () => void` installs SIGINT and SIGTERM handlers and returns a function that removes them.
- `exitCodeForSignal(sig: "SIGINT" | "SIGTERM"): 130 | 143`.

`src/cli/dispatcher.ts`: `runCli(argv, streams?: { stdin?, stdout?, stderr?, signal?: AbortSignal })` passes `signal` into `CommandContext` as `ctx.signal`. `CLI_OPTIONS` gains `help: { type: "boolean", short: "h" }`.

`src/engine/actions/shared.ts` exports `bindAbort(ctx: EffectContext, handle: SessionHandle): () => void`. If `ctx.signal` is already aborted, it calls `handle.kill("cancel")` at once. Otherwise it adds a one-time `abort` listener that calls `handle.kill("cancel")`, and it returns a function that removes the listener.

`package.json`: `"bin": {"substrate": "bin/substrate.mjs"}`, `"files": ["bin", "dist", "assets"]`, `"version": "0.3.0"`, `"description": "Substrate: a deterministic orchestration engine that runs coding-agent harnesses"`, `"prepare": "npm run bundle"`. The `description` must not contain "(scaffold)".

## Behavior
1. `bin/substrate.mjs` computes `dist/substrate.mjs` relative to its own file. If that file is missing it writes `substrate: dist/substrate.mjs is missing; run \`npm run bundle\`` to stderr and exits 1. Otherwise it does `await import(<file URL of dist/substrate.mjs>)`. It contains no other logic (remove the current SIGINT code from it).
2. `scripts/bundle.mjs` uses `src/cli/main.ts` as the default entry point, bundles it to `dist/substrate.mjs` with the existing esbuild options, and then copies `assets/` to `dist/assets/` with `fs.cpSync(..., {recursive: true})`. The shebang rule stays.
3. `src/index.ts` exports `runCli` (re-exported from `./cli/dispatcher.js`) and `version` (the string `"0.3.0"`). It no longer exports `SUBSTRATE_SCAFFOLD`.
4. `installSignalHandlers`: the first SIGINT or SIGTERM writes `substrate: stopping (<SIG>); press Ctrl-C again to force exit` and calls `controller.abort()`. A second signal calls `exit(exitCodeForSignal(sig))` at once. The return value removes both listeners.
5. `main.ts` records the last signal. When `controller.signal.aborted` is true after `runCli` returns, it exits with `exitCodeForSignal(lastSignal)`, otherwise with `runCli`'s code.
6. `dispatcher.ts`: when `flags` contains `help` (`--help` or `-h`), `runCli` prints the help text and returns 0 before any other check, even when stdin is not a TTY.
7. `ctx.signal` is copied into `RunOptions.signal` in `run.ts` and `plan.ts`, and into `resumeOpts.signal` in `resume.ts`, before `engine.run` or `engine.resume` is called.
8. `bindAbort` is called right after every `ctx.adapter.spawn(...)` in `plan.ts`, `task.ts` (worker and heal), `solo.ts` and `replan.ts`. The returned remover is called when the session result is read. An aborted session makes the engine record `run.paused` with `reason: "user_cancel"` (the existing `runEffectsLoop` abort check and the `user_cancel` reason already do this).
9. `engine.ts` releases the run lock and clears its heartbeat interval in a `finally` on every exit path, including abort. It must not leave the lock held after `run` resolves.
10. `test/fixtures/fake-harness/dialects/claude.mjs`: when a call's `failure` is `hang`, first write `String(process.pid)` to `<FAKE_SCENARIO_FILE>.pid`, then hold the process. This lets the test check the child's pid.
11. `test/smoke.test.ts` is deleted (`git rm`). Its assertions are replaced by the E2E tests.
12. `test/e2e/smoke.test.ts`: remove the `it.fails` marker from the test "node dist/substrate.mjs --help exits 0 and prints usage" and keep it as `it`. Leave the other test unchanged.
13. `test/e2e/entry.test.ts` (create) runs three checks, each through `runSubstrate` from R0.3:
    (a) `--help` exits 0 and stdout contains `Usage`.
    (b) SIGINT: a solo run (`run --mode solo "do it"`) with the scenario `{calls: [{failure: "hang"}]}`. Poll `events.jsonl` until a `task.session.started` event appears, read the pid from `<scenario>.pid`, send `SIGINT` to the child, and expect exit code 130 within 30 seconds, a `run.paused` event with `data.reason` `user_cancel`, and `process.kill(pid, 0)` to throw `ESRCH`. Also expect the run lock file to be gone.
    (c) After (b), `resume <run_id>` with scenario `{calls: [{failure: "hang"}, {edits: {"src/a.txt": "two\n"}, reply: "DONE"}]}` exits 0 and the final `run.finished` event has `exit_code` 0.

## Invariants
- Exit 130 after SIGINT and 143 after SIGTERM, always (not 0 or 1).
- A signal never leaves the lock held. A second signal exits immediately.
- `bin/substrate.mjs` never imports `src/` files.

## Edge cases
- A signal before `run.created` is written: the handler still exits with the signal code; no run directory is required.
- A signal while no session is running (for example during routing): the abort check in `runEffectsLoop` pauses the run at the next loop step.
- A second signal may leave a detached child running, because the handler exits without waiting. Record this as a known limit in Notes; the first signal is the supported path.
- `dist/substrate.mjs` missing: exit 1 with the message from Behavior 1.

## Guardrails
- Not done if the signal path is reachable only from tests. The real `dist/substrate.mjs` must handle SIGINT, exercised by test (b).
- No stubs, TODO, FIXME, placeholder bodies or hard-coded exit codes other than the rules above. No `process.env.VITEST` or other test checks in `src/`.
- Do not change the adapter's kill logic in `src/backends/process.ts`. Use `handle.kill("cancel")` only.
- Do not write an IP address or port anywhere.
- The writes to `run.ts`, `plan.ts` and `resume.ts` are only the signal pass-through in Behavior 7. Do not change any other behaviour in those files; the plan's R1.3 and R1.5 change them later.
