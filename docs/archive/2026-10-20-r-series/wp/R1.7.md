## Objective
Make prompts come from `assets/`, rendered by code, and make the code contain no prompt text. The five prompt builders in `src/roles/prompts/` keep their exported signatures and call a loader instead of holding inline text. After this WP every template under `assets/prompts/` is rendered by a test, and `substrate agents` lists the built-in agents. You change no file under `assets/`.

## Interface
`src/prompts/render.ts` exports `render(template: string, vars: Record<string, string>): string`.
`src/prompts/index.ts` exports:
- `loadAgentBody(role: "planner" | "worker" | "test-writer" | "reviewer" | "governor", opts?: PromptRoots): string`: the body of `agents/<role>.md` with its YAML frontmatter removed, trimmed.
- `loadTemplate(relPath: string, opts?: PromptRoots): string`: the text of `prompts/<relPath>`, for example `planner/request.md`.
- `assembleSystem(role: "planner" | "worker" | "test-writer" | "reviewer", opts: PromptRoots & { taskClass?: string }): string`: the parts from the table in Behavior 3, joined by a blank line.
- `listAgents(opts?: PromptRoots): Array<{ role: string; source: "project" | "user" | "built-in"; path: string }>`.
- `builtinRoot(): string`: the built-in assets directory (Behavior 2).
`PromptRoots = { projectRoot?: string; userConfigDir?: string }`.

`src/roles/prompts/*.ts`: each exported `build...Prompt` keeps its signature and returns `{system, user}`; `system` comes from `assembleSystem`, and `user` from `render(loadTemplate(...), vars)`.

## Behavior
1. `render(template, vars)`: replace each `{{name}}` with `vars[name]`. A `vars` value of `""` (or whitespace only) becomes `(none)`. If the template uses a name that is not a key of `vars`, throw `missing template variable: <name>`. After substitution, if `{{` remains anywhere, throw `unrendered placeholder in template`. The syntax is `{{name}}` only; no conditionals or loops.
2. Built-in root: `builtinRoot()` returns the first existing directory among `<here>/assets`, `<here>/../assets`, `<here>/../../assets`, where `<here>` is the directory of this module (`import.meta.url`). A directory counts when it contains `agents/`. Never use `process.cwd()`. If none exists, throw `built-in prompt assets not found`.
3. Assembly per role (from `assets/prompts/README.md`):
   - planner: `agents/planner.md` body, then `prompts/planner/format.md`.
   - worker: `agents/worker.md` body, then `prompts/worker/class/<taskClass>.md` if `taskClass` is given and the file exists.
   - test-writer: `agents/worker.md` body, then `agents/test-writer.md` body, then `prompts/worker/class/tests.md`.
   - reviewer: `agents/reviewer.md` body.
4. Override order, first match wins: (a) `<projectRoot>/.substrate/prompts/<relPath>` and `<projectRoot>/.substrate/agents/<role>.md`; (b) `<userConfigDir>/prompts/<relPath>` and `<userConfigDir>/agents/<role>.md`; (c) the built-in files. `userConfigDir` defaults to `SUBSTRATE_CONFIG_DIR` or `~/.config/substrate`; `projectRoot` defaults to `process.cwd()`.
5. Builders (`src/roles/prompts/`):
   - `buildWorkerPrompt(specAbsPath)`: `user` is `render(loadTemplate("worker/task.md"), {spec_path: specAbsPath})`. The existing check that the path is absolute stays.
   - `buildTestWriterPrompt(opts)`: `user` renders `test-writer/task.md`; `system` is the test-writer assembly.
   - `buildPlannerPrompt(opts)`: `system` is the planner assembly. `user` renders `planner/request.md` with `request`, `repo_map` (from `opts.repoMap`), `instruction_files` and `skills` (formatted as one `- ` line each), and the other variables from the README table (`run_id`, `base_ref`, `repo_root`, `classes`, `task_budget`, `run_budget`, `max_tasks`, `charter`, `history`) passed as `""`, which renders as `(none)`.
   - `buildReplanPrompt`, `buildReviewerPrompt`: same pattern; variables from the README table, `""` for any the caller does not have.
   Delete every inline prompt string in these five files, including the `"You are the Substrate ..."` literals.
6. `substrate agents` (`src/cli/commands/agents.ts`) prints one line per agent from `listAgents`: `<role> <source> <path>`. It lists the five built-in agents (planner, worker, test-writer, reviewer, governor) even when no project overrides exist.

## Invariants
- No `.ts` file under `src/` contains a string literal starting with `You are the Substrate`, except `src/roles/governor.ts`, whose debt is tagged `DEFERRED` (removed only by the optional R5.4) and which stays untouched.
- Rendering is pure: the same inputs give the same output and no file is written.
- Every template under `assets/prompts/` renders with the variable names listed in the README table.

## Edge cases
- A template variable present in the table but missing in `vars`: `missing template variable: <name>`.
- An override file that contains a `{{unknown}}` placeholder: render fails with the missing-variable message.
- A `taskClass` with no addendum file (for example `search` if absent): the worker system is the agent body alone, with no error.
- Windows line endings in an asset: normalised to `\n` before rendering.

## Guardrails
- Not done if the builders still hold prompt text. Check with `grep -n "You are" src/roles/prompts/*.ts`, which must print nothing.
- No stubs, TODO, FIXME, placeholder bodies, or a render that returns its input unchanged.
- Do not change any file under `assets/`. If a template is missing a variable the builder needs, pass the variable from the builder and note it in Notes.
- Do not change the protocol lines in the assets (`PLAN READY`, `DONE`, `VERDICT:` and the rest).
- Do not write an IP address or port in any file.

## Out of scope
The planner's real output protocol and the replan calls (R3.1, R3.5), the worker's class selection (R3.3), `init` (R2.10), and `governor.ts` prompt text (`DEFERRED` with the governor).
