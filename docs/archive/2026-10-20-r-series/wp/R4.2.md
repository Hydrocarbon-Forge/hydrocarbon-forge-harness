## Objective
When the planner needs a human, the run pauses with its questions on the caller's interface. The caller answers with a file, and the same planner session continues. The protocol works in text, JSON and stream-json output.

## Interface
- `src/cli/questions.ts` exports:
  - `parseQuestions(markdown: string): Question[]` where `Question = {id: string; text: string; default?: string}`. Numbered items (`^\s*\d+[.)]\s+`) are questions, with ids `Q1`, `Q2` in order. A `Default:` marker inside an item (case-insensitive) sets `default`, and the text before it is `text`.
  - `formatAnswers(questions, answers): string` builds the text for `answers.md`.
- Pause data: `run.paused {reason: "needs_human", questions_path, session_id, questions}`.
- `RunSummary` (src/contracts/index.ts) gains optional `questions?: Question[]`. `src/cli/output.ts` `result` object gains `subtype: "needs_input"`, `run_id` and `questions` when a run pauses with needs_human and `questions` is set.
- `substrate resume <run> --answers <file|->` reads `{"answers":[{"id","text"}]}`. Unknown ids are rejected.
- Template: `assets/prompts/planner/answers.md` with variable `answers`. The row is added to the variables table in `assets/prompts/README.md`.

## Behavior
1. `NEEDS INPUT` with `QUESTIONS.md` (R3.1) pauses the run. `parseQuestions` builds the list. An empty list still pauses, with `questions: []`.
2. Exit code is 3. The result (`--output-format json`, and the final `result` event in `stream-json`) carries `{subtype: "needs_input", run_id, questions: [{id, text, default}]}`. Text mode prints each question with its default and the command `substrate resume <run> --answers <file>`.
3. `resume <run> --answers <file|->` is valid only when the run is paused with `needs_human` and has `questions_path`. Otherwise: `Error: run <id> has no pending questions`, exit 2.
4. Answers: each `id` must match a question (unknown id: `Error: unknown question id <id>`, exit 2). A question with no answer uses its `default`. A question with neither answer nor default: `Error: question <id> has no default; pass --answers`, exit 2.
5. `resume` appends `run.resumed {answers}` (answers as `{id, text}` with defaults filled in), then the plan action re-enters `PLANNING`.
6. The plan action (`plan.ts`) on re-entry with answers: spawns the planner with `session: {resume: session_id}` and prompt `render(loadTemplate("planner/answers.md"), {answers: formatAnswers(...)})`. The normal R3.1 finish-line and validation rules then apply.
7. `resume` with no `--answers` on a needs_human pause uses every default. It is exit 2 if any question lacks one (rule 4).
8. `status <run>` lists pending questions (with defaults) when the run is paused with `needs_human` and `QUESTIONS.md` exists and no `run.resumed` with answers follows the pause.

## Invariants
- The planner session is resumed, never restarted, when answering.
- Answers are recorded in the event log before the planner is spawned.
- The answers file is never written by the engine except as the content of the `run.resumed` event.

## Edge cases
- `QUESTIONS.md` with no numbered items: pause with `questions: []`; the caller resumes with an empty answers list (valid only if the list is empty).
- Answer text containing `Default:`: stored verbatim.
- Second pause after answers (planner asks again): a new pause with a new `QUESTIONS.md`; the old questions are not reused.

## Guardrails
- No security hardening beyond the plan (DECISIONS A6): no new sandbox, environment scrubbing or permission-file checks.
- Never write a raw IP address or port in code, specs, docs or fixtures.
- Not done if the protocol is reachable only from tests. The E2E must run `run`, then `resume --answers`, through the built CLI.
- The answer prompt text lives only in `assets/prompts/planner/answers.md`.
- No test-only branches in `src/`. No stub questions.

## Out of scope
Interactive prompts (there is no TUI). Structured answers beyond `{id, text}`. Governor clarifying turns (retired).
