## Objective
Make the model flags work and make overrides merge instead of clobbering. Today `--model` and `--worker-model` write `roles.worker`, which the strict settings schema rejects, so they exit 2 (C-H18). Overrides are a shallow spread that drops nested keys (C-M13). After this WP the settings schema has a worker route, overrides deep-merge, the sandbox is off by default and an enabled sandbox without `bwrap` is an error, and `--timeout` takes seconds. You change no file under `src/roles/`, `src/git/`, `src/verify/` or `src/backends/`.

## Interface
`src/contracts/index.ts` `Settings`:
- `roles.worker: Route` (optional in the type; the default in `DEFAULT_SETTINGS` is set, see Behavior 2).
- `routing.escalation` stays a list of strings (model ids); change nothing else in `routing`.
- `sandbox.enabled` default is `false` in `DEFAULT_SETTINGS`.

`src/util/merge.ts` exports `deepMerge<T>(base: T, overlay: unknown): T`. Plain objects merge recursively; arrays and primitives in `overlay` replace the base value; `undefined` in `overlay` is ignored; `null` replaces.

`src/config/index.ts` exports `sandboxProblem(settings: Settings, which?: (bin: string) => boolean): string | null`. It returns `"sandbox.enabled is true but bwrap is not installed; install bubblewrap or set sandbox.enabled to false"` when the sandbox is enabled and `which("bwrap")` is false. The default `which` runs `execFileSync("bwrap", ["--version"], {stdio: "ignore"})` in a try block.

`src/cli/commands/run.ts` `buildSettingsOverrides(flags, mode)` is the single place that turns flags into overrides. `plan.ts` and `resume.ts` use the same function (move it to `run.ts` and import it, or copy the same rules; do not keep two rule sets).

## Behavior
1. Override rules (all in `buildSettingsOverrides`):
   - `--model X`: in plan mode sets `roles.planner.model = X`; in solo mode sets `roles.worker.model = X`; in auto mode sets `roles.planner.model = X` only.
   - `--worker-model Y`: sets `roles.worker.model = Y`.
   - `--effort E`: sets `roles.planner.effort = E` (unchanged).
   - `--timeout S`: S is seconds; sets `budgets.run.max_wall_min = S / 60` (fractional minutes allowed). Put a code comment above that line in `buildSettingsOverrides` stating that the flag is in seconds and the setting is in minutes.
   - `--max-budget-usd N`: sets only `budgets.run.max_usd = N`.
   - `--sandbox` sets `sandbox.enabled = true`. There is no flag to disable it.
   A partial route such as `{model: X}` is merged over the base route by `deepMerge`, so `backend` comes from the base.
2. `DEFAULT_SETTINGS.roles.worker = { backend: "claude", model: "claude-sonnet-5-5", effort: "medium" }`. `DEFAULT_SETTINGS.sandbox.enabled = false`. The strict `Settings` schema accepts `roles.worker`.
3. `engine.ts`: the settings are built with `deepMerge(DEFAULT_SETTINGS, this.options.settings)` and then `deepMerge(..., opts.overrides)`. The shallow spread is removed.
4. `solo.ts`: the worker model is `ctx.settings.roles.worker.model`. Remove the `?? "claude-haiku-5-5"` fallback and the `as any` cast.
5. `run.ts`, `plan.ts`, `resume.ts`: after loading settings, call `sandboxProblem(settings)`. If it returns a message, write `Error: <message>` to stderr and return 2.
6. `loader.test.ts` gains tests: `--model` and `--worker-model` settings validate (no exit 2); `sandbox.enabled` defaults to false; an enabled sandbox with `which` returning false gives the message from Behavior 1.

## Invariants
- A flag never makes settings validation fail. `loadSettings` output always passes `Settings.parse`.
- An override only changes the keys it names. Other keys of the same object (for example `budgets.task`) keep their values.
- `deepMerge` never mutates its arguments.

## Edge cases
- `--model` in plan mode does not change `roles.worker`.
- `--worker-model` with `--model` in solo mode: `--worker-model` wins for `roles.worker.model`.
- `--timeout 90` gives `max_wall_min` 1.5.
- A project settings file that sets `budgets.task.max_usd` and a flag that sets `budgets.run.max_usd`: both survive.
- `deepMerge` with an array in both: the overlay array replaces the base array (`permissions.allow`).

## Guardrails
- Not done if a flag is parsed but has no effect on the settings the engine reads. Check with the dispatcher-level test in Done when, which asserts the setting value reaches `loadSettings`.
- No stubs, TODO, FIXME, placeholder bodies or hard-coded values. No `as any` added.
- Do not fix `--effort` or `--max-budget-usd` beyond Behavior 1.
- Do not write an IP address or port in any file.
- Do not add a dependency.
