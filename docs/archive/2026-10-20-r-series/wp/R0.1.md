## Objective
Build the static checks that make fake or unused code fail the build, plus a tagged "debt allowlist" so the build stays green while the existing problems are paid down one work package at a time. After this WP, `npm run check` exists, passes today, and fails whenever someone adds a new violation or forgets to remove debt belonging to a finished work package. You change no file under `src/`.

## Interface
Every script is a Node ES module (`.mjs`) run as `node scripts/<name>.mjs [options]`. Common options: `--root <dir>` (project root to scan; default: the repo root, found by walking up to the directory containing `package.json`) and `--allowlist <file>` (default `<root>/scripts/debt-allowlist.json`). Exit code 0 = clean, 1 = violations (print them), 2 = usage or internal error. Each violation prints as `RULE path:line message` on stdout; the last line is `FAIL: <n> violation(s)` or `OK`.

Files you create:
- `scripts/lib/scan.mjs` exports `listFiles(root, relDir, extensions)`, `readLines(file)`, `resolveRelativeImport(fromFile, specifier, root)` (maps `./x.js` to `./x.ts`, or `./x/index.ts`; returns `null` for non-relative specifiers), `importSpecifiers(text)` (static `import ... from "x"`, `import "x"`, `export ... from "x"`, `import("x")`, and dynamic imports written with backticks and no interpolation such as ``import(`./x.js`)`` (the dispatcher loads every command module this way, so missing this form would report all commands as unreachable); returns `{specifier, line}[]`).
- `scripts/lib/allowlist.mjs` exports `loadAllowlist(file)`, `workPackageStatus(progressFile)` (parses `docs/plan/PROGRESS.md` rows: split a line starting with `|` on `|`, cell 0 is the id, cell 4 is the status), and `applyAllowlist(kind, violations, allowlist, status)` which returns `{remaining, problems}`.
- `scripts/debt-allowlist.json`: `{"purity":[{"rule","path","until"}], "wired":[{"path","until"}], "events":[{"type","kind","until"}], "settings":[{"key","until"}]}`. `until` is a work package id such as `R3.3`, or the literal `DEFERRED`.
- `scripts/check-all.mjs` runs the four checks and `scripts/check-boundaries.mjs` and `scripts/docs-check.mjs` in sequence, prints each name and result, and exits non-zero if any failed.
- `package.json` scripts: `check:purity`, `check:wired`, `check:events`, `check:settings`, `check` (runs `node scripts/check-all.mjs`).

Allowlist rules (implemented once in `allowlist.mjs`, used by all four checks):
1. A violation that matches an allowlist entry is suppressed.
2. An allowlist entry that matches no violation is a **stale entry** and fails the check ("remove it").
3. If an entry's `until` work package has Status `DONE` in `docs/plan/PROGRESS.md`, the entry fails the check ("debt of finished WP still present"). `DEFERRED` entries are exempt.
4. `until` must match `^R\d+\.\d+$` or equal `DEFERRED`; anything else is an error.

## Behavior
1. **check-purity** scans `src/**/*.ts` (not `*.d.ts`). Rules, each with an id used in the allowlist `rule` field:
   - `P1`: a relative import whose resolved path is under `test/` (or whose specifier contains `/test/`).
   - `P2`: `console.`, `process.stdout.write` or `process.stderr.write` used in any file under `src/engine`, `src/backends`, `src/roles`, `src/git`, `src/verify`, `src/spec`, `src/store`, `src/ledger`, `src/prompts`, `src/util`, `src/archive`, `src/charter`. Files under `src/cli` are exempt, and so is `src/util/log.ts`.
   - `P3`: stack sniffing: `new Error().stack`, `.stack?.includes`, `.stack.includes`.
   - `P4`: test sniffing: `process.env.VITEST`, `process.env.JEST`, `process.env.NODE_ENV === "test"`, `import.meta.vitest`.
   - `P5`: the magic strings `"First attempt done"`, `"Attempt 1"`, `"Attempt 2"`, `"L2 contract amendment"`.
   - `P6`: a string literal that starts with `You are the Substrate` (prompt text must live in `assets/`).
   - `P7`: fabricated edits: the text `export const val_${` or `// modified ${`.
   - `P8`: the identifiers `FakeAdapter` or `FAKE_SCENARIO` anywhere in `src/`.
   - `P9`: an IPv4 address literal (for example `127.0.0.1`) in any file under `src/` or `assets/`.
   Ignore matches inside `//` line comments. Violation path is repo-relative with forward slashes.
2. **check-wired** (module level only; a later WP adds symbol-level analysis). Entry files: `src/cli/dispatcher.ts` and `src/index.ts` (option `--entries a,b`). Build the import graph from every `src/**/*.ts` using `importSpecifiers` and `resolveRelativeImport`, walk it from the entries, and report each `src/**/*.ts` file that is not reachable. Allowlist entry `path` may be an exact path or a directory ending in `/**`.
3. **check-events** needs an event vocabulary. Use the file `src/contracts/events.ts` if it exists (all string literals matching `^[a-z]+(\.[a-z]+)+$` in it), otherwise parse SUBSTRATE-PLAN.md Appendix D (the line after `## Appendix D`, backticked names) and add `plan.ready`, `integration.failed`, `tasks.invalidated`, `task.verify.started`. *Emitted* = the first string-literal argument of every call `emit(` in `src/engine/**`. *Consumed* = string literals compared to a `type` property or used in a `case` label inside `src/engine/reducer.ts` and `src/cli/**`: patterns `type === "x"`, `type == "x"`, `case "x":`. Violations: `consumed-not-emitted` (a type read but never emitted, like `task.verified`) and `emitted-not-consumed` (emitted, never read, and not in the allowlist file's `"events_observe_only"` array, which you create as an empty array). Allowlist entries match on `{type, kind}`.
4. **check-settings** finds settings keys nobody reads. Bundle `src/contracts/index.ts` with esbuild (`build({entryPoints, bundle: true, format: "esm", platform: "node", outfile: <temp dir>/contracts.mjs, external: ["zod", "yaml"]})`), import it, take the exported `Settings` zod object and walk it: unwrap optional/default/nullable/effects, descend into objects, treat records as the segment `*`, and for unions descend into every object option. Produce dotted leaf paths such as `git.auto_merge`. A leaf is *read* if some file under `src/` (excluding `src/contracts/**`, `src/config/**`, and `src/cli/commands/config.ts`) contains `<parent>.<leaf>` or `<parent>?.<leaf>` or `["<leaf>"]`, where `<parent>` is the previous path segment (for a top-level key use the key itself with `.`/`?.` access). Report unread leaves. Keys whose last segment is `*` are skipped. Allowlist entries match on `key`.
5. **Initial allowlist.** Run each script with `--init-allowlist` to write all current violations into `scripts/debt-allowlist.json` (merge, do not duplicate). Assign `until` with this table, which applies only to violations that actually exist (a row that matches nothing is ignored); use `R5.3` for anything not listed and print a warning for each such entry:
   - purity: `P1` in `src/engine/engine.ts` and `src/cli/commands/backends.ts` → `R2.2`; `P2` in `src/engine/**` → `R0.5`, in `src/backends/adapters/claude.ts` and `src/backends/adapters/agy.ts` → `R2.3` and `R2.5` respectively, in `src/backends/normalize/opencode.ts` and `src/backends/adapters/opencode.ts` → `R2.4`; `P9` in `src/backends/adapters/opencode.ts` → `R2.4`; `P6` in `src/roles/governor.ts` → `DEFERRED` (the governor stays until the optional R5.4); `P3` in `src/spec/parser.ts` → `R0.5`; `P5` in `src/engine/effects.ts` → `R0.5`; `P6` in `src/roles/prompts/*.ts` → `R1.7`; `P7` in `src/engine/effects.ts` → `R0.5`; `P8` in `src/engine/engine.ts`, `src/cli/commands/backends.ts` → `R2.2`, in `src/backends/adapters/agy.ts` → `R2.5`.
   - wired: `src/tui/**` → `R0.7`; `src/cli/bench.ts`, `src/cli/agents-import.ts` → `R1.8`; `src/store/event-store.ts` → `R3.2`; `src/ledger/index.ts` → `R1.4`; `src/engine/scheduler.ts` → `R3.2`; `src/engine/replan.ts` → `R3.5`; `src/roles/worker.ts` → `R3.3`; `src/roles/planner.ts` → `R3.1`.
   - events: `consumed-not-emitted` for `task.started`, `task.verified`, `usage`, `system.init` → `R1.2`; `emitted-not-consumed` entries → `R1.2`.
   - settings: `git.auto_merge`, `git.branch_prefix`, `execution.strategy`, `instructions.workers`, `sandbox.network`, `budgets.task.max_turns`, `budgets.run.max_tokens` → `R1.6`; `backends.*.max_concurrency`, `backends.*.version_pin`, `backends.*.bin`, `backends.*.extra` → `R2.2`; `roles.governor.*` → `DEFERRED`.
6. **Tests.** Under `test/fixtures/check/` create tiny trees (each with a `src/` folder, a `tsconfig`-free layout, and an allowlist file) that contain seeded violations, and a clean tree. Each test runs the script with `--root <fixture>` through `child_process.execFileSync` (catch the non-zero exit) and asserts: exit 1 and the expected `RULE` lines for the bad tree; exit 0 for the clean tree; stale-entry failure; failure when an entry's WP is DONE in a fixture `PROGRESS.md` (the script takes `--progress <file>`, default `<root>/docs/plan/PROGRESS.md`).

## Invariants
- No file under `src/` or `assets/` changes in this WP. `npm test`, `npm run typecheck` and `npm run check:boundaries` stay green.
- The checks read files only; they never write except `--init-allowlist` (which writes only the allowlist file).
- Output is deterministic (sort violations by path then line).

## Edge cases
- A file with no imports, or a circular import, must not crash the graph walk.
- Imports with `.js` extensions that map to `.ts` files, directory imports, `import type`, and backtick dynamic imports without interpolation must all resolve. A dynamic import with `${...}` inside cannot be resolved: ignore it and print a warning listing the file.
- `console` inside a string or a comment must not trigger `P2` (strip `//` comments and ignore matches inside quotes with a simple tokenizer or regex that handles the common cases; document the limit in a comment).
- `PROGRESS.md` missing: treat all statuses as TODO and print a warning, do not fail.
- Windows path separators: normalise to `/`.

## Guardrails
- Do not "fix" any violation the scripts find; record it in the allowlist with its `until` tag. Fixing them is other work packages' job.
- Do not weaken a rule to make the allowlist smaller. If a rule produces a false positive on current code, add an allowlist entry with `until: "R5.3"` and a one-line comment in the test explaining it.
- No new runtime dependencies. `esbuild` and `typescript` are already devDependencies.
- Do not leave `TODO`, `FIXME` or placeholder bodies in the scripts; each rule above must work.

## Out of scope
Symbol-level dead-code analysis (that is R0.6). Changing any `src/` file. Wiring `npm run check` into git hooks or CI.

## Done when
1. `npm run check` exits 0 and prints each of the six sub-checks as OK.
2. `npx vitest run test/unit/scripts` passes.
3. Temporarily adding `console.log("x")` to `src/engine/engine.ts` makes `npm run check:purity` exit 1 (verify by hand, then revert).
4. Proof to paste into `docs/plan/PROGRESS.md` Notes: the output of `npm run check` and the number of allowlist entries per kind.
5. Mark R0.1 DONE in `docs/plan/PROGRESS.md`, commit as `R0.1: tripwire scripts and npm run check`.
