## Objective
Make OpenCode spawns work, keep the temporary agent file out of scope checks, and recover usage when the stream has no `step_finish`. Four defects are fixed: the agent file body is the prompt instead of the system text (C-H11), the agent file can trip scope checks (C-M3), the deny action is `subagents` instead of `subagent` (C-H12), and a missing `step_finish` loses all usage. After this WP OpenCode runs pass the scope check with the agent file present, and usage is recovered from `opencode session export`. You change no file under `src/roles/`, `src/engine/` or `src/contracts/`.

## Interface
`src/backends/adapters/opencode.ts`:
- `generateOpenCodeRunConfigSync(req, options)` keeps its name. It writes the agent file to `<req.cwd>/.opencode/agents/<agentName>.md`. Its body is `req.system_append ?? ""` (not `req.prompt`). Its frontmatter is `mode: primary`, `steps: <n>`, and `permissions` (list of `{action, resource, effect}`), as today.
- `OpenCodeAdapterOptions` gains `exportSession?: (sessionId: string, cwd: string) => Promise<{input: number; output: number; cacheRead: number; cacheWrite: number; reasoning: number} | null>`, used when a stream has no `step_finish`. The default runs `opencode session export <id> --standalone` with `execFile` in `cwd` and parses the token totals from its JSON output (Notes gives the parse rule).
- The deny action for `subagent` is `subagent` (singular), mapped through `TOOL_MAP`; every deny entry goes through `TOOL_MAP` (unknown names are lowercased, as now).

`src/backends/normalize/opencode.ts`: `normalizeOpenCodeStream(rawStream, options)` keeps its signature. `OpenCodeNormalizeOptions` gains `usageFallback?: (sessionId: string) => Promise<UsageTotals | null>` (the adapter passes its `exportSession` wrapper).

`src/git/scope.ts`: the ignore list in the changed-file filter also skips paths starting with `.opencode/`. `src/git/workspace.ts`: the worktree exclude file gains the line `.opencode/`, added the same way as `.substrate-task/`.

## Behavior
1. Agent file: written before the spawn, to `<req.cwd>/.opencode/agents/<agentName>.md`, and deleted in the cleanup after the run (already implemented; keep it). The spawn argv keeps `--agent <agentName>` and the positional prompt `req.prompt` (the prompt is passed once, as the positional argument).
2. Scope: `.opencode/` is excluded from the changed-file list in `scope.ts` (same as `.substrate/`). `workspace.ts` adds `.opencode/` to the worktree's exclude file when the worktree is created.
3. Permissions: the deny list maps through `TOOL_MAP`; `subagent` is used, never `subagents`. Test: a deny of `Agent` yields a `permissions` entry with `action: "subagent"`, `effect: "deny"`.
4. Model name: the usage record's `model` is `provider/model` with any `#variant` suffix removed. Use the part before `#` of `-m`.
5. Missing `step_finish`: when the stream ends after a `text` step with no `step_finish` event, call `usageFallback(sessionId)`. If it returns totals, emit one `usage` event (`cumulative: false`) with them and `cost_source` from the price table (`computed`, or `unknown` when unpriced). If it returns null or throws, emit one `usage` event with zero tokens and `cost_source: "unknown"`, and an `error` event with `kind: "protocol"` and message `opencode usage unavailable for session <id>`. Never silently zero.
6. Warning: the `process.stdout.write("Warning: missing step_finish ...")` line in `normalize/opencode.ts` is replaced by `log.warn` from `src/util/log.ts`. Nothing is written to stdout by the normalizer.
7. `system_append` is the agent file body (Behavior described in the Interface). The engine's spawn sites already set it (R2.3, step 7).
8. Local base URL: the literal `http://127.0.0.1:8080/v1` in `generateOpenCodeRunConfigSync` is removed. The base URL comes from `options.customBaseUrl`. When a local provider is needed and `customBaseUrl` is absent, the adapter returns an error from `spawn`'s event stream (`kind: "protocol"`, message `local provider needs backends.opencode.extra.base_url`). No IP address or port literal remains in `src/backends/adapters/opencode.ts`.

## Invariants
- The agent file never appears in the scope check of a worker's changed files.
- Every usage step produces exactly one `usage` event, and a run with no `step_finish` never reports a silent 0 as `computed`.
- `opencode` is always spawned with `--standalone`.

## Edge cases
- Two agents with the same name in one worktree: the name is random per run (`agent_` plus 8 base-36 characters), so this does not happen across runs; within a run, one file.
- `-s <session>` resume: `--fork` only when `req.session.fork` is true.
- `session export` not installed: Behavior 5 (`unknown`).
- A `permission_denied`-style text refusal (S2): no event; the model text is the result.

## Guardrails
- Not done if the agent file is excluded by a test-only check. The exclusion is the real prefix rule in `scope.ts`, which production runs use.
- No stubs, TODO, FIXME, placeholder bodies, hard-coded token counts, or `as any` to skip a type error.
- No `process.env` check in `src/`.
- Do not change the `--format json`, `--standalone` or `-m` flags.
- Do not write an IP address or port in any file, including comments.

## Out of scope
The local-model route itself (R4.3), `listModels` (R2.6), the `models` command (R2.7), and the cost table (R2.1, already done).
