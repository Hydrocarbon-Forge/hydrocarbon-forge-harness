## Objective
Define every engine event once, in `src/contracts/events.ts`, as a zod discriminated union on `type` with exact `data` shapes. All engine code emits through a typed `emit` that rejects unknown types and malformed data, and the reducer and CLI read only these names. After this WP `npm run check:events` passes with no `R1.2` entries, and the CLI no longer reads `task.started`, `task.verified` or `usage`. You change no file under `src/roles/`, `src/git/`, `src/backends/` or `src/ledger/`.

## Interface
`src/contracts/events.ts` exports:
- `EngineEventV1`: a zod discriminated union on `type`. Each member is `z.object({ v: z.literal(1), seq: z.number().int(), ts: z.string(), run_id: RunId, type: z.literal("<name>"), data: <strict shape> }).strict()`.
- `EventType`: the union of the `type` literals.
- `EVENT_TYPES`: a readonly array of every type name.
- `parseEngineEvent(value: unknown): EngineEventV1` (throws a zod error with the type name in the message).

`src/engine/emit.ts` exports `makeEmitter` (moved here from `actions/shared.ts`, which re-exports it) and `typedEmit`, where `emit<T extends EventType>(type: T, data: EventData<T>): EngineEvent` validates `data` with `parseEngineEvent` before pushing. `EventData<T>` is the `data` type of member `T`.

## Behavior
1. Catalog (every member is `.strict()`). Names from SUBSTRATE-PLAN Appendix D, plus the four from DECISIONS (`plan.ready`, `integration.failed`, `tasks.invalidated`, `task.verify.started`), plus the events the engine already emits that are not in Appendix D (`bisect.started`, `bisect.culprit`, `merge.conflict`, `rate_limit.backoff`, `task.replanned`, `governor.fallback`). Data shapes, with `?` for optional:
   - `run.created` `{}`; `run.routed` `{mode: "solo"|"plan"}`; `run.paused` `{reason: PauseReason}`; `run.resumed` `{}`; `run.finished` `{exit_code: number, status?: string, reason?: string}`; `run.budget.warning` `{cost_usd, max_usd}`; `run.budget.exceeded` `{cost_usd?, max_usd?}`.
   - `plan.started` `{}`; `plan.produced` `{}` (check the emit sites); `plan.lint` `{errors?: number, diagnostics?: unknown[]}`; `plan.approved` `{}`; `plan.rejected` `{}`; `plan.ready` `{}`; `contracts.committed` `{}`.
   - `setup.done` `{}`; `batch.started` `{batch?: string[]}`; `batch.merged` `{batch: string[], checkpoint_ref: string}`.
   - `task.ready` `{task_id}`; `task.worktree.created` `{task_id, path?}`; `task.session.started` `{task_id, generation, attempt, session_id}`; `task.session.ended` `{task_id, generation?, attempt?}`; `task.scope.checked` `{task_id, generation, attempt, ok, violations?}`; `task.verify.started` `{task_id, generation, attempt}`; `task.verify.finished` `{task_id, generation, attempt, passed}`; `task.healing` `{task_id, generation, attempt, session_id?}`; `task.passed` `{task_id, generation?, attempt?}`; `task.merged` `{task_id}`; `task.blocked` `{task_id}`; `task.failed` `{task_id?, failure_class: FailureClass}`; `task.replanned` `{task_id, generation}`; `tasks.invalidated` `{task_ids: string[]}`.
   - `replan.started` `{task_id?}`; `replan.finished` `{task_id, generation}`.
   - `integration.started` `{}`; `integration.finished` `{passed: boolean}`; `integration.failed` `{base?: boolean}`; `bisect.started` `{}`; `bisect.culprit` `{culprit_task_id}`; `merge.conflict` `{task_id, conflict_files: string[]}`.
   - `usage.recorded` `{record: UsageRecord, role, task_id?, generation?, attempt?, class?}` where `role` is `RoleName`.
   - `rate_limit.backoff` `{task_id, concurrency}`; `governor.fallback` `{reason}`.
   Before writing the members, read every `emit(` site in `src/engine` and make the member match it. A field the site passes must be in the member; a required field the site omits must be made optional or the site fixed in this WP.
2. Every emit site uses `typedEmit` from `src/engine/emit.ts`. `grep -rn 'emit("' src/engine` shows only calls whose names are catalog members.
3. `usage.recorded` is emitted at the five sites (planner, worker and solo) with `task_id`, `generation`, `attempt`, `class` and `role`. `batch.merged` carries `checkpoint_ref`: the commit SHA of the run branch after the batch merged (`git rev-parse` in the repo root), or the base SHA for the empty batch.
4. The `scope.checked` emit in `actions/task.ts` is renamed to `task.scope.checked`, and any consumer of the old name is updated (its shape is identical).
5. Reducer (`reducer.ts`): add cases for `integration.failed` (records failure and clears integrating state), `tasks.invalidated` (sets each listed task back to `READY`), pause reasons (`run.paused` stores `reason` in state), and `batch.merged` (appends `checkpoint_ref` to `checkpoints`). Events that do not change state are listed in step 6 and get no case.
6. Emitted but not consumed: add these types to `events_observe_only` in `scripts/debt-allowlist.json` (the array is created by R0.1): `plan.started`, `batch.started`, `contracts.committed`, `task.worktree.created`, `task.session.ended`, `replan.started`, `integration.started`, `bisect.started`, `merge.conflict`, `governor.fallback`, `rate_limit.backoff`, `run.budget.warning`, `run.budget.exceeded`, `run.resumed`, `task.replanned`, `plan.ready`. Any other emitted type gets a reducer case.
7. Consumed but not emitted: in `src/cli/output.ts` and `src/cli/commands/tasks.ts`, `task.started` becomes `task.session.started` and `task.verified` becomes `task.verify.finished` with `data.passed`. In `src/cli/commands/cost.ts`, `usage` becomes `usage.recorded` and the record is `ev.data.record`. These are minimal renames; R1.3 rewrites those files.
8. `appendRunEvent` in `effects.ts` calls `parseEngineEvent` before writing. An invalid event throws with the type name, and nothing is appended.
9. Allowlist: delete every `events` entry in `scripts/debt-allowlist.json` whose `until` is `R1.2`.

## Invariants
- Event `seq` values are unchanged; only data shapes and names change.
- `EngineEvent` in `src/contracts/index.ts` (the outer envelope) is unchanged; `type` stays a free string there.
- Unknown types are rejected at emit time; they are not silently dropped.

## Edge cases
- `run.finished` emitted with `{exit_code: 1, status: "failed"}` and with `{exit_code: 0}`: both match the member.
- A `task.failed` without a task (for example a spec-level failure): `task_id` is optional.
- `plan.lint` with errors: `diagnostics` is the array the linter produced; if none, omit it.
- Solo mode: `task.ready`, `task.passed` and `task.merged` use `task_id: "solo"`.

## Guardrails
- Not done if the catalog exists but an emit site still bypasses it. `grep -rn "emit(\"" src/engine` must show only calls that go through `typedEmit`.
- No stubs, TODO, FIXME, placeholder bodies or `as any` used to silence a data-shape mismatch. Fix the shape or the site.
- Do not add a catalog member for an event nothing emits, except the Appendix D names listed in Behavior 1.
- Do not change the outer `EngineEvent` schema in `src/contracts/index.ts`.
- Do not write an IP address or port in any file.

## Out of scope
The CLI output rewrite (R1.3), the usage ledger and budget math (R1.4), the replan logic changes (R3.5), the worker core (R3.3), and the `console.error` calls in the adapters.
