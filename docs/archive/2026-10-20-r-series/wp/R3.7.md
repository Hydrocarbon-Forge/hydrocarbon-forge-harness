## Objective
Make `merge`, `undo` and `discard` do exactly what they say, and refuse what they must not do. `merge` only merges a successfully finished run, into the user's current branch, through the git merger. `undo` moves the run branch back to a recorded checkpoint and never prints success otherwise. `discard` removes the run's worktrees and branches, with the correct paths.

## Interface
- `substrate merge <run> [--dry-run] [--abort-on-conflict]`
- `substrate undo [run] [--hard]`
- `substrate discard <run> [--force]`
- `src/cli/commands/merge.ts` exports `mergeRun(ctx, runId, opts): Promise<number>`, which `run.ts` calls when `git.auto_merge` is `true` after a finished run (exit 0).
- New `run.ts` behaviour: after `summary.exit_code === 0` and `settings.git.auto_merge === true`, call `mergeRun` with `{dryRun: false, abortOnConflict: false}`. Its exit code becomes the command's exit code.

## Behavior
1. Run state for `merge`, `undo` and `discard`: read `.substrate/runs/<id>/events.jsonl`. Ignore lines that do not parse. The run is `finished` only when the last `run.finished` has `exit_code: 0` and no `run.paused` follows it.
2. `merge <run>`: an unknown run id (no run directory and no `refs/heads/substrate/runs/<id>`) prints `Error: unknown run <id>` and exits 2. A run that is not `finished` prints `Error: run <id> did not finish successfully; not merged` and exits 1, with no git change.
3. `merge` refuses when the user's checkout has changes to tracked files (`git status --porcelain --untracked-files=no` non-empty): `Error: uncommitted changes to tracked files; commit or stash first`, exit 1.
4. `merge` runs `TaskMergerImpl.preflight(repoRoot, "HEAD", runBranch)`. On conflict, without `--abort-on-conflict`, it prints the conflicting files and exits 1 without touching git. With `--abort-on-conflict`, it runs `git merge --no-ff <runBranch>` and, if git reports conflicts, `git merge --abort`, then exits 1.
5. `merge` without conflicts runs `git merge --no-ff -m "merge run <id>" <runBranch>` in the user's checkout. It prints `Merged <runBranch> into <branch>` only after git exits 0, and exits 0.
6. `--dry-run` runs the same checks and the preflight, prints `would merge <n> commit(s) from <runBranch> into <branch>` where `n` is `git rev-list --count HEAD..<runBranch>`, makes no change, and exits 0.
7. `undo [run]` with no argument uses the most recent run directory that has a `batch.merged` event. A run with no `batch.merged` checkpoint prints `Error: no checkpoint recorded for run <id>` and exits 1.
8. `undo` takes the most recent `batch.merged.checkpoint_ref` whose sha differs from the current run-branch sha. It refuses with exit 1 when the user's checkout is on the run branch. It moves the ref with `advanceRunRef` (expected old value = current sha). It prints `Reverted substrate/runs/<id> to <sha>` only after that succeeds.
9. `undo --hard` also runs `git reset --hard <sha>` inside the run's integration worktree, if it exists. It never touches the user's checkout.
10. `discard <run>`: an unknown run prints `Error: unknown run <id>` and exits 2. A live lock (`.substrate/state/<id>.lock` with a pid that is alive) without `--force` prints `Error: run <id> is active; pass --force to stop it` and exits 1.
11. `discard --force` sends SIGTERM to the lock's pid, waits up to 5 seconds for it to exit, and removes the lock file.
12. `discard` removes every worktree listed by `git worktree list --porcelain` whose path is under `.substrate/worktrees/<id>/` (`git worktree remove --force`), removes any leftover directory, and runs `git worktree prune`. The old path `.substrate/worktrees/<id>` is never used.
13. `discard` deletes every branch under `substrate/tasks/<id>/` and the run branch `substrate/runs/<id>` (`git branch -D`).
14. `discard` appends `run.paused {reason: "user_cancel"}` to the run's events when the run is not already terminal, using the next seq. Then it prints `Discarded run <id>` and exits 0.

## Invariants
- `merge` changes only the user's current branch, and only through `git merge --no-ff`.
- `undo` and `discard` never print success on a path that did not succeed.
- No command deletes a file outside `.substrate/worktrees/<id>/` and `.substrate/state/<id>.lock`.

## Edge cases
- `merge` run whose run branch is already contained in `HEAD`: `merge` prints `Already up to date.` and exits 0.
- `undo` after `discard`: the run branch is gone, so `undo` prints `Error: unknown run <id>` and exits 2.
- `discard` of a run that has no worktrees: succeeds.
- Lock pid belongs to a dead process: treated as not live.

- No security hardening beyond the plan (DECISIONS A6): no new sandbox, environment scrubbing or permission-file checks.
- Never write a raw IP address or port in code, specs, docs or fixtures.

- No `git reset --hard` or `rm` on the user's checkout.
- No test-only branches in `src/`. No stub bodies.
