## Objective
Record every usage event in one append-only ledger, and make budget totals correct. Today the worker branch writes the total into state and the reducer adds the same cost again (C-H7), and nothing writes the ledger, so `cost` is always $0 (C-H20, S-H4). After this WP each `usage.recorded` event appends one ledger line to the project and, unless disabled, to the global mirror, and the run's total is counted once. You change no file under `src/backends/`, `src/roles/`, `src/cli/` or `src/git/`.

## Interface
`src/contracts/index.ts` gains `UsageLedgerEntry` (zod, `.strict()`):
`{ v: 1, ts: string, project: string, run_id: RunId, task_id?: TaskId, generation?: number, attempt?: number, role: RoleName, class?: string, backend: BackendName, model: string, effort?: Effort, input_tokens: number, output_tokens: number, cache_read_tokens?: number, cache_write_tokens?: number, reasoning_tokens?: number, cost_usd: number, cost_source: "reported" | "computed" | "unknown" }`. (`cost_source` gains `"unknown"` here; R2.1 owns the pricing logic. Update the existing `UsageRecord.cost_source` enum in the same edit so the two agree.)

`src/ledger/usage.ts` exports:
- `ledgerPaths(opts: { projectRoot: string; globalEnabled: boolean; env: NodeJS.ProcessEnv }): { project: string; global?: string }`. `project` is `<projectRoot>/.substrate/ledger/usage.jsonl`. `global` is `$XDG_STATE_HOME/substrate/usage.jsonl` when `XDG_STATE_HOME` is set, else `<homedir>/.local/state/substrate/usage.jsonl`, and only when `globalEnabled` is true.
- `appendUsage(entry: UsageLedgerEntry, paths): void` appends one JSON line to `project` and, when set, to `global`. It creates the directories.
- `rebuildFromEvents(runDir: string, paths): number` removes the lines whose `run_id` matches the run from both files, then appends one line per `usage.recorded` event in `<runDir>/events.jsonl`, and returns the count.
- `toDelta(prev: UsageTotals | undefined, record: UsageRecord, cumulative: boolean): { delta: UsageRecord; next: UsageTotals }`, where `UsageTotals` is `{input_tokens, output_tokens, cost_usd}`. With `cumulative` false the delta is the record. With `cumulative` true the delta is the record minus `prev` for each field (never negative; a negative difference is set to 0).

`src/config/index.ts`: `usage: { global: boolean }` in `Settings` (in `src/contracts/index.ts`, `.optional()`), default `{global: true}` in `DEFAULT_SETTINGS`.

## Behavior
1. Every `usage.recorded` event that the engine appends (in `runEffectsLoop`, after `appendRunEvent`) also calls `appendUsage` with an entry built from `data.record` plus `run_id`, `role`, `task_id`, `generation`, `attempt`, `class`, `project` (the repo root), `ts` (the event ts). Its `v` is 1. The engine never writes a usage line any other way.
2. The reducer's `usage.recorded` case adds `record.cost_usd` to `state.usage.total_usd` once and to `by_role[role]` once. It no longer reads `data.max_usd`, and it no longer pauses on budget. Budget decisions are made by the action (step 4).
3. Delete the line `state.usage.total_usd = currentTotal;` in the worker branch of `task.ts`, and delete the same assignment wherever the planner, replan or solo actions do it. Each action computes `currentTotal = state.usage.total_usd + delta.cost_usd` as a local value only.
4. Budget check: after each `usage.recorded` the action compares `currentTotal` with `settings.budgets.run.max_usd`. When the total is at least 80 percent of the cap and below it, it emits `run.budget.warning` (the existing rule in `effects.ts`). At or above the cap it emits `run.budget.exceeded` and `run.paused` with `reason: "budget_exhausted"`. The check uses the reducer state plus the pending event, never a stored total.
5. A `BackendEvent` of type `usage` with `cumulative: true` is converted to a delta with `toDelta`, keyed by session id, in the action that handles it. The `prev` totals for a session id are kept in a `Map` in the action's closure for the run. `cumulative: false` is used as is.
6. `usage.global` false: no global file is written, and no global path is read. `usage.global` true (default): the mirror is written.
7. The `usage.recorded` emit in the worker, planner, replan and solo actions passes the delta record, not the cumulative record.

## Invariants
- For a run, the sum of `cost_usd` over its `usage.recorded` events equals `state.usage.total_usd` in the final summary.
- The ledger has exactly one line per `usage.recorded` event (no duplicates on resume, because resume appends only new events).
- The project ledger lines never change after they are written, except inside `rebuildFromEvents`, which replaces only that run's lines.

## Edge cases
- A record with `cost_usd` missing: treated as 0 and kept (no record is dropped).
- A record with `cost_source` `unknown`: written as is, with `cost_usd` 0.
- The global directory is not writable: the write error is logged with `log.warn` (from `src/util/log.ts`, created by R0.5) and the project line is still written; the run continues.
- A torn last line in the ledger file (partial write): `rebuildFromEvents` rewrites the file completely; readers skip unparseable lines.

## Guardrails
- Not done if the ledger is written only by a function that tests call. The engine's `runEffectsLoop` path must call `appendUsage`, and the E2E check below proves it.
- No stubs, TODO, FIXME, placeholder bodies or hard-coded totals. No `as any` to read `max_usd`.
- Tests must set `XDG_STATE_HOME` to a temp directory; no test writes under the developer's home.
- Do not change the pricing table or cost computation (R2.1).
- Do not write an IP address or port in any file.

## Out of scope
The `usage` command and its aggregation (R2.8), the price table (R2.1), adapter usage parsing (R2.3-R2.5), budget timeouts and per-task enforcement (R3.4), and the `LedgerEntry` and `aggregateLedger` types, which stay unchanged.
