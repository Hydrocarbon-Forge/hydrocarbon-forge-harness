## Objective
Prove the whole product through the built CLI in one matrix, end with a debt allowlist that holds no entry except the governor's `DEFERRED` ones, and then retire the work-package plan. Every scenario in SUBSTRATE-PLAN section 14, plus the request, local-model, crash and git-command paths, runs with the fake harness for every dialect. Only after that passes are the R-series files moved to a dated archive; nothing is deleted.

## Interface
- `test/e2e/matrix.test.ts` is a table-driven suite. Each row is `{id, name, dialects, run(ctx) => Promise<void>}` and uses `runSubstrate` (from `test/e2e/helpers/run-substrate.ts`) and `test/e2e/helpers/repo.ts`. Dialects: `claude`, `opencode`, `agy`; rows that test engine behaviour run with each dialect.
- `scripts/debt-allowlist.json`: no entry remains in `purity`, `wired`, `events`, `settings` or `dead` except entries with `until: "DEFERRED"` (governor code that stays unless the optional R5.4 is done). The `events_observe_only` array is kept unchanged.
- Archive directory: `docs/archive/<YYYY-MM-DD>-r-series/` (the date of the archive commit, from `date +%F`). Moved with `git mv`: `docs/plan/wp/` to `<archive>/wp/`, `docs/plan/IMPLEMENTATION-PLAN.md` and `docs/plan/PROGRESS.md` to `<archive>/`. Kept in place: `docs/plan/DECISIONS.md`, `docs/plan/reference/AUDIT-FINDINGS.md`, and `docs/plan/BLOCKED.md` if it exists (it moves with the archive).

## Behavior
1. Matrix rows, one per scenario of SUBSTRATE-PLAN 14 (1 to 16), with the scenario's expected exit and events:
   - 1 all-pass batch: exit 0, `batch.merged`.
   - 2 fail, heal, pass: exit 0, `task.healing` with real failing output.
   - 3 double fail, packet, L1 replan, pass: exit 0, a packet file.
   - 4 scope violation reverted: exit 0, `scope.checked` with violations, file reverted.
   - 5 protected file modified: `task.failed` `protected_modified`.
   - 6 permission denial: exit 3, `run.paused` `permission_denied`.
   - 7 budget kill: exit 4 (run budget) or a task `budget_exceeded`.
   - 8 timeout kills the process group: `task.failed` `timeout`, no live child pids.
   - 9 merge conflict: `merge.conflict` then L1.
   - 10 integration failure: `bisect.culprit`.
   - 11 crash and resume at every event boundary: for each index i of a finished reference run's `events.jsonl`, truncate to i events, `resume`, and assert exit 0 and the same final task states.
   - 12 rate-limit backoff: `rate_limit.backoff` events.
   - 13 planner format retry: success after one retry; and failure after exhausted retries (exit 1).
   - 14 L2 amendment invalidates dependents only: `tasks.invalidated` excludes MERGED tasks.
   - 15 request run with no governor setting present: `run --request` (R4.1) exits 0.
   - 16 solo mode: exit 0 (R3.8).
2. Extra rows: local-model route (R4.3); SIGKILL then resume (R3.2); `merge`, `undo`, `discard` on a temp repo (R3.7); `--output-format json` and `stream-json` outputs parse with `JSON.parse` line by line; every dialect for the rows that use an executable.
3. A final row runs `git grep -n "val_\${" src` and `git grep -n "console.log" src/engine` and expects no output.
4. Archive step (only after steps 1 to 3 pass and the allowlist has no entry other than `DEFERRED` ones): confirm every row of `docs/plan/PROGRESS.md` except R5.3 and the optional R5.4 is DONE, otherwise stop and report the first row that is not. Mark R5.3 DONE in `PROGRESS.md` and commit that alone as `R5.3: Final wiring audit and E2E matrix`. Then, in a second commit, perform the moves from Interface.
5. Rewrite `START-HERE.md` to describe the current state: the binding decisions, the CLI as it now exists, how to run `npm run check`, `npm test` and `npm run docs:check`, and a pointer to the archive for the R-series history. It contains no governor default, no TUI claim, and no stub-status language. Update any link or path in `README.md`, `START-HERE.md` or `docs/` that points at a moved file to the archive path; `docs/plan/DECISIONS.md` is not changed.

## Invariants
- The matrix uses only fake executables. No row calls a real model. Each row's assertions come from the event log or the process exit, not from console text alone, and every row removes its temp directories.
- No file is deleted by the archive step; moved files keep their content byte for byte (`git mv`). `docs/plan/DECISIONS.md` is byte-identical before and after.
- `src/` is not edited in this WP.

## Edge cases
- Row 11 with a boundary that lands inside a task: the resume must still finish (R3.2 rule 8).
- A dialect that cannot express a scenario (for example stream-json for a permission denial): the row lists only the dialects that can.
- A link to `docs/plan/wp/` in `SUBSTRATE-PLAN.md`: updated to the archive path, not removed.
- After the move, `node scripts/check-plan.mjs` prints `no docs/plan/PROGRESS.md work packages found` and exits 0. That is expected.

## Guardrails
- No security hardening beyond the plan (DECISIONS A6): no new sandbox, environment scrubbing or permission-file checks.
- Never write a raw IP address or port in code, specs, docs or fixtures.
- Not done if the matrix only exists. Each row must run and pass. Do not skip a row to make the suite green: a failing row is a finding. Fix the code in the WP that owns it, or stop and record it in `docs/plan/BLOCKED.md`.
- No `it.fails` markers. No test-only branches in `src/`.
- Do not rewrite the R-series content when archiving; only its location and status change.

## Out of scope
Live harness runs (R5.2). Governor removal (R5.4). New documentation (R5.1 is done).

## Done when
1. `npm run typecheck` exits 0.
2. `npx vitest run test/e2e/matrix.test.ts` passes with all rows, and its output lists the row count (at least 16 scenario rows plus the extra rows).
3. `npm test`, `npm run check` and `npm run docs:check` pass with no allowlist entry other than `DEFERRED` ones.
4. `ls docs/plan` shows only `DECISIONS.md` and `reference`, and `ls docs/archive/*-r-series` shows `wp`, `IMPLEMENTATION-PLAN.md` and `PROGRESS.md`.
5. `git diff --stat HEAD~2 -- docs/plan/DECISIONS.md` is empty.
6. The first commit message is `R5.3: Final wiring audit and E2E matrix` (with the matrix row count and the `npm run check` output in the PROGRESS Notes); the second is `R5.3: Archive the R-series`.
