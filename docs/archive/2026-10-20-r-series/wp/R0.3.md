## Objective
Give the test suite a way to run the built CLI (`dist/substrate.mjs`) in a real temporary git repository against the three fake executables from R0.2, and record what happened. Add a smoke test file whose two tests describe the behaviour the plan requires and are marked `it.fails`, so the suite stays green now and turns red as soon as the feature works. After this WP, `npm test` passes with those markers and `npx vitest run test/e2e` reports both as expected failures. You change no file under `src/`.

## Interface
`test/e2e/helpers/run-substrate.ts` exports:
```ts
export interface RunSubstrateOptions {
  files?: Record<string, string>;      // written into the temp repo, committed as "seed"
  scenario?: { calls: unknown[] };     // written to a file outside the repo; sets FAKE_SCENARIO_FILE
  args: string[];                      // argv after dist/substrate.mjs
  env?: Record<string, string>;        // merged last (wins)
  stdin?: string;                      // omitted means stdin is closed (empty)
  settings?: Record<string, unknown>;  // merged into .substrate/settings.json (see Behavior 3)
  timeoutMs?: number;                  // default 120000
}
```
`RunSubstrateResult` and the function:
```ts
export interface RunSubstrateResult {
  exitCode: number;                    // child status; 124 when killed by the timeout
  stdout: string;
  stderr: string;
  repoDir: string;                     // the temp repo (removed by cleanup)
  runDir: string | null;               // newest .substrate/runs/<id>/ or null
  events: Array<{ v: number; seq: number; ts: string; run_id: string; type: string; data: unknown }>;
  cleanup(): void;
}
export function runSubstrate(options: RunSubstrateOptions): RunSubstrateResult;
```
`test/e2e/helpers/repo.ts` exports `createE2ERepo(files: Record<string, string>): { dir: string; git(args: string[]): string; cleanup(): void }`. It is self-contained (do not import from `test/integration`).
`test/e2e/global-setup.ts` default-exports `async function setup()`.

## Behavior
1. `createE2ERepo` makes a directory with `fs.mkdtempSync(os.tmpdir() + "/substrate-e2e-")`, runs `git init -b main`, sets `user.name` to `Substrate E2E`, `user.email` to `e2e@example.com` and `commit.gpgSign` to `false`, writes `files` plus a `README.md`, and commits them as `seed`.
2. `runSubstrate` creates the repo, then creates a second temp dir for the scenario file (not inside the repo). It writes `scenario.json` there when `scenario` is given and sets `FAKE_SCENARIO_FILE` to its path.
3. It writes `.substrate/settings.json` in the repo: `{"backends": {"claude": {"bin": B/claude}, "opencode": {"bin": B/opencode}, "agy": {"bin": B/agy}}, "concurrency": {"workers": 1}}`, where `B` is the absolute path `test/fixtures/fake-harness/bin` resolved from the repo root. `options.settings` is deep-merged over that object (plain objects merge, arrays and primitives replace).
4. It spawns `process.execPath` with `[<root>/dist/substrate.mjs, ...args]`, `cwd` set to the repo dir, `input` set to `stdin ?? ""`, `timeout` set to `timeoutMs`, and `env` set to `{...process.env, HOME: <empty temp dir>, FAKE_SCENARIO_FILE: <path>, ...options.env}`. Setting `HOME` to an empty directory keeps the developer's `~/.config/substrate` out of the test. Remove `FAKE_SCENARIO_FILE` from the inherited environment when `scenario` is not given.
5. `exitCode` is `status`, or `124` when the spawn was killed by the timeout. `stdout` and `stderr` are the captured UTF-8 text.
6. `runDir` is the newest directory (by name sort) under `<repo>/.substrate/runs/`, or `null`. `events` is every line of `<runDir>/events.jsonl` parsed with `JSON.parse`, in file order. A missing file gives `[]`, and a line that fails to parse makes the helper throw with the line number.
7. `global-setup.ts` runs `node scripts/bundle.mjs` once from the repo root with `execFileSync` and throws if it exits non-zero. Vitest runs it once before the test files.
8. `vitest.config.ts` keeps `include: ["test/**/*.test.ts"]` and adds `globalSetup: ["test/e2e/global-setup.ts"]`.
9. `smoke.test.ts` contains exactly two tests, both written with `it.fails`:
   (a) `it.fails("full solo run edits a file, verifies it and finishes with exit 0")`: seed `src/a.txt` with `one\n`; scenario `{calls: [{edits: {"src/a.txt": "one\ntwo\n"}, reply: "DONE"}]}`; args `["run", "--mode", "solo", "--verify", "grep -q two src/a.txt", "add a line two to src/a.txt"]`. Expect `exitCode` 0 and the last event with `type` `run.finished` to have `data.exit_code` 0. The marker is removed by R3.8.
   (b) `it.fails("node dist/substrate.mjs --help exits 0 and prints usage")`: args `["--help"]`. Expect `exitCode` 0 and `stdout` to contain `Usage`. The marker is removed by R1.1.
10. Each `it.fails` body must fail on its own assertion, not on an unrelated exception. Record the assertion message in the Notes section of PROGRESS.md (Done when, step 3).

## Invariants
- The helper never writes inside the repository root of this project. Only the temp repo, its `.substrate` directory and the temp scenario and home directories are written.
- Every temp directory is removed by `cleanup()`. Tests call `cleanup()` in `afterEach`.
- `runSubstrate` never calls the network and never reads the developer's home directory.
- The helper is deterministic: no random ports, no shared temp names.

## Edge cases
- `dist/substrate.mjs` missing: `global-setup` builds it first; if the build fails the whole E2E run fails with the bundle error.
- Child killed by timeout: `exitCode` 124, `stderr` keeps what was written.
- No `.substrate/runs` directory (the CLI never created a run): `runDir` null, `events` `[]`.
- Two runs in one repo: `runDir` is the newest by name, which is the later run id (run ids are time-sortable per `RunId`).
- `files` with nested paths create their directories.
- Windows path separators are not supported; the test suite runs on Linux and macOS.

## Guardrails
- Not done if the helper is used only by the smoke tests in a way that cannot run the real CLI. It must spawn `dist/substrate.mjs`, never import `src/` to run the engine in-process.
- No stubs, TODO, FIXME, placeholder bodies, hard-coded return values, or mocks of the CLI. The tests must not assert on canned output.
- Do not modify `bin/substrate.mjs`, `scripts/bundle.mjs` or anything in `src/`. The bundle script already produces `dist/substrate.mjs`.
- Do not write a raw IP address or port in any file, including the helper defaults. The fake executables use `fake.invalid` hosts only.
- Do not delete `test/smoke.test.ts` in this WP (R1.1 does that).
- Do not use `it.skip` or `it.todo`; the markers must be `it.fails`.

## Out of scope
Making either smoke test pass (R1.1 and R3.8 do that), the scenario format itself (R0.2), the golden fixtures (R0.4), and the live adapters (R2.3-R2.5).
