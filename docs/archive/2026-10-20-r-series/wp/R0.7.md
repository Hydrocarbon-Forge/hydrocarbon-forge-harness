## Objective
Delete the terminal user interface (TUI) code. Substrate's callers are agents and command-line users, the TUI cannot render (it has no entry point and `ink` and `react` are not installed, and `tsconfig.json` only compiles `*.ts`, so its `.tsx` files are never built), and leaving it makes every dead-code check and every reader think it is a feature. After this WP there is no `src/tui/` and no mention of a TUI in user-facing docs.

## Interface
No runtime interface changes. Removed: `src/tui/**` (about 1,150 lines: `app.tsx`, `index.ts`, `commands/`, `components/`, `keys/`, `state/`) and `test/unit/tui/**` (four test files). The boundary rules in `scripts/check-boundaries.mjs` stop mentioning `tui`.

## Behavior
1. Prove nothing uses the TUI. Run `git grep -n "tui" -- src test scripts ':!src/tui' ':!test/unit/tui'`. The only hits must be in `scripts/check-boundaries.mjs`. If anything else appears, stop and write it to `docs/plan/BLOCKED.md`.
2. Record the current test count (the last lines of `npm test`) in the PROGRESS Notes, then run `git rm -r src/tui test/unit/tui`.
3. In `scripts/check-boundaries.mjs` remove `"tui"` from `SURFACE_FORBIDDEN` and `ENGINE_FORBIDDEN` and from the comments and violation messages that mention it (the rules become: nothing imports `cli`; engine may import everything except `cli` and `hooks`). Keep the `hooks` ban.
4. In `README.md` delete the bullet "Interactive TUI: ..." (around line 60) and remove the words "the interactive TUI," from the status banner at the top. In `docs/reference/cli.md` change the `-p`/`--print` description (around line 17) to: `Run headlessly and print the result to stdout.`
5. Move `docs/spikes/S5-ux.md` to `docs/archive/S5-ux-tui-research.md` with `git mv`, and add as its first line: `> Archived: research for a TUI that was removed (work package R0.7). Not part of the product.`
6. In `scripts/debt-allowlist.json` delete every entry whose `path` starts with `src/tui` (they were tagged `until: "R0.7"`). Do not touch other entries.

## Invariants
- No file outside the lists above changes. `src/` other than `src/tui/` is byte-identical afterwards (`git diff --stat -- src ':!src/tui'` is empty).
- The number of failing tests is zero; the total drops only by the tests in `test/unit/tui/`.
- `npm run check:boundaries` still enforces the other rules (cli and hooks bans, per-area allowlists).

## Edge cases
- If `scripts/debt-allowlist.json` has no `src/tui` entries (R0.1 was implemented differently), skip step 6 and say so in Notes.
- `docs-check` must still pass: no link in the README or `docs/reference/` may point at the moved spike file.
- The legacy specs in `build/specs/` mention `src/tui`; leave them untouched.

## Guardrails
- Do not edit anything under `src/` except by removing `src/tui/`. Do not "improve" the boundary script beyond removing `tui`.
- Do not add a replacement `status --watch` or any other feature in this WP.
- No stubs, no placeholder files, no empty `src/tui` directory left behind.
- Never write a raw IP address or port anywhere.

## Out of scope
Any human-monitoring feature (a future `status --watch`), changes to the CLI, SUBSTRATE-PLAN.md (its banner already marks the TUI sections historical), and the legacy `build/` specs.

## Done when
1. `test -e src/tui && echo present || echo gone` prints `gone`; same for `test/unit/tui`.
2. `npm run typecheck`, `npm run check:boundaries`, `npm test` and `npm run check` all exit 0.
3. `git grep -n -i "tui" -- . ':!docs/archive' ':!docs/plan' ':!SUBSTRATE-PLAN.md' ':!build' ':!research' ':!docs/spikes'` prints nothing.
4. In `docs/plan/PROGRESS.md` mark R0.7 DONE and note the test counts before and after. Commit as `R0.7: Remove the inert TUI scaffold`.
