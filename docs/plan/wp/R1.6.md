## Objective
Make documented configuration work. Settings are layered exactly as `docs/reference/config.md` describes, the `SUBSTRATE_*` variables in its table are read, `config get`, `list` and `set` work on the merged result and validate writes, and a first word that is not a command is a prompt. After this WP `substrate "refactor"` reaches `run`, and each precedence layer has a test. You change no file under `src/engine/`, `src/roles/`, `src/git/`, `src/backends/` or `src/contracts/`.

## Interface
`src/config/index.ts` exports `loadSettings(options)` (existing name, extended) and `readEnvLayer(env: NodeJS.ProcessEnv): { settings: Partial<Settings>; runDefaults: { permissionMode?: PermissionMode; outputFormat?: "text" | "json" | "stream-json" } }`.

`loadSettings` options gain `env?: NodeJS.ProcessEnv` (default `process.env`) and `flags?` (existing). The layers, lowest to highest, are:
1. `DEFAULT_SETTINGS`.
2. User file: `<dir>/settings.json`, where `<dir>` is `SUBSTRATE_CONFIG_DIR` if set, else `~/.config/substrate`.
3. Project file: `<project>/.substrate/settings.json`, where `<project>` is `SUBSTRATE_PROJECT_DIR` if set, else `options.projectDir`, else `process.cwd()`.
4. Project local file: `<project>/.substrate/settings.local.json`.
5. Explicit file: `options.settingsFile` (from `--settings`), else `SUBSTRATE_SETTINGS`. A missing explicit file throws `Settings file not found: <path>`.
6. Environment: `readEnvLayer(env).settings`.
7. Flags: `options.flags`.

Merging uses `deepMerge` from `src/util/merge.ts`. `pricing` is replaced whole, as the reference says.

`src/cli/commands/config.ts`: `config get <key>`, `config list` print the merged, validated settings (not the raw file). `config set <key> <value> [--local]` writes `.substrate/settings.json` (or `.substrate/settings.local.json` with `--local`). It writes only the target file's own content, after checking that the merged result with the new value still parses with `Settings.parse`. On failure it writes the zod message to stderr, leaves files unchanged and returns 2.

`src/cli/dispatcher.ts`: `CLI_OPTIONS` gains `local: { type: "boolean" }`. `CliGlobalFlags` gains `local?: boolean`.

## Behavior
1. Environment table (values are read only when set and non-empty):
   - `SUBSTRATE_SETTINGS`: layer 5 (Interface).
   - `SUBSTRATE_CONFIG_DIR`, `SUBSTRATE_PROJECT_DIR`: layers 2 and 3 (Interface).
   - `SUBSTRATE_MAX_BUDGET_USD` (number): settings `budgets.run.max_usd`. A value that is not a finite number is an error: `SUBSTRATE_MAX_BUDGET_USD must be a number`, exit 2.
   - `SUBSTRATE_MODEL`: settings `roles.planner.model`.
   - `SUBSTRATE_WORKER_MODEL`: settings `roles.worker.model`.
   - `SUBSTRATE_PERMISSION_MODE` (one of `default`, `plan`, `acceptEdits`, `dontAsk`, `bypassPermissions`): `runDefaults.permissionMode`, used when `--permission-mode` is not given. An unknown value is an error, exit 2.
   - `SUBSTRATE_OUTPUT_FORMAT` (`text`, `json`, `stream-json`): `runDefaults.outputFormat`, used when `--output-format` is not given.
   - `SUBSTRATE_LIVE`: read by the test batteries only, never by `loadSettings`. Say so in a comment at `readEnvLayer`.
2. Dispatch: with no arguments at all, `runCli` prints the help text and returns 0, even when stdin is not a TTY. A first positional that is not a registered command makes the whole argument list a `run` prompt (`substrate "refactor"`, and `substrate refactor` with one word). The existing rule for two or more words stays. An unknown command word is therefore never an error; it is a prompt.
3. `config get <key>` prints the value at the dotted key from the merged settings (an object as indented JSON, a scalar as text, `undefined` when absent). `config list` prints the merged settings as indented JSON.
4. `config set <key> <value>`: the value is parsed as JSON if it parses, else kept as a string (existing `parseVal`). Success prints `Set <key> = <json value>` and returns 0. Validation failure prints `Invalid setting <key>: <zod message>` and returns 2, and nothing is written.
5. `loadSettings` still throws on an invalid merged result, with the zod message.

## Invariants
- `loadSettings` output always passes `Settings.parse`.
- Each layer changes only the keys it sets; a key set by no layer keeps the default.
- Writes by `config set` never remove other keys of the target file.

## Edge cases
- `SUBSTRATE_MODEL` and `--model` both set: the flag wins (layer 7).
- A user file that is malformed JSONC: `parseJsonc` throws with the filename, unchanged.
- `--settings` and `SUBSTRATE_SETTINGS` both set: the flag wins.
- `substrate config` with no subcommand prints the merged settings (same as `list`).
- `substrate ""` (an empty first argument) is a `run` with an empty prompt, so it exits 2 with `Error: prompt required` (the existing rule for `run`).

## Guardrails
- Not done if a layer is only tested in isolation. The precedence test (`test/unit/config/precedence.test.ts`) must show each layer overriding the one below it in one call to `loadSettings`.
- No stubs, TODO, FIXME, placeholder bodies or hard-coded values. No test-only branch in `src/`.
- Do not read `SUBSTRATE_LIVE` in `src/`.
- Do not write an IP address or port in any file, including examples.
- Do not change `DEFAULT_SETTINGS` values in this WP.
