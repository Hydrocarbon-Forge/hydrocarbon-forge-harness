## Objective
Split `src/engine/effects.ts` (1589 lines, one 1140-line `executeAction` switch) into one module per action, so later work packages touch separate files. This is a pure move: no behaviour change, no renames, no logic edits, no cleanup. Before moving anything, record golden event logs from the existing scenario tests so the move can be proven behaviour-preserving. You change no file outside `src/engine/`, `test/integration/scenarios/helpers.ts` and `test/fixtures/golden/`.

## Interface
`src/engine/effects.ts` keeps and exports, with the same names and signatures:
`safeParseManifest`, `safeLoadPlan`, `nextActions`, `executeAction`, `appendRunEvent`, `readAllRunEvents`, `runEffectsLoop`, and the types `EngineActionType`, `EngineAction`, `EffectContext`. It re-exports every symbol that was exported before this WP. `src/engine/engine.ts` imports `EffectContext`, `runEffectsLoop`, `appendRunEvent` and `readAllRunEvents` from `./effects.js` and must keep compiling unchanged.

`src/engine/actions/shared.ts` exports `makeEmitter(ctx: EffectContext, state: EngineState): { events: EngineEvent[]; emit(type: string, data?: Record<string, unknown>): EngineEvent }`, `extractFencedFiles` (moved from effects.ts line 64), and `safeParseManifest` (line 90) and `safeLoadPlan` (line 98) with their bodies unchanged. `safeParseManifest` and `safeLoadPlan` are then re-exported from effects.ts.

Each action module exports one function `runXxxAction(action: EngineAction, ctx: EffectContext, state: EngineState, emit: Emit): Promise<void> | void`, where `Emit` is the type of `emit` from `makeEmitter`. The events are pushed by `emit` into the shared array.

## Behavior
1. Golden capture (do first, before any move). In `test/integration/scenarios/helpers.ts`, change `readEventLog(runDir, runId)` so that it also records its result. Read the environment variable `SUBSTRATE_GOLDEN`. If it is `record`, write the normalized events to `test/fixtures/golden/<name>.jsonl`, where `<name>` is the basename of the calling test file without `.test.ts` (get it from `expect.getState().testPath`). If it is `compare`, read that file and `expect` the normalized events to equal it. If the variable is unset, do nothing extra.
2. Normalization: replace each event's `ts` with `"<ts>"` and `run_id` with `"<run_id>"`; in the JSON string, replace `/r_[A-Z2-7]{12}/g` with `<run_id>`, UUIDs with `<uuid>`, and `ses_[A-Za-z0-9]+` and `fake-session-[a-z0-9]+` with `<session>`. Keep `seq`, `type` and `data` otherwise intact. Write one JSON object per line.
3. Run `SUBSTRATE_GOLDEN=record npx vitest run test/integration/scenarios` once, then again. The two recordings must be byte-identical. If a scenario differs between the two runs, add a normalization rule for the varying field and say so in Notes; do not drop a scenario.
4. Move the code. `makeEmitter` is the body of the `emit` closure now at effects.ts lines 368-380, with `seq` taken from `(state as any)._seq ?? 0` exactly as before. Move each `switch` case body out of `executeAction` into the module listed here, then make `executeAction` call `makeEmitter`, switch on `action.type`, call the matching `runXxxAction`, and return `events`:
   - `route.ts`: `case "route"` (lines 383-444).
   - `plan.ts`: `case "plan"` (445-566) and `case "lint"` (567-645).
   - `approve.ts`: `case "gate"` (1479-1483).
   - `setup.ts`: `case "setup"` (646-695).
   - `task.ts`: `case "worker"` and `case "heal"` (696-1135) except the `if (taskId === "solo") {...}` block, which moves to `solo.ts` as `runSoloTask`. `task.ts` calls `runSoloTask` for that branch.
   - `replan.ts`: `case "replan"` (1136-1331).
   - `merge.ts`: `case "merge"` (1332-1392).
   - `integrate.ts`: `case "integration"` (1393-1478) and the helper `runIntegrationVerify` (effects.ts lines 323-359).
   - `finish.ts`: `case "abort"` (1484-1493).
5. Action modules import types from `../effects.js` with `import type` only. They must not import any runtime value from `effects.ts`, which avoids a circular runtime import.
6. The `default:` case returns the events unchanged, as today.
7. Allowlist. `scripts/debt-allowlist.json` keys purity entries by `rule` and `path`. Every `purity` entry whose `path` is `src/engine/effects.ts` must be re-pointed to the file that now holds the violating line (run `node scripts/check-purity.mjs` and copy the reported `path` for each `P2`, `P5`, `P7` and `P3` violation). Keep each entry's `until` unchanged. Remove an entry only if the check reports it as stale. Do not add entries.

## Invariants
- The 15 scenario tests behave as before: same assertions, same events, same order, same `seq` values.
- `SUBSTRATE_GOLDEN=compare npx vitest run test/integration/scenarios` passes after the move, against the files recorded before it.
- `executeAction`, `nextActions`, `runEffectsLoop`, `appendRunEvent` and `readAllRunEvents` keep their signatures.
- The `console.log("[DEBUG]...")` lines in `runEffectsLoop` stay in place; R0.5 removes them.

## Edge cases
- `solo` is not an action type. The solo path is reached through `worker` and `heal` with `taskId` `"solo"`, and through the route branch at lines 384-388 and 434-437, which stays in `route.ts`.
- Helper functions used by several cases (`safeParseManifest`, `extractFencedFiles`) must live in `shared.ts`, not be duplicated.
- If a case body refers to a local variable from the top of `executeAction` (other than `emit` and `events`), pass it through the function arguments and do not change its meaning.
- `test/fixtures/golden/` may be empty before recording. The `.gitkeep` file keeps it in git.
