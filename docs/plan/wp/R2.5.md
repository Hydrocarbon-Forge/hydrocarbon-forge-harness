## Objective
Make agy runs report usage correctly and make agy unable to change git state silently. Five defects are fixed: a test-only `--denial-tool` branch in the adapter (`bin !== "agy"`), the fake-harness environment variables passed to the real binary (`FAKE_SCENARIO`, `AGY_LIVE`), an unconditional `--sandbox` flag that S3 shows grants nothing, a session total that double counts on resume (agy usage is conversation-cumulative), and an unpriced model that breaks the stream. After this WP every agy usage step is one record, the session total is the sum of steps, and the adapter has no test-only branch. You change no file under `src/engine/`, `src/roles/` or `src/git/`.

## Interface
`src/backends/adapters/agy.ts`:
- `AgyAdapter.spawn(req)` builds argv: `-p <prompt> --output-format stream-json --model <model>`, then `--effort <e>` only when `e` is `low`, `medium` or `high`, then `--mode accept-edits`, then `--print-timeout 0s` (Notes), then `--conversation <id>` when resuming.
- The `capabilities.sandbox_flag` value is `false`. The adapter never passes `--sandbox`.
- The adapter's env allow list is the process list without `FAKE_SCENARIO` and `AGY_LIVE`.

`src/backends/normalize/agy.ts`: `normalizeAgyStream(stream, stderrStream, options)` keeps its signature. The session total (the `session.result` usage) is the sum of the per-step `usage` records, not the value in `result.usage`.

## Behavior
1. Denial: `permission_denial_signal` is `"stderr"` in the capabilities object of the adapter, with a comment that cites S3 (the stderr line `jetski: no output produced` and `result.denied_actions` are both parsed). The adapter's `--denial-tool` argument is removed entirely.
2. Permission grants: when `req.permission.allow` is non-empty, the adapter writes nothing to git state. The engine's HEAD-unchanged check (R3.3) is the safeguard. Record in Notes that agy's allow-rules live in `settings.json` (S3), which the adapter does not write.
3. System text: there is no verified system-prompt flag (S3). When `req.system_append` is non-empty, the prompt sent is `SYSTEM RULES\n<system_append>\n\nTASK\n<prompt>`. The `-p` argument carries that combined text.
4. Effort: `low`, `medium` and `high` are passed as given. `xhigh` and `max` are not passed, and the adapter calls `log.warn` once with `agy: effort <e> is not supported by agy 1.4.0; omitted`. (S3: no shipped slug accepts them.)
5. Usage per step: each `step_update` with `state: "DONE"` and a `usage` object produces one `usage` event with `cumulative: false` and a record from `toUsageRecord`. The `result` event's `usage` is not emitted as a usage event.
6. Session total: `session.result.usage` is the sum over the step records of the session (`input_tokens`, `output_tokens`, `cache_read_tokens`, `cost_usd`), with `cost_source` `computed` when every step is priced, else `unknown`. Resume does not double count, because each session's steps are summed once.
7. Unpriced model: the record is built with the non-throwing calculation from R2.1 (`cost_source: "unknown"`, `cost_usd: 0`), and the stream continues.
8. The adapter's pricing lookup (the fallback to the first priced model when the model is not priced) is removed. The model in the record is `req.model`.
9. The adapter's `catch` blocks that swallow errors while reading usage are removed. A failure to build a record emits `error` with `kind: "protocol"` and the step number.

## Invariants
- The adapter has no test-only branch: no `bin !== ...`, no `FAKE_*` or `AGY_LIVE` name, no `process.env` check.
- The sum of usage events in a run equals the session total.
- A denied action is reported as a `permission.denied` event, never only as exit code 0.

## Edge cases
- `--conversation` resume: `init` echoes the same conversation id (S3); the normalizer keeps the first id.
- `result.status` `ERROR` with `invalid model selection ... --effort`: the adapter already reports the error; add no retry.
- `denied_actions` present with an empty `response` (S3): `session.result` has `final_text` `""` and the denial event is emitted.
- A usage object with only `input_tokens` and `output_tokens`: `cache_read_tokens` is absent in the record.

## Guardrails
- Not done if the adapter still has the `--denial-tool` argument or the `FAKE_SCENARIO` name. `grep -n "denial-tool\|FAKE_SCENARIO\|AGY_LIVE\|--sandbox" src/backends/adapters/agy.ts` must print nothing.
- No stubs, TODO, FIXME, placeholder bodies, hard-coded token counts, or mocks of the normalizer.
- Do not change `src/backends/registry.ts` (R2.2).
- Do not write an IP address or port in any file.

## Out of scope
`agy models` (R2.6), `substrate models` (R2.7), the fake agy dialect's `--conversation` behaviour (R0.2), and the agy sandbox policy (A6).
