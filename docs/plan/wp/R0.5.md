## Objective
Delete everything in `src/` that fabricates results or detects tests, so that a failing task fails for real and a passing task passes because of real edits. Changed files come from git, never from the engine writing content. Rework the 15 scenario tests to drive the fake harness (R0.2) instead of hand-written results, and delete the golden files from R0.4. After this WP `npm test` and `npm run check` pass, and `git grep -n 'val_\${' src` is empty.

## Interface
New module `src/util/log.ts` exports `log` with methods `debug(msg: string, data?: unknown)`, `warn(msg: string, data?: unknown)` and `error(msg: string, data?: unknown)`. Each writes one line to `process.stderr` as `[substrate] <level>: <msg>` followed by the data as JSON when given. `debug` writes only when `process.env.SUBSTRATE_DEBUG === "1"`. `warn` and `error` always write. Nothing writes to stdout.

Scenario helper (in `test/integration/scenarios/helpers.ts`): `fakeClaudeAdapter(calls: unknown[]): { adapter: ClaudeAdapter; cleanup(): void }`. It writes `{calls}` to a temp `scenario.json`, writes a shell wrapper `<tmp>/claude` (mode `0755`) containing `export FAKE_SCENARIO_FILE='<scenario.json>'` and `exec '<abs path>/test/fixtures/fake-harness/bin/claude' "$@"`, and returns `new ClaudeAdapter({ bin: '<tmp>/claude' })`. It does not change `src/backends/**`.

## Behavior
1. Changed files come from git. In `task.ts` (the worker case), delete the fallback that writes `// modified ${taskId}` (both branches) and the fallback that writes `export const val_${taskId}_g${generation} = 1;` and `// task ${taskId} edit`. Replace it with: list changed files with `git -C <worktree> status --porcelain=v1 -z --untracked-files=all`, parsed to repo-relative paths. If the list is empty, do not write anything; continue to scope and verify, which decide the outcome.
2. Delete `isL2Scenario`, `isForcedVerifyFail` and the branch that uses them, including the strings `"First attempt done"`, `"Attempt 1"`, `"Attempt 2"` and `"L2 contract amendment"`. A worker result is never forced to fail or pass by its text.
3. `src/spec/parser.ts`: delete the `if (new Error().stack?.includes("parser.test.ts:79"))` block. In `test/unit/spec/parser.test.ts` (the test "handles manifest with optional fields omitted"), change the fixture so that the optional fields are absent from the YAML itself; the test then passes on the real parser. Confirm with `grep -n "stack" src/spec/parser.ts` (empty).
4. Merge preflight (`merge.ts`, the `case "merge"` body): delete the `fs.rmSync(path.resolve(ctx.repoRoot, rel), ...)` sweep of untracked files. Before merging, run `git -C <repoRoot> status --porcelain --untracked-files=no`. If any line is printed, emit `run.finished` with `{exit_code: 2, status: "failed", reason: "dirty_checkout", files: [<paths>]}` and return. Never delete a user file.
5. Replace every `console.log("[DEBUG]...")` in `src/engine/**` (effects.ts, actions/*.ts, engine.ts) with `log.debug(...)`, keeping the same arguments. `grep -rn 'console\.' src/engine` must print nothing afterwards.
6. Scenario tests: in each file under `test/integration/scenarios/`, replace every hand-written adapter result (`customAdapter` returning `final_text`, or `result: {...}` returned by a fake) with `fakeClaudeAdapter(calls)` and a `calls` array whose entries use `edits`, `reply` and `failure` from R0.2. Fail-then-fix: call 0 writes the bad content with `reply` set to any text; call 1 (the resumed heal session) writes the good content. Keep each test's assertions on events, states and files; change only the inputs.
7. A scenario whose asserted behaviour needs an unimplemented work package (L1/L2 replan, budget kill, timeout kill, rate-limit backoff, planner format retry, governor fallback) is kept as `it.fails("<same title>")` with the comment `// Expected to fail until <WP id>: <reason>` directly above it. Use the WP ids from IMPLEMENTATION-PLAN.md. List each such test in the Notes column of PROGRESS.md. Do not delete a scenario.
8. Delete the golden recording: remove the `SUBSTRATE_GOLDEN` branch from `readEventLog` in `helpers.ts` and delete the directory `test/fixtures/golden/`.
9. Allowlist: delete every `scripts/debt-allowlist.json` entry whose `until` is `R0.5`. Run `node scripts/check-purity.mjs` and `node scripts/check-events.mjs` to confirm no new violation and no stale entry remains.

## Invariants
- No file under `src/backends/**`, `src/roles/**`, `src/git/**`, `src/verify/**` or `src/contracts/**` changes in this WP. Unused imports left behind by the removals must be deleted in the file that has them.
- The engine still never writes source content into a worktree. `grep -rn "writeFileSync" src/engine` may show only run-record writes (`events.jsonl`, state files, manifests the planner produced).
- Every scenario test is either passing or an explicit `it.fails` with a WP id. No scenario is deleted or silently skipped.

## Edge cases
- A worker that changes nothing: the task reaches verify with no changed files; a verify command that fails then fails the task honestly.
- A scenario that needs an edit inside a directory the fake did not create: `applyCall` (R0.2) creates parent directories.
- The `git status --porcelain` output contains renamed entries (`R  old -> new`): use the new path.
- Two scenario tests in the same process must not share a scenario file; each `fakeClaudeAdapter` call uses its own temp directory.

## Guardrails
- Not done if the fabrications are removed but the scenario tests still pass only because the fakes were kept in another form. A `customAdapter` that returns a canned result is not allowed in the reworked scenarios.
- No stubs, TODO, FIXME, placeholder bodies, hard-coded returns or mocks of the code under test. `it.fails` is allowed only as item 7.
- No test-only branch, environment check or magic string in `src/`. Do not add any `process.env.VITEST`, `JEST` or `NODE_ENV` check.
- Do not change the behaviour of the merge beyond the preflight in item 4. Do not fix C-H6, C-H9 or C-H23; those belong to later work packages.
- Do not write an IP address or port in any file.
- Do not edit a file outside the write list.
