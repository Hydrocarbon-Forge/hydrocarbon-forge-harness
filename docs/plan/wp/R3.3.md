## Objective
A task runs in its own worktree and is judged by code only. `runWorker` (src/roles/worker.ts) becomes the one worker path, called by the `worker` action in `src/engine/actions/task.ts`. The worker's word is never the test: scope, protected files, HEAD and verify decide. Changed files come only from git.

## Interface
- `runWorker(opts: WorkerRunOptions): Promise<WorkerReport>` keeps its shape and adds `adapter: HarnessAdapter` (the adapter for `route.backend`), `rawDir: string` (the run directory) and `setupCommands`. Events are emitted only through `typedEmit` in `src/engine/emit.ts` (R1.2), which validates each `data` against the catalog. Raw `BackendEvent`s are never forwarded.
- Worktree path: `.substrate/worktrees/<run_id>/<task_id>-g<n>/`, created by `createTaskWorktree`. Branch: `substrate/tasks/<run_id>/<task_id>-g<n>`, created new from the run branch. An existing task branch is an error, not reused.
- `WorkspaceManager.createTaskWorktree` returns the existing worktree when its path already exists (used by resume and heal). It never removes a worktree.
- Worker prompt: `system_append` = `assembleSystem("worker", {taskClass: <class>})`. `prompt` = `render(loadTemplate("worker/task.md"), {spec_path})`, where `spec_path` is the absolute path of `<worktree>/.substrate-task/TASK.md`.
- `runWorker` no longer calls `buildWorkerPrompt` for text.

## Behavior
1. Create the worktree, emit `task.worktree.created`, write the spec to `.substrate-task/TASK.md` only (the duplicate `spec.md` write is deleted).
2. Run `manifest.setup` with `runSetup`. On failure emit `task.failed {failure_class: "worker_crashed", detail: "<command>"}`, keep the worktree, and return a failed WorkerReport. The worktree is not removed.
3. Record `hashProtectedFiles` and the HEAD and branch (`git rev-parse HEAD`, `git symbolic-ref -q --short HEAD`) before the spawn.
4. Spawn with the adapter for `route.backend`, `model` and `effort` from `resolveTaskRoute(class, generation, settings)`, `permission.allow` = `[worktree]`, `permission.deny` = `["git commit","git push","git checkout","git reset","git rebase","git clean","subagents"]`, and `raw_dir` = the run directory. Session id is the id the adapter reports in `session.started`. When no id is reported the attempt fails `worker_crashed`. No synthetic `worker-<task>-g<n>` ids.
5. Each `usage` event emits `usage.recorded {record, role: "worker", task_id, generation, attempt, class}` and adds to the task totals (used by R3.4).
6. After the session, compare HEAD and branch with step 3. A change is `scope_violation` with detail `HEAD or branch changed`. Nothing is reverted.
7. `checkScope` (existing policy `git.on_scope_violation`) runs. Out-of-scope paths are reverted when the policy is `revert`, and recorded as violations either way. A protected hash change is `protected_modified`: the task FAILS and goes to escalation L1 (R3.5). The run is not paused for it.
8. Verify with `VerifyRunner`, `cwd` = worktree, `sandbox` = `settings.sandbox.enabled`, `network` = `"allow"`. All commands must exit 0.
9. On pass, `commitAllowed` runs. A failed commit is NOT swallowed: the task FAILS with `worker_crashed` and detail `commit failed`. On success emit `task.passed`.
10. `files_changed` comes from the scope result only. Any engine-written placeholder file is absent from this WP's code.

## Invariants
- The engine, never the worker, commits. The worker is denied git commit, push, checkout, reset, rebase and clean.
- Every event type emitted is in the R1.2 catalog.
- A task's worktree path contains its run id.

## Edge cases
- Worker exits 0 but changes nothing: verify decides. An empty diff with passing verify is a pass.
- Worker commits to its branch: `scope_violation` (rule 6), no commit by the engine.
- Protected file changed and verify also fails: `protected_modified` is recorded (scope is checked before verify).
- A second run in the same repo: new run id, new path. No collision.

## Guardrails
- No security hardening beyond the plan (DECISIONS A6): no new sandbox, environment scrubbing or permission-file checks.
- Never write a raw IP address or port in code, specs, docs or fixtures.
- Not done if the worker path is reachable only from tests. The E2E must run the built CLI with the fake harness.
- Do not add stub bodies or hard-coded worker output.
- Do not move the heal logic (R3.4) or budget logic (R3.4) into this WP.
- The E2E "worker that commits" case uses `test/conformance/fake-adapter.ts` in an integration test, because the fake harness cannot run git.
- No prompt text in TypeScript. No test-only branches in `src/`.

## Out of scope
Heal and budgets (R3.4). Escalation (R3.5). Integration and merge (R3.6). Solo mode (R3.8). The governor.
