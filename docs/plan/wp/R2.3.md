## Objective
Make Claude spawns match the real `claude` CLI and report honest usage. Five defects are fixed: the session id is not a UUID (C-M4), the system text is never passed (C-H11), the permission rules use the wrong syntax (C-H12), the raw stream is written inside the worktree and causes scope violations (C-M3), and the usage model and usage totals are wrong. After this WP the E2E test shows the fake `claude` executable receiving a UUID session id, the system text, and Claude-syntax deny rules. You change no file under `src/roles/`, `src/git/` or `src/verify/`, and no OpenCode or agy file.

## Interface
`SpawnRequest` (in `src/contracts/index.ts`) gains `raw_dir?: string` (absolute directory where the raw NDJSON stream is written). `system_append` already exists.

`buildClaudeArgs(req)` (in `adapters/claude.ts`) keeps its name and returns the argv. Its shape after this WP:
`-p <prompt> --output-format stream-json --verbose [--model M] [--effort E] --session-id <uuid> | --resume <uuid> [--append-system-prompt <system_append>] --permission-mode dontAsk --permission-prompts none [--allowedTools <rules>] --disallowedTools <rules> [--max-budget-usd N]`.

Permission rules use Claude's syntax. A plain tool name stays as is (`Read`); a shell rule is `Bash(<prefix>*)`, where `<prefix>` is the command text without the trailing `*`; `Agent` is always denied.

`src/backends/normalize/claude.ts`: `normalizeClaudeEvent` and `normalizeClaudeStream` keep their names. A `result` event's usage record uses the model id that the `modelUsage` object reports with the most output tokens, else the requested model.

## Behavior
1. Session id: the engine creates one UUID (`crypto.randomUUID()`) per task, generation and attempt in `plan.ts`, `task.ts`, `solo.ts` and `replan.ts`, and passes it as `session.id`. On resume it passes `session.resume` instead. `buildClaudeArgs` throws `Error: claude session id must be a UUID: <id>` when `session.id` or `session.resume` is not in the UUID form (`/^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i`). It never generates a fallback id silently.
2. System text: when `req.system_append` is non-empty, `buildClaudeArgs` appends `--append-system-prompt <text>`. Verify the flag name first (Notes). The engine fills `system_append` from `assembleSystem` (R1.7) in the spawn sites.
3. Permissions: `req.permission.deny` entries are converted to Claude rules before `--disallowedTools`. A deny entry that is a plain tool name (for example `Agent`, `Edit`) is kept. A deny entry in the form `git <verb>` (for example `git commit`) becomes `Bash(git <verb>*)`. `Agent` is always included. The solo and task deny lists use the `git <verb>` form, so the conversion is applied in `buildClaudeArgs`. The entry `subagents` becomes `Agent`. `req.permission.allow` entries are converted the same way for `--allowedTools`. No other permission string is rewritten.
4. Raw stream: the raw stream is written to `req.raw_dir` joined with `<session id>.ndjson`. When `raw_dir` is absent, the adapter does not write a raw file (it does not fall back to `req.cwd`). The engine's spawn sites set `raw_dir` to the run directory (`<repo>/.substrate/runs/<run_id>`), so the worktree never receives the raw file.
5. Usage: the usage record's `model` is the key of `modelUsage` with the largest `outputTokens`, else `req.model`. Result usage is per invocation, so the `usage` event has `cumulative: false`.
6. Errors: a `result` with `subtype` `error_max_budget_usd` ends with `session.result` `ok: false`, `stop_reason: "budget"`. A stream error whose text contains `rate limit` or `429` is `kind: "rate_limit"`; text containing `authentication`, `invalid api key` or `401` is `kind: "auth"`; a non-zero exit with no result event is `kind: "crash"` (existing). Each `permission_denials` entry becomes a `permission.denied` event, once per `tool_use_id`.
7. Spawn sites: `plan.ts`, `task.ts`, `solo.ts` and `replan.ts` set `system_append` from `assembleSystem` for the role, `raw_dir` to the run directory, and `permission` from the same lists the engine passes today (`settings.permissions` plus the per-role deny list in the action), unchanged in content.

## Invariants
- A claude spawn never receives a non-UUID `--session-id` or `--resume`.
- Nothing is written under the worktree by the adapter.
- Every `--disallowedTools` value list contains `Agent`.
- `buildClaudeArgs` is deterministic for the same request.

## Edge cases
- `system_append` empty: no `--append-system-prompt` flag.
- `permission.allow` empty: no `--allowedTools` flag.
- A deny entry already in Claude syntax (`Bash(rm*)`): kept unchanged.
- `modelUsage` absent: the requested model is used.
- Resume with a session id that the claude CLI rejects: the adapter reports `session.result` `ok: false` with the stderr text; no retry here.
