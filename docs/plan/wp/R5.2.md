## Objective
The documentation describes only what the code does, and `docs:check` fails when a documented flag, command, environment variable or settings key has no implementation. Superseded sections of SUBSTRATE-PLAN.md are marked as superseded by DECISIONS.md.

## Interface
- `scripts/docs-check.mjs` gains four rules, each printed as `RULE path:line message`, in the same style as R0.1 scripts. Exit 0 clean, 1 violations, 2 internal error.
  - `DOC-FLAG`: a `--flag` token in `README.md`, `docs/reference/*.md` must appear in `src/cli/dispatcher.ts` (`CLI_OPTIONS` keys or `ParsedCliFlags` mapping) or in another file under `src/cli/`.
  - `DOC-CMD`: a `substrate <word>` token in those files must be a registered command name or alias (names parsed from `name:` and `aliases:` in `src/cli/commands/*.ts`).
  - `DOC-ENV`: a `SUBSTRATE_[A-Z_]+` token must appear as a literal in some file under `src/`.
  - `DOC-KEY`: a dotted settings key in the table of `docs/reference/config.md` must have its last segment read as a property (`.<leaf>`, `?.<leaf>` or `["<leaf>"]`) in a file under `src/` other than `src/contracts/**`, `src/config/**` and `src/cli/commands/config.ts`.
- Marker for superseded sections: a block quote line beginning `> **Superseded by DECISIONS.md**` directly under the section heading.

## Behavior
1. Each documented flag, command, variable and key is checked as above, and each failure prints one line.
2. `README.md` and the three reference files describe: the CLI commands that exist (R1 to R4); the configuration layers in the order R1.6 implemented; the adapters with their pins. They contain no TUI claims, no hooks as available features, and no governor as a default path.
3. `docs/reference/local-model.md`, `caller-guide.md` (copied from R5.1) are kept and checked by the same rules.
4. In `SUBSTRATE-PLAN.md`, each section that DECISIONS.md supersedes gets the marker from Interface. Sections not superseded are not edited.
5. The `docs:check` output lists the number of checks per rule, then `OK` or `FAIL: <n> violation(s)`.
6. `test/fixtures/docs-check/bad/README.md` contains one violation of each rule. `clean/README.md` contains none. The unit test runs the script with `--root` on each and asserts the output.

## Invariants
- The script reads files only.
- Output is deterministic (sorted by file, then line).
- The rules check existence in code, not correctness of behaviour.

## Edge cases
- A flag written as `--model=<id>` in docs: the part before `=` is checked.
- A `substrate` token inside a code span that is a path, such as `substrate/runs/`: not a command (the token must be followed by a space or the end of the span).
- A key with a `*` segment: skipped, as in R0.1.

## Guardrails
- No security hardening beyond the plan (DECISIONS A6): no new sandbox, environment scrubbing or permission-file checks.
- Not done if the checks are only unit-tested. `npm run docs:check` must pass on the real repository.
- Do not weaken a rule to make the docs pass. Fix the document instead, or record the violation in the debt allowlist only with `until` set to a real WP id.
- Never write a raw IP address or port in docs or fixtures.
- Do not document the governor, the TUI or hooks as features.

## Out of scope
Symbol-level checks (R0.6). Archive docs. Benchmark docs. Packaging docs. Any change to `src/`.

## Done when
1. `npm run typecheck` exits 0.
2. `npx vitest run test/unit/scripts/docs-check.test.ts` passes: the clean fixture gives exit 0; the bad fixture gives exit 1 with one line per rule.
3. `npm run docs:check` exits 0 and prints the four rule counts.
4. `npm test` and `npm run check` pass.
5. Delete the entries in `scripts/debt-allowlist.json` whose `until` is `R5.2`.
6. Mark R5.2 DONE in `docs/plan/PROGRESS.md` with the `docs:check` output in Notes, and commit as `R5.2: Docs reconciliation and stronger docs-check`.
