## Objective
Prove on this machine that a full `run` works with each installed real harness, within a fixed cost cap, and record the proof. `npm run gate:g5` passes only when every installed harness has a recorded live pass with its current version pin.

## Interface
- `npm run test:live` runs `test/live/smoke.test.ts` with `SUBSTRATE_LIVE=1`. Without `SUBSTRATE_LIVE=1` every live test is skipped and writes a `skipped` record.
- `npm run gate:g5` runs `node scripts/gate-g5.mjs`. Exit 0 when every installed harness has a passing record, else 1.
- Record file: `.substrate/ledger/live-smoke.json`, an array of `{harness, version, model, run_id, status: "passed" | "failed" | "skipped", exit_code, cost_usd, ts}`.
- `test/live/helpers.ts` creates the toy repository: a git repo with `package.json` and a `src/math.js` file, and the task "add a function `sum(a, b)` in `src/math.js` and a test for it".

## Behavior
1. For each harness `claude`, `opencode`, `agy`: call `validateEnvironment()` through `createAdapters` (R2.2). A harness with `ok: false` is not installed and is not tested.
2. For each installed harness, the smoke test writes settings with `budgets.run.max_usd: 0.25`, `budgets.task.max_usd: 0.10`, `profiles` where the `plan` and `work` slots use the cheapest model `listModels()` returns (R2.6, price order from the price table), and a single planner and worker route to that harness.
3. It runs `substrate run` (plan mode) through the built CLI on the toy repo, with `SUBSTRATE_LIVE=1`.
4. Exit 0 with a finished run, and the test fails if the summary exceeds `$0.25`. The test then appends `{status: "passed", ...}` with the real `usage` cost. Any other result appends `{status: "failed"}` and fails the test.
5. `gate-g5.mjs` reads the record file and, for each installed harness, requires a `passed` record whose `version` equals the current version pin. A missing record, a `failed` latest record, or any `skipped` record for an installed harness makes the gate fail with one line per problem.
6. The gate prints a table: harness, version, model, run id, cost, and result.

## Invariants
- The live test never runs without `SUBSTRATE_LIVE=1`.
- The cost cap is `$0.25` per harness, enforced by the engine's budget (R3.4) and checked by the test.
- A record is written only by the live test, never by the gate.

## Edge cases
- No harness installed: gate exits 1 with `no installed harness; nothing recorded` (a gate that passes with zero harnesses would prove nothing).
- A harness installed at a version other than its pin: the test fails before any model call, with a `version_pin` problem.
- Record file missing: treated as no records.

## Guardrails
- Never write a raw IP address or port in code, specs, docs or fixtures.
- This WP spends real money (at most `$0.25` per installed harness). Run `npm run test:live` only with the owner's go-ahead recorded in `docs/plan/PROGRESS.md` Notes.
- Not done if the gate passes without records. The gate must read the file.
- Security is out of scope (DECISIONS A6). Do not add sandbox or network checks.
- No prompt text in TypeScript. No stub records.

## Out of scope
Benchmarks (not in this version). Harness installation. Security checks. The governor.

2. `npx vitest run test/live/gate.test.ts` passes. It covers: no records (fail); a passing record with the current pin (pass); a failing latest record (fail); a skipped record (fail).
3. `npm run test:live` run with `SUBSTRATE_LIVE=1` writes a record for each installed harness. Paste the record count in Notes.
4. `npm run gate:g5` exits 0. Paste the table, and list which harnesses are installed, in Notes. This is the G5 gate.
5. `npm test` and `npm run check` pass.
