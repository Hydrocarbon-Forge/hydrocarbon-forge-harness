## Objective
Show, per model, how well it performs in this project: how many tasks it ran, how often its first attempt passed verify, how often it needed a heal or a replan, what each task costs, and the average tokens. The numbers come only from the ledger and the run event logs.

## Interface
- CLI: `substrate models --stats [--since 30d] [--output-format json]`. Without `--stats` the command is unchanged (R2.7).
- `src/cli/model-catalog.ts` exports `modelStats(opts: {projectRoot, since?: number}): ModelStat[]` where `ModelStat = {model: string; provider: string; tasks: number; first_pass_rate: number | null; heal_rate: number | null; replans: number; avg_input_tokens: number | null; avg_output_tokens: number | null; avg_cost_per_passed_task: number | null; cost_unknown: boolean; note?: "no data"}`.
- `src/ledger/usage.ts` gains `distinctTasks(entries: UsageLedgerEntry[]): Map<string, UsageLedgerEntry[]>` keyed by `run_id/task_id/generation`.
- JSON: `{"since","stats":[ModelStat...]}`.

## Behavior
1. Source: the project ledger (`projectUsagePath`) for tokens, cost and the model of each task generation, plus each run's `events.jsonl` for verify results, heals and replans.
2. A task generation is `run_id`, `task_id`, `generation`. Its model is the model on its ledger rows (the first one with a non-empty model).
3. `tasks` = number of distinct task generations for the model.
4. `first_pass_rate` = generations whose attempt 1 emitted `task.verify.finished {passed: true}`, divided by `tasks`. `null` when `tasks` is 0.
5. `heal_rate` = generations with a `task.healing` event, divided by `tasks`.
6. `replans` = `task.replanned` events whose previous generation ran on this model.
7. `avg_input_tokens` and `avg_output_tokens` = ledger token sums divided by `tasks`.
8. `avg_cost_per_passed_task` = ledger cost of the model's generations that ended `task.passed`, divided by that count. `cost_unknown` is true when any of those rows has `cost_source: "unknown"`, and the text output then shows `unknown` instead of a number.
9. A model with no task generations gets `note: "no data"`, and every rate is null.
10. `--since` filters ledger rows and events by timestamp, as in R2.8.
11. Text output: one table per provider, then an `all models` summary line. Numbers are shown with 1 decimal place for rates (as percent) and 4 decimal places for cost.

## Invariants
- No value is taken from a model's own text.
- Division by zero never occurs; the value is null.
- The command reads files only. It writes nothing.

## Edge cases
- A run with events but no ledger rows (ledger deleted): tokens and cost null, tasks counted from events.
- A model that appears only in replans: `tasks` 0, `note: "no data"`.
- Malformed event lines: skipped.

## Guardrails
- No security hardening beyond the plan (DECISIONS A6): no new sandbox, environment scrubbing or permission-file checks.
- Never write a raw IP address or port in code, specs, docs or fixtures.
- Not done if the stats are reachable only from tests. The E2E must run `models --stats` through the built CLI after two real runs.
- No estimated or invented numbers. Missing data is `null` with `no data`.
- No test-only branches in `src/`.

## Out of scope
Pricing (R2.1). Changing `usage` (R2.8). Benchmarks (out of scope for this version). The governor.
