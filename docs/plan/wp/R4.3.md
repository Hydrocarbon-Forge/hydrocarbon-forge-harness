## Objective
A local OpenAI-compatible server (for example llama.cpp) can serve as a worker route through an OpenCode custom provider. Its address lives only in `.substrate/settings.local.json` and in the per-run config that is never committed. A profile slot can name a local model.

## Interface
- `Settings.backends.opencode.provider` (src/contracts/index.ts) = optional `{id: string, npm: "@ai-sdk/openai-compatible", base_url: string, models: Record<string, {name?: string}>}`, `.strict()`. `id` defaults to `local`.
- `src/config/index.ts` rejects this key outside `.substrate/settings.local.json`: `Error: backends.opencode.provider may only be set in .substrate/settings.local.json`, exit 2 through `loadSettings`.
- `src/backends/adapters/opencode.ts`: `generateOpenCodeRunConfigSync` writes the provider block (`provider.<id>` with `npm`, `options.baseURL` = `base_url`, and `models`) into the per-run config. The OpenCode model string is `<id>/<model key>` for a local model.
- `Capabilities.max_concurrency` for the opencode adapter = `backends.opencode.max_concurrency` (default 2 when a local provider is set; otherwise unset). R3.2's scheduler reads it.
- `docs/reference/local-model.md` (created) documents the setup with placeholder URLs only.

## Behavior
1. A profile slot whose `model` equals a key of `provider.models` (or `<id>/<key>`) routes to the local provider. The adapter maps it to `<id>/<key>`.
2. The per-run OpenCode config contains the provider block. The file is written under the run directory and is removed after the run (the R2.4 rule for the agent file applies). It is never written into the worktree or the repository.
3. `substrate config set backends.opencode.provider.base_url <url> --local` writes `settings.local.json` (R1.6 `config set`) and validates the URL is `http:` or `https:`. It rejects any other scheme with exit 2.
4. A non-local (`settings.json`) `provider` key is rejected (Interface).
5. Concurrency: the adapter's `max_concurrency` is exposed through `capabilities`. Scheduling is R3.2's job.
6. Prompts and task specs never include the base URL. The URL is passed only through the OpenCode config file.
7. `loadSettings` keeps the `provider` object exactly as written; no default is added for `base_url`.

## Invariants
- `git grep` of a repository using the local route finds no URL and no `host:port` literal in any committed file.
- The generated config is deleted after the run, including after a crash of the engine on the next start of that run (R2.4 cleanup rule).
- The local route is never selected unless a profile names its model (no implicit fallback).

## Edge cases
- `base_url` with a path (`/v1`): kept verbatim.
- `provider.models` empty while a slot names a model: the slot is an error: `unknown model` (R4.1 rule), exit 2.
- Two providers with the same `id`: impossible in this schema (one provider per backend).

## Guardrails
- No security hardening beyond the plan (DECISIONS A6): no new sandbox, environment scrubbing or permission-file checks.
- Not done if the route is reachable only from tests. The E2E must run `run` with a local-model profile through the built CLI and the fake opencode executable.
- Never write a raw IP address or port in any file of this WP, including specs, docs and tests. Tests use a value built at runtime (for example `http://localhost:` plus a free port).
- No stub config, no hard-coded base URL in `src/`.
- No test-only branches in `src/`.

## Out of scope
Benchmark arm D (later). Native OpenCode providers other than the custom one. The governor. Security hardening (DECISIONS A6).
