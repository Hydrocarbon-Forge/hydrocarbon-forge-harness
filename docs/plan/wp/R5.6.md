## Objective
Remove the governor (the optional local triage model) from the code, once the owner asks for it. The default path already has no governor (DECISIONS A2). This WP deletes the code, the setting, the prompt and its tests, so nothing can be wired back by accident.

## Interface
- Deleted files: `src/roles/governor.ts`, `src/roles/governor-tools.ts`, `assets/agents/governor.md`, `test/unit/roles/governor.test.ts`, `test/unit/roles/governor-tools.test.ts`.
- Removed from `src/contracts/index.ts`: `RoleName` value `governor`, the `roles.governor` object in `Settings`, and the `GovernorTool` and `RoutingDecision` schemas.
- `src/roles/router.ts`: `routeRequest` loses its governor step (Step 3) and its import.
- `src/engine/actions/route.ts`: the governor branch and `governor.fallback` event are removed.
- `test/unit/roles/assets.test.ts`: expects four agents (planner, worker, test-writer, reviewer).
- `test/integration/scenarios/scenario-15-governor-fallback.test.ts` is replaced by the governor-free request run in `test/e2e/no-governor.test.ts`.

## Behavior
1. Before any deletion, `grep -rn "governor" src test assets scripts docs/reference` lists every use. Each use is removed or replaced in this WP.
2. A settings file containing `roles.governor` is rejected by the strict schema with exit 2 and a message naming the key.
3. `routeRequest` without the governor step: `--mode solo` and `--mode plan` are unchanged; the deterministic mechanical rule is unchanged; the default is `plan`.
4. The `route` action in `auto` mode uses the deterministic `routeRequest` only.
5. `test/e2e/no-governor.test.ts` runs `run --request` (R4.1) with a request file and a settings file that has no governor key, and expects exit 0 with the fake executable.
6. `scripts/debt-allowlist.json` entries with `until` = `R5.6` are removed; `roles.governor.*` settings entries are removed.

## Invariants
- No file under `src/` or `test/` imports a governor module after this WP.
- No setting key `roles.governor` exists in the contracts.
- `assets/agents/` contains exactly planner, worker, test-writer and reviewer.

## Edge cases
- A user settings file with `roles.governor` present: rejected with exit 2 (Behavior 2). This is intended.
- `src/engine/effects.ts` still referencing the governor after R0.4: the route action is the only place; if a reference remains in `effects.ts`, stop and record it in Notes (effects.ts is protected here because R0.4 owns it).

## Guardrails
- No security hardening beyond the plan (DECISIONS A6): no new sandbox, environment scrubbing or permission-file checks.
- Never write a raw IP address or port in code, specs, docs or fixtures.
- Do not start this WP without the owner's instruction recorded in `docs/plan/PROGRESS.md` Notes ("Only if the owner asks"). Otherwise stop.
- Not done if the governor is only unreferenced but still present on disk. The files must be deleted.
- No new governor logic, no replacement classifier.
- No stub bodies.

## Out of scope
Any replacement router. Any change to `effects.ts` beyond the route action import. The TUI (already out of scope).

## Done when
1. `npm run typecheck` exits 0.
2. `grep -rln "governor" src test assets` prints nothing except the removed-setting rejection test in `test/unit/config`, if one exists.
3. `npx vitest run test/unit/roles test/integration/scenarios` passes.
4. `npx vitest run test/e2e/no-governor.test.ts` passes.
5. `npm test` and `npm run check` pass.
6. Delete the entries in `scripts/debt-allowlist.json` whose `until` is `R5.6`.
7. Mark R5.6 DONE in `docs/plan/PROGRESS.md` and commit as `R5.6: OPTIONAL: retire the governor`.
