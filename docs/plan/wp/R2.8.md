## Objective
Add `substrate usage`, the one command that reports input tokens, output tokens and cost across every harness, grouped by `model`, `provider`, `role`, `run`, `task`, `class` or `day`. `substrate cost` becomes an alias of it. The command only reads the usage ledger that R1.4 writes. It never recomputes prices (R2.1 owns pricing) and never drops a row whose cost is unknown.

## Interface
- CLI: `substrate usage [--by model|provider|role|run|task|class|day] [--since 7d|YYYY-MM-DD] [--provider P] [--model M] [--run ID] [--all-projects] [--cache] [--rebuild] [--output-format text|json]`. `substrate usage <run_id>` is shorthand for `--run <run_id>`. `substrate cost ...` is an alias with identical behaviour.
- `src/ledger/usage.ts` (created by R1.4) gains these exports in this WP:
  - `readUsageLedger(file: string): UsageLedgerEntry[]` reads JSONL and skips malformed lines, including a torn last line. A missing file returns `[]`.
  - Paths come from R1.4's `ledgerPaths({projectRoot, globalEnabled: true, env})` (`{project, global?}`). This WP does not define its own path helpers.
  - `groupUsage(entries: UsageLedgerEntry[], by: UsageGroupBy, opts: {cache: boolean}): UsageRow[]`, where `UsageRow = {group: string; runs: number; calls: number; input_tokens: number; output_tokens: number; cost_usd: number; unknown_cost_rows: number; cache_read_tokens: number; cache_write_tokens: number; reasoning_tokens: number}` and `UsageGroupBy` is the seven `--by` values.
- `src/cli/commands/usage.ts` exports `usageCommand` (`name: "usage"`, `aliases: ["cost"]`).
- `src/cli/dispatcher.ts`: add `by`, `since`, `provider`, `run`, `allProjects`, `cache`, `rebuild` to `CLI_OPTIONS`, to `ParsedCliFlags`, and to the mapping in `parseCliArgs`. `--model` and `--output-format` already exist.
- `src/cli/commands/cost.ts` contains only `export { usageCommand as costCommand } from "./usage.js";` and registers nothing.

## Behavior
1. `--since`: `^\d+d$` means now minus N x 24 h. `^\d{4}-\d{2}-\d{2}$` means that date at 00:00 UTC. Any other value prints `Error: invalid --since '<v>' (use 7d or YYYY-MM-DD)` to stderr and exits 2. Entries with a `ts` before the cut-off, or without `ts`, are dropped.
2. `--by` defaults to `model`. An unknown value prints `Error: invalid --by '<v>'` and exits 2. Group keys: `model` = `model`; `provider` = `backend`; `role` = `role`; `run` = `run_id`; `task` = `task_id` or `(none)`; `class` = `class` or `(none)`; `day` = the first 10 characters of `ts`.
3. `--provider` (matches `backend`), `--model` and `--run` filter the entries before grouping.
4. The source is `ledgerPaths(...).project`. `--all-projects` reads `ledgerPaths(...).global` instead, and prints `no global mirror` (exit 0) when that path is undefined. A missing file means zero entries, not an error.
5. Text output: a header `group runs calls input output cost`, one row per group sorted by cost descending then group name, then a `total` row. A cost cell is `$<known cost, 4 decimals>`. When the group has n > 0 rows with `cost_source: "unknown"`, the cell is `$<x> (+ n unknown)`. `--cache` adds `cache_read cache_write reasoning` columns. With zero entries print `no usage recorded` and exit 0.
6. `--output-format json` prints one object `{"by","since","filters":{"provider","model","run"},"rows":[...],"totals":{...}}`. Row fields are the `UsageRow` numbers; cache fields appear only with `--cache`. Unknown cost stays visible through `unknown_cost_rows`.
7. `--rebuild` calls `rebuildFromEvents(runDir, paths)` (R1.4; it replaces each run's lines in both files) for every directory under `.substrate/runs/`, sums the returned counts, prints `rebuilt <n> line(s) from <m> run(s)`, and then prints the normal report. It never deletes a ledger file itself.

## Invariants
- A row is never dropped because its price is unknown. It counts toward tokens and calls and is flagged.
- Numbers are sums of the ledger's own fields. No price is computed in this command.
- The command writes the ledger only through `--rebuild`, and only through R1.4's `rebuildFromEvents`.
- Output ordering is deterministic.

## Edge cases
- A torn last line in `usage.jsonl` is skipped.
- A group where every row is unknown prints `$0.0000 (+ n unknown)`, never a bare `$0`.
- `--all-projects` with `XDG_STATE_HOME` unset uses `~/.local/state`.
- `usage <run_id>` for a run with no rows prints `no usage recorded` and exits 0.

## Guardrails
- No security hardening beyond the plan (DECISIONS A6): no new sandbox, environment scrubbing or permission-file checks.
- Never write a raw IP address or port in code, specs, docs or fixtures.
- Not done if the feature is reachable only from unit tests. The E2E test in Done when must run the built CLI through `runSubstrate`.
- No stub output, placeholder numbers or hard-coded totals. Each number comes from `groupUsage`.
- Do not edit `src/backends/**` or `src/ledger/index.ts`.
- No prompt text in TypeScript. No test-only branches in `src/`.

## Out of scope
Pricing (R2.1). `models --stats` (R4.6). Per-task usage tables in `report` (R1.3). The retired governor `show_cost` tool.
