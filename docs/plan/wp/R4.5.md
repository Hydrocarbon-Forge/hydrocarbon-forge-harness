## Objective
The planner receives the project's standing charter and the recent history of the current version, within fixed size caps. Only the user's explicit commands change the charter, and older versions stay out of planner context.

## Interface
- `src/charter/index.ts` exports:
  - `readCharter(substrateDir): {body: string; version: string | undefined} | undefined`
  - `plannerCharter(substrateDir): string`: the charter body, cut to 4096 bytes with `capBytes` (marker `[truncated]`), or `(none)`.
  - `plannerHistory(substrateDir, opts: {historyAll: boolean}): string`: the five most recent summaries of the current version (newest first in the INDEX sense: the last five lines of `INDEX.md`), each run's `summary.md`, cut to 6144 bytes in total, or `(none)`. With `historyAll`, every version is included, newest version first.
- CLI: `substrate charter show`, `substrate charter set <file|->`, `substrate charter bump <version>`. `<version>` matches `^v\d+$`. `--history-all` is a flag on `run` and `plan`, added in `src/cli/dispatcher.ts`.
- `plan` action (src/engine/actions/plan.ts) fills the R3.1 variables `charter` = `plannerCharter(...)` and `history` = `plannerHistory(...)`.

## Behavior
1. `charter show` prints `.substrate/charter.md`. Missing: `Error: no charter; create one with substrate charter set <file>`, exit 2.
2. `charter set <file|->` writes `.substrate/charter.md`, keeping any existing `version:` frontmatter. It refuses empty content (exit 2). Content over 4096 bytes prints a warning to stderr and is still written.
3. `charter bump <version>` sets `version: <version>` in the frontmatter (adding the frontmatter if absent), keeps the body, and creates `.substrate/archive/<version>/` with an empty `INDEX.md` when it does not exist. It prints `charter now at <version>`.
4. The charter is never written by the engine. Only the three commands above write it.
5. The planner request includes the charter text under `## Project charter` and the history under `## Recent history (current project version)`, both through the R3.1 template.
6. The plan action writes the rendered user prompt to `<runDir>/planner-request.md` before spawning, so the content can be inspected (runtime file, gitignored).
7. `--history-all` includes every version's runs, newest version first, under the same 6144-byte cap.
8. Old versions are excluded by default. Their archives are never read unless `--history-all` is given.

## Invariants
- The planner never receives more than 4096 bytes of charter or 6144 bytes of history.
- The charter body is the same text that `charter show` prints (frontmatter removed).
- Changing `version` never edits an archive directory.

## Edge cases
- Charter with no frontmatter: version undefined; `bump` adds frontmatter.
- `INDEX.md` missing for the current version: history is `(none)`.
- A summary file missing for an INDEX line: that run is skipped, not an error.
- Charter exactly 4096 bytes: not truncated.

## Guardrails
- No security hardening beyond the plan (DECISIONS A6): no new sandbox, environment scrubbing or permission-file checks.
- Never write a raw IP address or port in code, specs, docs or fixtures.
- Not done if the caps and version rules are reachable only from tests. The E2E must run `charter` and `plan` through the built CLI.
- No automatic charter writes. No placeholder charter text in `src/`.
- No test-only branches in `src/`.

## Out of scope
