## Objective
Catch exported code that is imported or exported but never called from the product's entry points, the failure that created this repo's problems (C-H21). Module-level reachability (R0.1's `check-wired`) cannot see it, because the module that defines the dead function is itself reachable. After this WP `npm run check` fails when a new exported function, class or const in `src/` is dead, and the known dead symbols are recorded in the allowlist with the work package that will wire them. You change no code under `src/`.

## Interface
`scripts/check-dead-exports.mjs` exports `analyzeDead({root, entries, excludeDirs})` and can be run as `node scripts/check-dead-exports.mjs [--root <dir>] [--allowlist <file>] [--init-allowlist]`. `analyzeDead` returns `[{path, line, name}]` for every DEAD symbol, sorted by path then line. Default entries: `src/cli/dispatcher.ts` and `src/index.ts`. There are no default excluded directories (the TUI is removed by R0.7). Exit codes and output format follow R0.1: each violation prints as `dead-export <path>:<line> <name>`, the last line is `FAIL: <n> violation(s)` or `OK`.

`scripts/check-wired.mjs` calls `analyzeDead` after its module-level check and reports its results as rule `dead-export`, applying the allowlist kind `dead` through `applyAllowlist` in `scripts/lib/allowlist.mjs`.

`scripts/debt-allowlist.json` gains a key `"dead": [{"symbol", "path", "until"}]`. `until` follows R0.1's rules (`R\d+.\d+` or `DEFERRED`).

`package.json` gains the script `"check:dead": "node scripts/check-dead-exports.mjs"`.

## Behavior
1. Build the program with the TypeScript compiler API (`import ts from "typescript"`): root files are every `src/**/*.ts` file except `*.d.ts` and files under excluded directories. Use fixed compiler options (`module: NodeNext`, `moduleResolution: NodeNext`, `target: ES2022`, `noEmit: true`) so that fixtures need no `tsconfig.json`. Load `tsconfig.json` only if it exists, and never fail when it is missing.
2. Declarations to check: every top-level exported `function`, `class`, and `const` (variable statement) in a file under `src/`, excluding `export type`, `export interface` and re-export specifiers. `export default` counts as exported with its local name.
3. Reference: an identifier in another file under `src/` (or the same file, outside its own declaration) that resolves (`checker.getSymbolAtLocation`) to the declaration, excluding identifiers inside import or export specifiers and excluding type positions. Test files are not scanned.
4. Owner of a reference: the nearest enclosing top-level declaration in its file (function, class, variable statement, including non-exported ones), or the file's top-level code when there is none.
5. Liveness, computed as a fixed point: (a) every top-level code of a file reachable from an entry is live; (b) every exported symbol of an entry file is live; (c) a declaration is live when one of its references has a live owner. Iterate until no change. Everything else is dead. Reachability uses the same import graph as R0.1 (`importSpecifiers` and `resolveRelativeImport` from `scripts/lib/scan.mjs`).
6. A dead symbol produces one violation at the line of its declaration. Print `dead-export <path>:<line> <name>`.
7. `--init-allowlist` writes one `dead` entry per DEAD symbol, merging with existing entries and never duplicating. `until` comes from the table in Behavior 8. A symbol not in the table gets `until: "R5.4"` and a warning line `WARN: <name> assigned R5.4`.
8. Mapping table (symbol to `until`): `runWorker` R3.3; `runPlanner` R3.1; `commitContractStubs` R3.1; `generateRepoMap` R3.1; `executeReplan` R3.5; `scheduleNextTasks` R3.2; `appendRouteOutcome` R2.9; `aggregateLedger` R2.8; `detectEcosystem` R3.8. Symbols in `src/cli/index.ts` (an unimported duplicate, S-L4) and any symbol not listed get R5.4.
9. Allowlist matching for kind `dead` matches on `symbol` and `path` together. The stale-entry rule, DONE rule and `until` validation of R0.1 apply unchanged. `applyAllowlist` in `scripts/lib/allowlist.mjs` gains the `dead` kind.

## Invariants
- The analysis only reads files. It writes only when `--init-allowlist` is given, and then only the allowlist file.
- Output is deterministic: sorted by path, then line.

## Edge cases
- A chain A→B where only A is dead: both A and B are reported, because B is live only through dead code.
- `import {a} from "./a.js"` with no call to `a`: `a` is DEAD (the import is a specifier and does not count).
- A `.js` specifier that resolves to a `.ts` file: the program resolves it through NodeNext; the graph walk maps `./x.js` to `./x.ts` the same way R0.1 does.
- Circular imports between two dead files: both are dead; the fixed point does not loop forever.
- A class used only through `new` in live code: live. A const used only in a type position: dead.
- A file with a syntax error: the program still builds; report `dead-export` for nothing in that file and print `WARN: parse error in <path>`.

## Guardrails
- Do not weaken the definition of LIVE to make the allowlist smaller (for example, do not treat test references as live).
- Do not delete or wire any dead symbol in this WP. Their owners are the work packages in the mapping table.
- No new runtime dependency. `typescript` is already a devDependency.
- No stubs, TODO, FIXME or placeholder bodies in the script. The analysis must do the real compiler-API walk.
- Do not edit `src/` at all, including `src/cli/index.ts`.
- Do not write an IP address or port in any file.

## Out of scope
Settings-key and event checks (R0.1), the purity rules (R0.1), deleting or wiring any dead symbol, and the TUI (removed by R0.7).
