## Objective
Make every read-side command and every output format tell the truth about a run: the run summary and `status` count passed tasks correctly, `tasks` shows every real state, `report` shows what happened, text mode streams progress to stderr, `--output-format json` prints exactly one JSON object, and `stream-json` prints NDJSON only. The CLI reads only catalog events from R1.2. After this WP `status`, `tasks`, `report` and the run summary are proven against a real engine run, not hand-written event logs.

## Interface
`src/cli/stream-map.ts` exports `STREAM_TYPE: Record<EventType, string>` with one explicit entry for every member of `EVENT_TYPES` from `src/contracts/events.ts`, and `streamTypeFor(type: string): string` (returns the mapped name, or `"unknown"` for a type not in the table). The mapping is the identity for every catalog member except `usage.recorded`, which maps to `usage`. The mapping table is the single place where stream-json names are chosen.

`src/cli/output.ts`: `createFormatter(format, stdout, stderr)`. The text formatter writes progress to `stderr` and the final summary to `stdout`. The JSON formatter writes one object to `stdout`. The stream-json formatter writes NDJSON lines to `stdout`.

`src/cli/commands/report.ts` prints: goal (the first `run.created` data's `goal`, or the prompt), duration (last event `ts` minus first), a task table (task id, state, generation, attempts, failure class), tokens in and out summed from `usage.recorded` records, cost, files changed, and each `task.verify.finished` outcome.

## Behavior
1. Text progress (stderr), one line per event, only for these types: `task.session.started` gives `[task <id>] started (gen <g>, attempt <a>)`; `task.verify.finished` gives `[task <id>] verify passed` or `verify failed`; `task.merged` gives `[task <id>] merged`; `task.failed` gives `[task <id>] failed: <failure_class>`; `run.paused` gives `run paused: <reason>`. Other types print nothing in text mode.
2. Text summary (stdout) keeps the current layout. `Tasks:` counts a task as passed when its `state` is `PASSED` or `MERGED`. The total is the number of tasks in the summary.
3. JSON mode: `onSummary` writes exactly one JSON object followed by a newline to stdout, and nothing else goes to stdout in that mode. Errors in JSON mode are one object `{"error": "<message>"}` on stdout.
4. stream-json mode: each engine event is one line `{"type": streamTypeFor(event.type), "run_id", "seq", "ts", ...data}` on stdout. The final line is the existing `result` object. No other text goes to stdout.
5. `status` (`status.ts`): counts passed tasks as in Behavior 2 and prints the state of every task. The run list reads each run's `events.jsonl` through the catalog types only.
6. `tasks` (`tasks.ts`): prints every task with its real state (`PENDING`, `READY`, `RUNNING`, `SCOPE_CHECK`, `VERIFYING`, `HEALING`, `PASSED`, `MERGING`, `MERGED`, `FAILED`, `REPLANNING`, `BLOCKED`, `ABANDONED`), generation and attempt count. A passed task is shown.
7. `report` (`report.ts`): prints the sections in the Interface paragraph. A run with no events prints `no events recorded` and exits 1.
8. `run.ts`, `plan.ts` and `resume.ts`: pass `stderr` to `createFormatter`. Their exit-code mapping is unchanged.
9. Tests (`test/integration/cli/**`): rewrite every test that hand-writes event objects. Each test runs the engine through `EngineImpl` with `adapter: new FakeAdapter()` (from `test/conformance/fake-adapter.ts`) and a temp repo, then reads the resulting `events.jsonl`. Keep one test per formatter behaviour in Behaviors 1 to 7.

## Invariants
- The CLI never reads an event type that is not in `EVENT_TYPES`.
- Stdout in JSON and stream-json modes contains only the documented output; progress text goes to stderr only.
- A summary's `passed` count and the `status` count are equal for the same run.

## Edge cases
- A task in state `FAILED` with no `failure_class`: the table shows `-`.
- Stream-json with a `run.paused` event: the line has `reason` as a field.
- `report` on a paused run: the table shows the states as recorded; it does not infer a final state.
- A run whose `events.jsonl` has a torn last line (partial write): parse the complete lines and ignore the torn one, with a warning on stderr.

## Guardrails
- Not done if the formatters are unit-tested on hand-written objects only. The tests in `test/integration/cli/**` must drive the engine.
- No stubs, TODO, FIXME, placeholder bodies or hard-coded counts. Passed counts must come from the summary's task states.
- No test-only branch or environment check in `src/cli`.
- Do not write to stdout outside the formatters in JSON or stream-json mode.
- Do not add a dependency.
- Do not write an IP address or port in any file.
