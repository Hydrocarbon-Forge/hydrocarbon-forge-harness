## Objective
Make the CLI drive the real adapters. The engine no longer imports or defaults to `FakeAdapter`, adapters are built from settings in one registry, and every spawn picks the adapter for its route's `backend`. A route whose adapter is missing pauses the run with `backend_unavailable`. After this WP `git grep -n "fake-adapter" src` is empty, and an E2E run shows the fake `claude` executable receiving the `--model` from settings. You change no file under `src/contracts/`, `src/roles/`, `src/backends/adapters/` or `src/backends/normalize/`.

## Interface
`src/backends/registry.ts` exports:
- `createAdapters(settings: Settings): Record<"claude" | "opencode" | "agy", HarnessAdapter>`. It builds `new ClaudeAdapter({bin, versionPin, maxConcurrency})` from `settings.backends.claude` (`bin` defaults to `"claude"`), `new OpenCodeAdapter({binPath, versionPin, ...})` from `settings.backends.opencode` (note the option is named `binPath` in `OpenCodeAdapterOptions`), and `new AgyAdapter({bin, pricing: pricingTableFor(settings), maxConcurrency})` from `settings.backends.agy`. Missing settings entries mean defaults.
- `type AdapterMap = Partial<Record<BackendName, HarnessAdapter>>`.

`EngineOptions` (in `engine.ts`): `{ settings?: Settings; adapter?: HarnessAdapter; adapters?: AdapterMap }`. `adapter`, when given, is used for every backend (this is the test injection point; tests pass `new FakeAdapter()` explicitly). `adapters` overrides entries by backend name. With neither, the engine uses `createAdapters(settings)`. `engine.ts` no longer imports anything from `test/`.

`EffectContext` (in `effects.ts`) replaces `adapter: HarnessAdapter` with `adapters: AdapterMap`.

`src/engine/actions/shared.ts` exports `adapterFor(ctx: EffectContext, backend: BackendName): HarnessAdapter | null`. Spawn sites call it with the route's `backend`. If it returns null, the action emits `run.paused` with `reason: "backend_unavailable"` and returns.

## Behavior
1. Every `ctx.adapter.spawn(...)` in `plan.ts`, `task.ts` (worker and heal), `solo.ts` and `replan.ts` becomes `adapterFor(ctx, route.backend)?.spawn(...)`, where `route` is the route that action resolved (the planner route for `plan.ts` and `replan.ts`, the task route for `task.ts` and `solo.ts`). A null adapter pauses as in the Interface.
2. `EngineImpl` in `engine.ts` builds `adapters = {...createAdapters(settings) when no adapter given, ...(options.adapter ? {claude, opencode, agy: options.adapter} : {}), ...options.adapters}` once per run (in `run` and `resume`), and passes it in `EffectContext`.
3. `src/cli/commands/backends.ts`: the list comes from `createAdapters(settings)`; the `fake` row and the `FakeAdapter` import are removed (S-L5, C-L1).
4. `run.ts`, `plan.ts`, `resume.ts` pass no adapter; the engine builds them from settings. Their existing `engine` context override stays for tests.
5. `test/conformance/fake-adapter.ts` is unchanged and stays under `test/`.
6. `test/fixtures/fake-harness/dialects/claude.mjs`: when the environment variable `FAKE_ARGV_LOG` is set, append one JSON line `{"argv": [...]}` with the arguments to that file before doing anything else. This is how the E2E test checks `--model`.
7. `test/e2e/adapters.test.ts` (create): uses `runSubstrate` from R0.3 with `settings` setting `backends.claude.bin` to a wrapper script in the temp directory. The wrapper is a shell script (mode `0755`) that exports `FAKE_SCENARIO_FILE` and `FAKE_ARGV_LOG` and then runs `test/fixtures/fake-harness/bin/claude "$@"`. The scenario is one successful call. Run `run --mode solo "touch a.txt"` with `roles.worker.model` set to `claude-haiku-5-5` in settings, then assert the argv log contains `--model` followed by `claude-haiku-5-5`, and that the run's `events.jsonl` has a `task.session.started` event.
8. Tests that built the engine with `adapter: new FakeAdapter()` keep working; only imports and types change (`EffectContext.adapters`).

## Invariants
- No file under `src/` imports from `test/`. `git grep -n "from \"../../test" src` and `git grep -n "fake-adapter" src` print nothing.
- The engine never silently uses another backend's adapter. A route whose `backend` has no adapter pauses.
- `createAdapters` is the only place that maps settings to adapter options.

## Edge cases
- A settings file without `backends.agy`: the agy adapter is still built with defaults, and `validateEnvironment` reports the missing binary when it is used.
- `adapter` and `adapters` both given: `adapters` entries win for their backend names.
- `resume` after a pause: the adapters are rebuilt from the same settings; the run's routes choose the backend.

## Guardrails
- Not done if the registry exists but spawns still use `ctx.adapter`. `git grep -n "ctx.adapter" src` must print nothing.
- No stubs, TODO, FIXME, placeholder bodies, mocks in `src/`, or a `process.env` check in `src/`.
- Do not change adapter internals (R2.3 to R2.5 own them).
- Do not write an IP address or port in any file.
