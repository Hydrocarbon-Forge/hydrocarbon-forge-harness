## Objective
Planning runs through `runPlanner` (src/roles/planner.ts) and the prompt library in `assets/`, not through the inline loop in the `plan` action. The planner's finish line decides the outcome. Format errors are retried in the same planner session. A planner that asks questions pauses the run with its questions on disk.

## Interface
- `runPlanner(opts: PlannerRunOptions): Promise<PlannerOutcome>` where
  `PlannerOutcome = {kind: "plan_ready"; plan: ParsedPlan; usage: UsageRecord; commitSha: string; sessionId: string} | {kind: "needs_input"; questionsPath: string; sessionId: string; usage: UsageRecord}`.
  It throws `PlannerFailure` (exported class, `reason: "format" | "session"`) when retries are exhausted or the session crashes.
- `PlannerRunOptions` keeps its fields and adds `adapter` as the adapter for `route.backend` from R2.2.
- Prompts come from `assembleSystem("planner", {})` and `render(loadTemplate(...))` in `src/prompts/index.ts` (created by R1.7). The planner builder in `src/roles/prompts/planner.ts` becomes a thin wrapper that calls them.
- `src/engine/actions/plan.ts` exports the `plan` action. `src/engine/actions/approve.ts` exports the `lint` action (approval gate).
- `commitContractStubs` keeps its signature. It now passes an expected old value to `update-ref`.

## Behavior
1. The `plan` action emits `plan.started`, resolves the route with `resolvePlannerRoute` (R2.9), and calls `runPlanner` with the adapter for `route.backend`. The inline loop, `extractFencedFiles` and the `safeParseManifest` fallback in `src/engine/effects.ts` are deleted.
2. The first spawn has `role: "planner"`, `cwd: runDir`, `system_append` = `assembleSystem("planner", {})`, `prompt` = `render(loadTemplate("planner/request.md"), vars)`, `permission.deny` = `["git commit","git push","git checkout","git reset","subagents"]`, and no session id. Variables: `request` = the goal; `run_id`; `base_ref` = `git rev-parse HEAD` of `repoRoot`; `repo_root`; `classes` = `TASK_CLASSES` joined by `, `; `task_budget` and `run_budget` = `$<max_usd, 2 decimals>` or `(none)`; `max_tasks` = `(none)`; `charter` and `history` = empty (R4.5 fills them); `instruction_files` (rule 3); `skills`; `repo_map` = a first line `Detected ecosystem: <detectEcosystem(repoRoot)>` followed by `generateRepoMap` text.
3. Instruction files: `instructions.workers` = `none` gives no files. `project` gives every existing file of `CLAUDE.md`, `AGENTS.md`, `SUBSTRATE.md` in `repoRoot`, in that order, as relative paths.
4. After each session, the finish line is the last non-empty line of `final_text`, trimmed. It must be `PLAN READY` or `NEEDS INPUT`. Any other value is a format error.
5. `PLAN READY` requires `manifest.yaml` in runDir, parsed by `parseManifest` (a YAML error is a format error; there is no unvalidated fallback). Every `tasks[].spec` must exist and parse with `parseTaskSpec`, and contain the seven required headings.
6. Fallback: only when `manifest.yaml` is absent and `final_text` holds fenced blocks whose info string is `<lang>:<relative path>`, those blocks are written under runDir. A path that is absolute or contains `..` is a format error.
7. `lintPlan` errors are format errors with `[code] message` diagnostics. The unconditional suppressions of L007 and L016 in `planner.ts` are removed. L003, L019 and L027 may be suppressed only when the referenced path exists in runDir, and the code comment names the reason.
8. `typecheckContracts(runDir, contracts, {cwd: runDir})` runs before commit. Failure is a format error.
9. Format errors resume the same session (`session: {resume: sessionId}`), with `correction.md` rendered from `attempt` (1-based, starting at 2), `max_attempts` (`1 + budgets.planner_format_retries`) and `diagnostics` (one line per problem). Retries stop after `max_attempts`, then throw `PlannerFailure("format")`.
10. `SessionResult.ok === false` or a non-zero exit throws `PlannerFailure("session")` without retry.
11. `NEEDS INPUT`: `QUESTIONS.md` must exist in runDir (missing is a format error). Return `needs_input`. The plan action emits `run.paused {reason: "needs_human", questions_path, session_id}`.
12. `PLAN READY` commits the stubs with `commitContractStubs` and emits `contracts.committed {commit_sha}` and `plan.produced {manifest, tasks, commit_sha}`.
13. `commitContractStubs` reads the current run ref. When it exists, `update-ref` gets that value as old; when absent, the all-zero object id. A moved ref throws instead of overwriting.
14. Each usage event emits `usage.recorded {record, role: "planner"}`, including the retries.
15. The `lint` action (`approve.ts`) runs `lintPlan` on the parsed plan and emits `plan.lint {valid, diagnostics}` with every diagnostic. It must not filter any code (the L001 `run_id` filter is removed). Approval follows the existing permission-mode rules. `plan` mode emits `plan.ready` and `run.finished {exit_code: 0}`.

## Invariants
- The planner never commits and never writes outside runDir.
- Prompt text exists only in `assets/`. No new string literal starting with "You are the Substrate" appears in `src/`.
- The finish line is parsed from `final_text` only. No file content is used to decide the outcome.

## Edge cases
- Planner writes `manifest.yaml` but final line is `NEEDS INPUT` without `QUESTIONS.md`: format error, retried.
- `QUESTIONS.md` present and final line `PLAN READY`: format error (a question file must pair with `NEEDS INPUT`).
- Two planner retries that both fail: `PlannerFailure("format")`, the run fails with exit 1.
- A task spec path that resolves outside runDir: format error.

## Guardrails
- No security hardening beyond the plan (DECISIONS A6): no new sandbox, environment scrubbing or permission-file checks.
- Never write a raw IP address or port in code, specs, docs or fixtures.
- Not done if the planner is reachable only from tests. The E2E must drive the `plan` action through the built CLI.
- No stub bodies, no hard-coded plan content, no fake manifests written by the engine.
- Do not add new event names; use the catalog from R1.2.
- No prompt text in TypeScript. No test-only branches in `src/`.
- Do not modify `assets/` in this WP. If a template variable is missing, stop and record it in Notes.

## Out of scope
Scheduling (R3.2). Replanning (R3.5). Question answers (R4.2). Charter and history content (R4.5). The governor.
