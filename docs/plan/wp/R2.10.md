## Objective
Make first-run setup produce working configuration. `substrate init` writes only the settings that differ from the built-in defaults, so the built-in pricing table (R2.1) is used rather than a copied placeholder. `substrate doctor` checks every condition a run depends on and says how to fix each failure.

## Interface
- `substrate init [--force] [--provider P] [--plan model[:effort]] [--work model[:effort]] [--fast model[:effort]]`. `P` is `claude`, `opencode` or `agy`. `effort` must be one of `Effort` (`low|medium|high|xhigh|max`).
- `substrate doctor [--output-format text|json]`. The JSON shape already defined by R1.8 is kept; this WP adds checks to its list.
- `src/cli/commands/init.ts` and `doctor.ts` use `createAdapters(settings)` from `src/backends/registry.ts` (created by R2.2) and `listModels()` (R2.6).

## Behavior
1. `init` creates `.substrate/` subdirectories `runs`, `worktrees`, `state`, `sessions`, `ledger` and `archive`.
2. `init` writes `.substrate/.gitignore` with these lines: `runs/`, `worktrees/`, `state/`, `sessions/`, `ledger/`, `settings.local.json`. It never writes `archive/` into the ignore file, so archives stay committable.
3. `init` removes the current code that appends `.substrate/` to `.git/info/exclude`. DECISIONS requires that `.substrate/` is not added to the exclude file.
4. `init` writes `.substrate/settings.json` containing only keys that differ from defaults: `profiles` and `defaults` when slot flags are given. It never writes `pricing`, `budgets` or any other default.
5. `init` writes `.substrate/charter.md` only when absent, as a stub with a heading and one sentence saying the charter is sent to the planner (capped at 4 KB).
6. An existing `settings.json` or `.gitignore` is kept unless `--force` is given. Without `--force` init prints `kept <path>` and exits 0.
7. With no slot flags, init lists each provider whose `validateEnvironment().ok` is true and its `listModels()` ids, prints the exact command to set profiles, and writes no profile. Exit 0.
8. With slot flags, `--provider` is required. `--plan` and `--work` are required together. Each model must appear in `listModels()` of an installed provider. Otherwise print `Error: model '<id>' is not listed by <provider>; valid ids: <ids>` and exit 2. A provider that is not installed exits 2 with `Error: provider <p> is not installed`.
9. With slot flags, init sets `defaults.planner_provider` and `defaults.worker_provider` to `--provider`, and writes `profiles.<P>` with `plan`, `work` and optional `fast`.
10. `doctor` checks, in order: Node >= 22; git >= 2.30 (parse `git --version`); each adapter's `validateEnvironment()` including `pin_matches` (a mismatch is FAIL with the pinned version in the fix line); `loadSettings()` succeeds; every profile model appears in that provider's `listModels()` (a missing model is WARN); bwrap (WARN only, since sandbox is off by default).
11. Each check prints `[PASS|WARN|FAIL] <name>: <detail>`. WARN and FAIL lines are followed by `fix: <how>`. Exit 0 when there is no FAIL, otherwise 1.

## Invariants
- `init` never overwrites a file without `--force`.
- `init` writes no model id that `listModels()` did not return or that the user did not pass.
- Doctor makes no change to any file.

## Edge cases
- `init` in a directory that is not a git repository: skip the exclude step, still write `.gitignore`.
- A harness binary that is missing: `validateEnvironment().ok` is false, so init does not list it and doctor reports FAIL for it only if a profile names that provider.
- `--effort` value outside the enum: exit 2 with the list of valid values.

## Guardrails
- No security hardening beyond the plan (DECISIONS A6): no new sandbox, environment scrubbing or permission-file checks.
- Never write a raw IP address or port in code, specs, docs or fixtures.
- Not done if the feature is reachable only from tests. The E2E in Done when must run `init` and `doctor` through the built CLI.
- No placeholder pricing or example model ids written into settings.
- No prompt text in TypeScript.
- Do not edit the adapters; read their `validateEnvironment` results only.

## Out of scope
Harness installation. Pricing (R2.1). Model listing output (R2.7). Interactive prompts (there is no TUI).
