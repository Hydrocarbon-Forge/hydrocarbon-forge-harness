## Objective
Make every flag documented in `docs/reference/cli.md` for run control do what it says, fail clearly on a bad id, remove the never-implemented `-w/--worktree` flag, and register the two commands that exist but are not reachable (`bench`, `agents import`). After this WP each flag below has one test that drives the CLI, and `bench --help` and `agents import --help` work from the bundle. You change no file under `src/roles/`, `src/git/`, `src/verify/`, `src/backends/`, `src/config/` or `src/store/`.

## Interface
Flags (added to `CLI_OPTIONS` in `src/cli/dispatcher.ts`):
- `-w, --worktree` is **removed** from `CLI_OPTIONS`, from the help text in `dispatcher.ts`, from `README.md` and from `docs/reference/cli.md`. Passing it afterwards fails with the standard unknown-option error (exit 2). It was never implemented, and agent callers do not need a named run branch.
- `--from <claude|opencode>` (string), used by `agents import`.
- `--allowed-tools <list>` and `--disallowed-tools <list>` stay `multiple: true`. Each value is split on commas that are not inside parentheses; entries are trimmed and empty entries dropped; repeated flags concatenate.

`verify <task> [--run <id>] [--timeout <seconds>]`: the task id is the first positional. `--run` selects the run; without it, the latest run directory (by name) that has a worktree for the task is used. `--timeout` overrides each command's `timeout_s` with the given seconds.

## Behavior
1. `resume <run_id|session_id>`: resolves the argument as a run id first, then as a session id (through the session store). An argument that matches neither exits 2 with `Error: no run or session matches '<id>'`. `--session-id <id>` is accepted as the same selector when no positional is given.
2. `run --resume <run_id>`: runs the same code path as `resume <run_id>` (`run.ts` calls `resumeCommand.execute` with the same context).
3. `-c, --continue`: selects `sessionStore.getLatest()`; its run is resumed. With no session, exit 2 with `Error: no session to continue`.
4. `--fork-session` (with `--resume`, `-c` or `resume`): calls `sessionStore.fork(<session id>)` and prints `Forked session <new id>` to stderr in text mode. The forked record is the one recorded against the run. No other semantics are implemented here.
5. `verify <task>`: the worktree is `.substrate/worktrees/<run_id>/<task_id>` (the current layout; R3.3 changes it). If it does not exist, exit 2 with `Error: no worktree for task <task> in run <run_id>`. There is no fallback to another task's worktree. When no run contains a worktree for the task, exit 2 with `Error: no worktree for task <task> in run unknown`.
6. `--allowed-tools` and `--disallowed-tools` produce `permissions.allow` and `permissions.deny` lists (split as above). `--allowed-tools "Bash(git status),Read"` gives two entries.
7. `bench` is registered by importing `src/cli/bench.ts` from the dispatcher. `agents import --from claude|opencode` is handled in `src/cli/commands/agents.ts`: when `rawArgs[0] === "import"`, it calls `runAgentsImport({from, cwd: ctx.cwd})` and prints the report summary. `--from` other than those two exits 2 with `Error: --from must be claude or opencode`. `agents import --help` prints usage and exits 0.
8. `--output-format json` for `sessions`, `backends` and `doctor` prints one JSON object to stdout and nothing else to stdout.

## Invariants
- No flag is parsed and then ignored. Each flag in the Interface changes an option the engine or a command reads.
- A bad id never falls back to another run or task.

## Edge cases
- `resume` with a finished run: prints `already finished` and exits 0 (existing behaviour).
- `-w` or `--worktree` on the command line: unknown-option error, exit 2, no run started.
- `--timeout 0`: treated as no override (each command keeps its `timeout_s`).
- `agents import` with no `--from`: exit 2 with `Error: --from is required`.

## Guardrails
- Not done if a flag works only in a test that calls the command function directly. Each flag must be checked through `runCli` in `test/integration/cli/run-control.test.ts` or `flags.test.ts`.
- No stubs, TODO, FIXME, placeholder bodies, or silent `catch` that hides a bad id.
- Do not change the store or the verify runner; use their public methods.
- Do not add a dependency.
- Do not write an IP address or port in any file.

## Out of scope
Session fork semantics in the adapters (R2.x), the `merge` command with a named run (R3.7), the verify worktree layout with generations (R3.3), and the TUI.
